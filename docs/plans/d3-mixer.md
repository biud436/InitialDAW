# D3. 믹서

> 작성일: 2026-10-07. 계기: 곡마다 트랙 효과 20~30개, 센드 20~30개, 버스 둘셋, 마스터 효과 셋이 있는데 앱에서는 볼 수도 고칠 수도 없다.
> 지금은 크기 하나를 바꾸려 해도 작곡 생성기나 JSON 을 고쳐야 한다. 듣는 자리에서 섞고, 섞은 것이 곡 파일에 남아야 한다.

## 1. 목표

앱 아래 칸에서 피아노 롤 대신 믹서를 연다. 트랙마다 채널 스트립(효과 슬롯, 센드, 밸런스, 페이더, 미터, 뮤트와 솔로)이 있고,
버스와 마스터에도 스트립이 있다. 효과를 고르면 매개변수 화면에서 값을 바꾼다. 재생 중에 바꾼 것이 바로 들리고,
손을 떼면 실행 취소 한 단계로 곡 파일(JSON)에 들어간다. 내보내기는 같은 트랙 사슬을 지나므로 믹서에서 들은 것과 같다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 믹서 상태의 자리 | 따로 두지 않는다. 페이더, 밸런스, 뮤트, 솔로, 센드, 효과는 모두 곡 JSON 의 `mixer`, `sends`, `effects` 이고, 바꾸면 문서 편집(실행 취소, 저장)이다 | 곡의 형식은 JSON 하나다. 명령행 렌더와 앱이 같은 믹스를 쓴다 |
| 뮤트와 솔로 | 문서 편집으로 바꾼다 (트랙 보기의 버튼도). 저장하면 남고, 명령행 렌더도 따른다 | 지금은 트랙 보기에서 끈 것이 재생기에만 있고 파일과 어긋난다 |
| 끌기 | 끄는 동안은 재생기에만 미리 반영하고(문서는 그대로), 손을 떼면 한 번 편집한다 | 끌 때마다 문서를 다시 파싱하지 않는다. 실행 취소가 끌기 한 번에 한 단계다 |
| 재생 반영 | 엔진의 `RealtimePlayer::apply(곡)` 이 이전 곡과 비교해 바뀐 부분만 바꿔 끼운다 (음과 곡선, 페이더, 밸런스, 뮤트, 솔로, 센드, 효과). 템포, 박자, 트랙과 버스의 목록, 악기, 사이드체인 연결, 트랙 효과의 지연이 바뀌면 false 를 돌려주고 앱이 재생기를 다시 만든다 | 편집, 실행 취소, 다시 실행이 한 길로 간다. 엔진을 먼저 넓히고 앱을 그 위에 올린다 |
| 페이더와 센드의 변화 | 오디오 스레드가 블록 하나에 걸쳐 직선으로 잇는다. 멈춰 있을 때 바꾼 값은 바로 쓴다 | 끌 때 지퍼 잡음이 나지 않는다. 재생 전에 바꾼 곡은 새로 만든 재생기와 샘플 단위로 같다 |
| 효과 바꿔 끼우기 | 새 효과 사슬은 메시지 스레드에서 만들고, 오디오 스레드가 블록 처음에 바꿔 끼우며 앞 사슬에서 같은 형식의 효과(같은 차례)의 상태를 이어받는다 (필터 상태, 딜레이 줄, 리미터, 리버브의 입력 기록) | 매개변수를 바꿀 때 리버브 꼬리와 딜레이 메아리가 끊기지 않는다. 이어받기는 할당하지 않는다 |
| 우회(bypass) | 효과 객체에 `"bypass": true`. 처리하지 않고 그 효과의 지연만큼 늦춰 내보낸다 | 우회를 켜고 꺼도 트랙의 지연 보상이 바뀌지 않아 재생기를 다시 만들지 않는다. 오프라인과 실시간이 같은 코드다 |
| 버스 뮤트 | 버스의 `mixer.mute` 를 오프라인과 실시간 모두 따른다 (지금은 읽고 무시한다). 버스 솔로는 두지 않는다 | 리버브를 끄고 마른 소리를 들어 보는 일이 잦다 |
| 효과 매개변수 표 | 엔진이 효과마다 매개변수(이름, 범위, 기본값, 단위, 로그 눈금, 켜기와 끄기, 고르기, 선택적, 리버브 방식)를 한 표로 내놓고, 검사(`validateEffectSpec`)와 앱의 화면이 같은 표를 쓴다 | 화면의 범위와 파서의 범위가 갈라지지 않는다. 기본값은 효과의 생성자와 같은지 시험한다 |
| EQ 곡선 | 엔진이 매개변수로 주파수 응답(dB)을 계산해 준다 (같은 바이쿼드 계수) | 화면의 곡선이 실제 필터와 같다 |
| 페이더 눈금 | +24 dB 위끝, 0 dB 이 4분의 3 높이, -60 dB 아래는 좁게. 미터도 같은 눈금 | 0 dB 근처를 세밀하게 고른다. 미터와 페이더 눈금이 맞는다 |
| 미터 | 트랙, 버스, 마스터의 좌우 최고값. 올라갈 때 바로, 내려갈 때 초당 24 dB, 최고값 표시 1.5초, 0 dBFS 를 넘으면 빨간 표시. 숫자는 지금까지의 최고값(누르면 지운다) | 클리핑과 균형을 본다 |
| 마스터 미터 | 모니터 게인과 끝의 리미터 뒤 (들리는 소리) | 모니터 게인은 목표 음량에 맞춘 값이라 내보낼 소리와 가깝다 |
| 효과 매개변수 화면 | 믹서 오른쪽(마스터 스트립 왼쪽)에 붙는 칸. 효과 슬롯을 누르면 열린다 | 떠 있는 창 없이 스냅숏으로 그릴 수 있다 |
| 버스 만들기 | 버스 추가, 이름 바꾸기(센드의 버스 이름도 함께), 지우기(그 버스로 가는 센드도 함께). 한 번의 실행 취소로 묶는다 | 버스 목록이 바뀌면 재생기를 다시 만든다 (드물다) |
| 키 | X 로 피아노 롤과 믹서를 바꾼다. 보기 메뉴에도 둔다 | |
| 창 없는 시험 | `--snapshot --mixer` 가 믹서를 그린다. 스냅숏은 재생기를 오디오 장치 없이 만들어 `--at` 부터 0.4초를 돌려 미터를 채운다. `--effect 트랙:번호` 는 매개변수 화면을 연다. `--edit-test` 가 믹서에 마우스를 흉내 내 보낸다 | 창을 띄우지 않고 화면과 편집을 확인한다 |

## 5. 확인한 것

- 엔진 단위 시험 97건(검사 2030), 명령행, 앱 스냅숏, 믹서 스냅숏, 앱 편집 시험 모두 통과 (D2 끝에는 85건, 검사 1850)
- `apply`: 페이더, 밸런스, 센드(배치까지), 버스 뮤트, 효과 매개변수, 우회, 효과 더하기, 음을 한꺼번에 바꾼 곡을 재생 전에 반영하면
  새로 만든 재생기와 샘플 단위로 같다(차이 0). 버스를 끄고 트랙을 끈 곡은 오프라인 렌더와 1e-5 안에서 같다
- 재생 중 바꿔 끼우기: 매개변수가 같은 효과 사슬(리버브, 딜레이, EQ, 컴프레서)로 바꿔 끼우면 끊지 않고 돌린 재생기와 출력이 한 샘플도
  다르지 않다. 효과 아홉 가지 모두 사슬 하나만으로도 같다
- 리버브 잔향 시간을 1.0초에서 2.5초로 바꿔 끼우면 지난 소리의 꼬리가 처음부터 2.5초로 처리한 것과 RMS 2% 안에서 같다. 잇지 않으면 꼬리가 1% 아래로 끊긴다
- 재생 중 페이더를 -6 dB 로 내리면 RMS 비가 0.5 (오차 0.005), 첫 블록의 샘플 간 변화가 평소의 1.05배를 넘지 않는다 (한 번에 뛰지 않는다)
- 다시 만들어야 하는 변경(템포, 악기, 버스 이름, 트랙 효과의 지연, 사이드체인 키, 곡 전체의 연주 처리)은 false 를 돌려주고 함께 고친 페이더도 바꾸지 않는다
- EQ 응답 곡선이 실제로 처리한 사인파의 크기와 0.15 dB 안에서 같다 (60 Hz~12 kHz 일곱 점)
- 우회한 리미터와 EQ 의 사슬은 입력을 지연(192 샘플)만큼 늦춘 것과 정확히 같다
- `--edit-test` 검사 56건: 페이더 끌기(끄는 동안 문서 그대로, 놓으면 편집 하나), 두 번 클릭 0 dB, 밸런스 손잡이, 뮤트와 솔로,
  센드 끌기(+40 픽셀에 +10 dB), 효과 추가와 매개변수 끌기, EQ 대역, 우회, 순서, 지우기, 버스 추가와 센드와 이름 바꾸기(센드가 따라감)와
  지우기(센드도 지움), 마스터 페이더, 버스 뮤트, 모두 되돌리면 처음 글과 같음, 다시 실행, 저장한 파일을 다시 읽으면 같음
- `--self-test`: 「네온 비」 준비 1.9초 3.04초 진행, 「붉은 별」 준비 1.5초 2.97초 진행
- 실시간 부하(「네온 비」 60초부터 15초, 블록 256): 평균 부하 이전 커밋 0.37, 지금 0.33 (기계 부하 평균 8~16 에서 세 번씩 번갈아 잼)
- 고친 것: 파일에서 뮤트한 트랙이 실시간 재생의 첫 블록에 새어 나왔다 (뮤트 게인이 1 에서 0 으로 줄었다). 오디오 스레드가 블록마다
  사이드체인 이름 목록을 새로 할당했고, 리미터의 최솟값 대기열(deque)도 할당했다. 모두 할당하지 않게 바꿨다
- 스냅숏과 편집 시험이 앱 설정(최근 파일, 믹서 보기)을 쓰지 않는다

## 6. 남은 것

- 플러그인 효과(VST3, AU 삽입)는 D4 에서
- 믹스를 바꾼 뒤 모니터 게인을 다시 재지 않는다 (D6 의 라우드니스 측정)
- 버스와 마스터 효과의 지연을 실시간 재생에서 맞추지 않는다 (리버브 1024 샘플, 오프라인은 맞춘다)
- 컴프레서와 리미터의 게인 감소 표시, RMS 와 LUFS 미터
- 효과 매개변수와 페이더의 자동화 곡선
- 버스 솔로, 버스에서 버스로 보내기, 트랙 순서 바꾸기
- 센드가 슬롯보다 많으면 가려진 센드는 메뉴로만 고친다 (레벨 끌기는 보이는 슬롯에서만)
- 잔향 시간을 끌면 끌 때마다 메시지 스레드에서 홀 IR 을 다시 만든다 (12초 잔향에서 무거울 수 있다)
