# D18. 반복 녹음의 테이크와 컴핑

> 작성일: 2026-10-23. 계기: 상용 DAW 와 견준 빈자리(D8 1절)의 "테이크 레인과 고르기". 오디오 녹음은 반복 구간을 한 번 돌면 끝났고,
> 여러 번 불러 보고 좋은 부분을 고를 길이 없었다.

## 1. 목표

반복 재생 중에 오디오를 녹음하면 반복마다 테이크가 남는다. 테이크 가운데 하나를, 또는 고른 구간만 다른 테이크로 골라 이어 붙인다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 녹음 | 반복 재생 중이면 녹음기가 위치가 끊겨도(반복의 끝에서 처음으로) 멈추지 않고 한 파일에 이어 쓰며, 끊긴 자리마다 반복(pass)의 파일 안 자리와 곡 위치를 적는다 (오디오 스레드에서 고정 크기 표, 256 반복까지) | 파일 하나, 테이크는 그 파일의 다른 자리 |
| 곡에 넣기 | 반복마다 클립 하나 (같은 파일, `offsetSeconds` 가 그 반복의 자리). 마지막 반복만 들리고 앞의 것은 `"muted": true` (클립 뮤트). 편집 하나 | 마지막으로 부른 것이 보통 가장 낫다. 고른 것만 들린다 |
| 클립 뮤트 | 클립의 `muted`: 재생과 렌더에서 빠진다 (곡 길이에는 들어간다) | |
| 보이기 | 트랙에 뮤트한 클립이 있으면 들리는 클립은 레인 위쪽에, 뮤트한 테이크는 레인 아래의 띠(12 px)에 흐리게. 띠를 눌러 그 테이크를 고르고 메뉴를 연다 | 겹친 테이크가 가리지 않는다 |
| 테이크 고르기 | 클립 메뉴의 "테이크" 에 그 클립과 겹치는 클립(테이크 1, 2, ...)과 파일 안 자리. 고르면 그 테이크가 그 자리에서 들리고 겹친 다른 클립은 그 자리에서 뮤트된다. 트랙 보기에서 고른 구간이 그 클립과 겹치면 그 구간만 고르고, 걸친 클립은 구간 경계에서 나눈다 (늘인 클립도 파일의 자리를 늘이기로 센다). 클립 메뉴에 "뮤트" | 구간을 끌어 고르고 테이크를 고르는 것이 컴핑이다 |

## 3. 체크리스트

- [x] 엔진: 클립의 `muted` (검사, 쓰기, 재생기와 렌더에서 빠지기), `AudioTakeRecorder` 의 반복 녹음 (`loopPasses`, `AudioTake::passes`)
- [x] 앱: 반복 재생 중의 오디오 녹음, 테이크를 클립으로, 레인의 테이크 띠, 클립 메뉴의 테이크와 뮤트, `useTake`
- [x] 시험: 엔진 단위 시험 2건, `--edit-test` 7건
- [x] 문서: README 두 판, CLAUDE.md, `docs/plans/index.md`

## 4. 확인한 것

- 엔진 단위 시험: 1000 에서 세 블록, 1000 으로 돌아가 두 블록, 다시 한 블록을 받으면 반복 셋 (파일 0, 1536, 2560 샘플에서 1536, 1024, 512 샘플), 반복 녹음이 아니면 하나.
  같은 자리에 겹친 두 클립 가운데 하나를 뮤트하면 한 클립만의 렌더와 1e-6 안에서 같다.
- 앱 `--edit-test` 7건: 2 박부터 1초 반복 두 번의 녹음이 2 박의 클립 둘 (파일의 0초와 1초, 앞의 것은 뮤트), 뮤트한 테이크가 들리는 클립 아래 띠에,
  첫 테이크를 고르면 첫 것이 들린다, 고른 구간(2~3 박)에서 둘째 테이크를 고르면 클립 넷 (구간 안은 둘째 테이크의 1~1.5초, 뒤는 첫 테이크의 0.5초부터), 실행 취소.
- 실제 입력 장치의 반복 녹음은 저자가 확인한다.
- 시험을 만들며 `useTake` 가 편집 뒤에 앞서 잡은 템포 지도 참조를 써서 충돌했고 (편집이 템포 지도를 새로 만든다), 충돌한 실행이 남긴 시험 폴더 때문에
  다음 실행의 테이크 번호가 어긋났다. 문구를 편집 전에 만들고, `--edit-test` 가 시작할 때 시험 폴더를 비우게 고쳤다.

## 5. 남은 것

- MIDI 의 반복 녹음 테이크는 없다 (MIDI 녹음은 반복 끝에서 그 반복의 음을 남긴다).
- 레인을 테이크마다 펼쳐 보이는 화면과 끌어서 고르기(스와이프 컴핑)는 없다. 테이크 띠는 겹친 테이크를 한 줄에 그린다.
