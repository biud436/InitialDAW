# D27. 워프 마커와 오디오 퀀타이즈

> 작성일: 2026-10-23. 계기: 상용 DAW 는 오디오 클립 안의 자리(어택)를 곡의 박에 묶는 마커를 두고, 마커 사이를 늘이고 줄여
> 녹음의 박을 고친다 (오디오 퀀타이즈). 타악기는 늘이지 않고 어택마다 잘라 옮기는 방식도 둔다. D16 의 클립 늘이기와 D23 의 어택 찾기 위에 올린다.

## 1. 목표

- 클립의 `warp` 마커: 파일의 초가 곡의 박에 놓인다. 마커 사이를 곡의 템포 지도에 맞춰 늘이고 줄인다.
- 오디오 퀀타이즈: 클립의 어택을 찾아 격자(박)로 끌어오는 마커를 쓴다 (세기, 스윙).
- 트랙 보기에서 마커를 보고, 끌어 옮기고, 더하고, 지운다.
- 워프 방식 둘: 늘이기(음높이 그대로)와 자르기(마커마다 잘라 그 자리에서 원래 빠르기로, 타악기의 어택을 지킨다).

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 형식 | 클립의 `"warp": [{ "seconds", "beat" }]` (둘 이상, 초와 박이 함께 오름차순). 곡의 박은 `startBeat + beat - W(offsetSeconds)` (W 는 마커 사이를 선형으로 이은 파일의 초에서 박). 박은 차이만 쓴다 | 앞을 자르거나 나누는 편집(`offsetSeconds` 와 `startBeat` 를 함께 옮긴다)이 마커를 고치지 않아도 같은 소리를 낸다. 지금의 자르기, 나누기, 편곡 함수가 그대로 맞다 |
| 마커 밖 | `sourceBpm` 이 있으면 그 빠르기, 없으면 끝 쪽 마커 사이의 빠르기로 잇는다 | 마커 밖으로 클립을 늘여도 소리가 끊기지 않는다 |
| 함께 쓰기 | `stretch`(고정 배수)와 함께 쓸 수 없다 (마커가 늘이기를 담는다). `pitchSemitones` 는 늘이기 방식에서만 | 같은 뜻을 두 곳에 적지 않는다 |
| 늘이기 | 클립 전체를 Signalsmith Stretch 로 한 번 만든다 (D16 의 `renderStretched`, 블록마다 `clipSourceAt` 의 빠르기). 캐시 열쇠에 마커와 템포 지도 | 곡 위치만의 함수라 실시간과 렌더가 같다 |
| 자르기 | `"warpMode": "slice"`: 마커의 10 ms 앞에서 자른 조각을 곡의 그 자리에서 원래 빠르기로 튼다. 자리보다 길면 다음 조각 앞에서 3 ms 로 줄이고, 짧으면 무음의 틈. 머리는 1 ms 로 키운다 | 마커보다 먼저 시작한 어택(같은 칸의 킥과 하이햇이 몇 ms 어긋난 자리)의 머리가 제 조각에 남는다. 늘이기는 킥의 어택을 번지게 한다 (아래 4절) |
| 퀀타이즈 | 클립 구간의 어택(`detectOnsets`)마다 지금 곡의 박 b 를 격자 t 로 `b + (t - b) x 세기` 만큼 (스윙은 둘째 칸을 격자/3 x 스윙 늦춘다). 클립의 양 끝(10 ms 안의 어택 포함)은 제자리 마커. 순서가 뒤집히거나 같은 자리로 가거나 이웃 마커 사이가 4배 넘게 늘고 줄면 옮길 거리가 큰 마커를 뺀다. 옮길 마커가 없으면 바꾸지 않는다 | 이미 마커가 있는 클립도 지금의 지도에서 다시 계산한다 (세기 50% 를 두 번 하면 다가간다) |
| 마커 편집 | 엔진의 `withWarpMarkerAdded` (지금 자리 그대로, 마커가 없으면 양 끝도), `withWarpMarkerMoved` (이웃 사이로 묶는다), `withWarpMarkerRemoved` (둘보다 적으면 모두 지운다). 클립 머리의 박이 바뀌면 `startBeat` 를 옮겨 다른 마커는 곡의 같은 박에 남는다 | 마커 하나를 옮기면 그 둘레만 늘고 준다 |
| 어택의 자리 | `detectOnsets` 의 거슬러 찾기를 고쳤다: -12 dB 아래에서도 한 걸음(0.5 ms)에 2 dB 넘게 오르는 머리는 -40 dB 까지 따라간다 | 실제 킥은 5 ms 남짓 걸려 차올라 마커가 어택 머리보다 4~5 ms 늦었다 (자르기에서 머리가 앞 조각에 남아 어택이 두 번 났다) |
| 화면 | 클립 아래 모서리의 삼각형과 옅은 세로줄. 삼각형을 끌면 그 마커를 옮기고 (격자에 맞추고 ⌘ 는 맞추지 않는다), ⌥ 누르기는 지우고, 클립을 두 번 누르면 그 자리에 더한다. 클립 메뉴: 어택을 격자에 맞추기 (1/4, 1/8, 1/16, 셋잇단 1/8, 1/16 마다 세기 100, 75, 50, 25%), 워프 마커 지우기, 워프 방식 (늘이기, 자르기) | 놓을 때 편집 하나 |
| 명령행 | `music-render arrange song.json quantize-audio <트랙> --grid 1/16 [--strength 100] [--swing 0] [--mode stretch\|slice] [--clip <n>]`, `unwarp <트랙> [--clip <n>]` | 에이전트와 생성기도 쓴다 |

## 4. 확인한 것

- 지도: 파일 0~1초를 1 박, 1~2초를 2 박에 둔 클립이 120 BPM 에서 440 Hz 를 0.5초, 880 Hz 를 1초 동안 낸다 (높이 그대로). 실시간이 오프라인과 1e-5 안. 나눈 뒤쪽 클립은 같은 마커로 같은 자리를 낸다.
- 퀀타이즈 (만든 소리: 120 BPM 8분음표 열여섯 타격, ±30 ms 어긋남): 렌더의 어택이 격자에서 가장 크게 2.83 ms (늘이기), 1.33 ms (자르기). 어택 찾기 자체의 어긋남이 이만큼이다.
  세기 50% 는 어긋남을 반으로. 자르기의 조각 안은 파일과 같다 (차이 1e-5 아래).
- 실제 드럼 세트 (「새벽 세 시」의 킥, 스네어, 하이햇 스템 9~12 마디, 16분음표 스윙 26.6 ms 와 휴머나이즈): 엇박의 어택이 평균 24.1 ms 늦다 (10~90%: -4.8~+27.2 ms).
  1/16 곧은 격자로 맞추고 각 마커 둘레(앞 5 ms, 뒤 40 ms)의 파형을 원본과 상관으로 맞춰 보면, 자르기는 61 타격 모두 격자에서 0 샘플 (상관 1.000), 늘이기는 -4.5~+4.1 ms (10~90%)이고
  파형이 바뀐다 (상관 중앙값 0.62). 타악기는 자르기, 선율과 목소리는 늘이기를 쓴다.
- 어택 찾기를 고친 뒤 D23 의 만든 드럼 루프는 가장 크게 2.38 ms 앞 (이전 1.9 ms), 조각과 템포 시험은 그대로 통과.

## 5. 남은 것

- 자르기의 틈을 채우는 방식(조각 끝을 되풀이하기)이 없다. 늘어난 자리는 무음이다.
- 템포를 모르는 녹음에서 곡의 템포 지도를 만드는 것(녹음을 따라 템포 점 찍기)은 없다.
- 여러 트랙을 한 기준 트랙의 어택으로 함께 맞추는 묶음 퀀타이즈(드럼 멀티트랙)는 없다.
