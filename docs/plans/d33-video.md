# D33. 영상 트랙

> 작성일: 2026-10-31. 계기: [D33 이후의 계획](next-stages.md) 의 첫 단계. 이 엔진이 처음 한 일이 홍보 영상 음악이고, 상용 DAW 가 모두
> 영상에 맞춰 음악을 쓰는 화면을 갖췄다. 지금까지는 영상과 맞추는 길이 명령행 밖(영상 편집 프로그램)에 있었다.

## 1. 목표

- 영상을 곡에 붙여 재생 위치의 화면을 보며 쓴다 (영상 레인의 섬네일과 타임코드, 영상 창).
- 장면이 바뀌는 자리를 찾아 사람이 골라 마커로 둔다.
- 영상의 소리를 오디오 트랙으로 가져온다.
- 음악을 영상에 입혀 내보낸다 (화면은 다시 인코딩하지 않는다).

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 곡 형식 | 최상위 `video`: `{ "file", "offsetSeconds" }`. 영상의 0초가 곡의 `offsetSeconds` 초에 놓인다 (음수면 영상 앞이 곡 앞으로 나간다). 소리에 쓰지 않는다. 파일은 곡 폴더 기준 (앱은 곡 폴더 안이면 상대 경로, 밖이면 절대 경로로 적는다) | 영상은 초로 흐른다. 템포를 바꾸거나 마디를 넣어도 영상은 그 초에 있다 (편곡 함수가 `video` 를 옮기지 않는다) |
| 읽기 | 엔진의 `media/Video` (Objective-C++, AVFoundation, ARC): 정보(`probeVideo`), 시각의 프레임(`VideoFrames`, `AVAssetImageGenerator` 허용 0), 재생용 차례로 풀기(`VideoDecoder`, `AVAssetReader`, 시작 시각에 보이는 프레임부터), 소리(`readVideoAudio`, 소리 트랙을 모두 섞는다). 다른 플랫폼은 `VideoStub.cpp` 가 "영상 없음" | 새 의존성이 없다. JUCE 를 쓰지 않아 자체 프레임워크로 옮길 때 그대로 간다 |
| 프레임 빠르기 | 영상 트랙의 가장 짧은 프레임 길이를 분수로 (`FrameRate`, 29.97 은 30000/1001). 프레임 번호는 `floor(t x fps)`, 경계 1 마이크로초 안은 다음 프레임 | 29.97 을 소수로 다루면 1시간에 3.6 프레임 어긋난다 |
| 타임코드 | `media/Timecode` (플랫폼과 상관없다): 시:분:초:프레임, 29.97 과 59.94 는 드롭 프레임 (분마다 앞 번호 둘, 넷을 건너뛰고 10분째는 건너뛰지 않는다, 구분은 `;`) | SMPTE 12M |
| 장면 바뀜 | 프레임을 네 사분면으로 나눠 밝기 히스토그램(32칸)을 잰다. 이웃 프레임 차이(0..1)가 0.2 위이고 앞뒤 0.5초 차이의 중앙값의 3배 위인 자리가 후보, 0.4초 안의 후보는 큰 것 하나. 후보는 곡에 쓰지 않고 영상 레인에 보이며 사람이 골라 마커로 둔다 | 빠르게 움직이는 장면의 큰 차이를 후보로 잡지 않는다. 히트 포인트를 손으로 찾지 않는다 |
| 영상에 입히기 | 엔진의 `writeScoredVideo`: 영상 샘플은 `AVAssetReader` 의 압축 샘플을 `AVAssetWriter` 로 그대로 옮기고 (회전 정보도), 소리는 AAC (기본 256 kbps, 48 kHz 까지). 소리 길이는 영상 길이, 영상의 t 초에 곡의 t + offset 초. 영상의 원래 소리는 빼거나 섞는다 | 화질이 그대로이고 빠르다 |
| 렌더러 | `RenderOptions::onAudio`: 자른 뒤의 마지막 소리를 받는다. 명령행과 앱의 내보내기가 같은 길로 영상에 입힌다 | 소리 파일을 거치지 않는다 |
| 명령행 | `video-info`, `video-frame --at --output f.png`, `video-scenes [--song]`, `video-audio --output`, `video-pattern` (프레임 번호를 칸으로 새긴 시험 영상), `render song.json --output scored.mp4 [--video] [--video-offset] [--video-sound mix]` | 홍보 영상 파이프라인과 시험이 쓴다. PNG 는 ImageIO 로 쓴다 |
| 화면 | 트랙 보기의 마커 띠 아래 영상 레인 (타임코드 줄, 섬네일, 장면 후보). 섬네일은 뒤 스레드가 칸(프레임 길이의 2의 거듭제곱 배)마다 가까운 키프레임 허용으로 읽어 둔다. 영상 창(⌥V)은 멈춘 동안 그 시각의 프레임을, 재생 중에는 차례로 풀어 앞서 읽어 둔 프레임을 보이고 재생기의 출력 지연과 장치 출력 지연을 빼서 들리는 소리에 맞춘다 | 키프레임 사이가 긴 H.264 에서 탐색은 느려도 되고 재생은 차례로 푸는 길을 따로 둔다 |
| 편집 | 영상 레인을 끌면 영상의 자리 (격자에 맞추고, ⌘ 는 프레임에 맞춘다, 곡 앞은 첫 마디나 박의 격자). 후보를 두 번 누르면 "장면 N" 마커, 레인의 오른쪽 클릭 메뉴로 모두 마커로. 영상의 소리는 곡 폴더 `audio/<영상> 소리.wav` 의 오디오 트랙 "영상 소리" (곡 앞의 부분은 클립의 `offsetSeconds` 로 자른다). 모두 편집 하나씩 | |

## 4. 잰 것

- 시험 영상(H.264, 키프레임 2초마다, B 프레임)을 24, 25, 29.97, 30 fps 로 만들어 프레임마다 앞 끝(+0.6 ms), 가운데, 뒤 끝(-0.6 ms)과 무작위 시각 60곳에서
  읽은 프레임 번호가 모두 `floor(t x fps)` 였다. 차례로 풀기도 네 시작 시각(0, 1.234초, 두 프레임째, 4.9초)에서 끝까지 번호가 하나씩 오른다.
- 드롭 프레임 타임코드: 29.97 의 두 시간(215784 프레임)과 59.94 의 20분(71928 프레임)이 하나씩 센 것과 모두 같다.
- 장면 바뀜: 30, 25 fps 시험 영상의 잘린 자리 넷을 모두 그 프레임에서 찾고 거짓 후보가 없다. 6초 29.97 fps 영상의 두 자리(44, 119 프레임)도 같다.
- 영상에 입히기: 원본과 결과의 영상 압축 샘플 120개의 바이트 해시가 모두 같다. 표시 시각은 편집 목록을 지나 견준다: AVAssetWriter 의 mp4 는 B 프레임 때문에
  첫 샘플을 미디어 시간축의 두 프레임 뒤에 두고 편집 목록으로 0초에 보이고, mov 는 0초에 둔다 (mov 에서 mp4 로 옮기면 미디어 시각이 0.08초 다르지만 보이는 시각은 같다). 다시 읽은 소리와 곡의 상호상관은 지연 0 샘플, 상관 0.99989 (offset +0.5초와 -1초).
  -1초면 영상 앞 0.95초가 -60 dB 아래. 원래 소리를 섞으면 곡과 원래 소리의 합과 상관 0.99 위. 같은 입력을 두 번 입히면 mp4 파일은 만든 시각이 달라 바이트가 다르지만 디코딩한 소리는 같다.
- 영상의 소리: 시험 영상의 클릭 셋 (0.5, 1.25, 2.0초) 이 다시 읽은 소리에서 지연 1 ms 안 (AAC 의 앞 지연은 AVFoundation 이 지운다).
- 앱: 영상 창이 재생 중 0.04초마다 옮긴 시각의 프레임을 모두 맞게 보이고, 뒤로 뛰기와 멈춘 탐색, 영상 밖도 맞다.

## 5. 남은 것

- 영상 레인의 섬네일은 그 칸의 절반 안의 아무 프레임이다 (키프레임). 프레임까지 맞춘 섬네일은 확대가 클 때 느려서 두지 않았다.
- 장면 바뀜은 잘린 자리만 찾는다 (서서히 바뀌는 디졸브와 페이드는 찾지 않는다).
- 영상 창은 따로 띄운 창 하나다 (앱 안에 붙이는 자리는 없다). 실제 창과 재생 중의 맞음은 저자가 본다.
- mp4 파일의 만든 시각 때문에 같은 입력의 결과가 바이트까지 같지 않다 (AVAssetWriter 가 정한다).
