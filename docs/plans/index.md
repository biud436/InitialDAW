# InitialDAW 계획과 진행

> 작성일: 2026-10-05. 작업을 시작하기 전에 이 문서를 읽고, 끝나면 단계 문서의 체크리스트와 아래 진행 표를 갱신한다.

## 1. 목표

남이 만든 DAW 를 쓰지 않고 우리 DAW 를 만든다. 곡의 형식은 음악 엔진이 읽는 Composition JSON 하나다.
사람은 앱에서 듣고, 보고, 고치고, 에이전트와 작곡 생성기는 같은 JSON 을 쓴다. 앱은 파일이 바뀌면 다시 불러오므로
두 흐름이 한 파일 위에서 만난다.

```text
작곡 생성기, 에이전트 ─┐
                        ├─ Composition JSON ─ 음악 엔진(engine/) ─ 실시간 재생(앱) 또는 WAV(명령행)
사람(앱의 편집) ───────┘
```

원칙:

- 재생과 내보내기는 같은 트랙 사슬(`buildTrackChain`)을 지난다. 앱에서 들은 소리가 내보낸 WAV 와 같아야 한다 (시험으로 지킨다).
- 엔진에 없는 것을 앱에서 흉내 내지 않는다. 앱의 기능은 엔진의 기능을 먼저 넓히고 그 위에 올린다.
- 화면은 창 없이 PNG 로 그려 확인하고(`--snapshot`), 재생 경로는 창 없이 작은 소리로 시험한다(`--self-test`).

## 4. 검증 고리

구현은 스스로 빌드하고 시험을 돌려 통과할 때까지 반복한다. 시험을 약하게 고쳐 통과시키지 않는다. 같은 실패가 세 번
반복되면 멈추고 저자에게 알린다.

```bash
./build.sh                                   # 빌드와 CTest (엔진 단위, 명령행, 앱 스냅숏)
APP=build/app/InitialDAW_artefacts/Release/InitialDAW.app/Contents/MacOS/InitialDAW
$APP --snapshot /tmp/daw.png --track 3 --at 40 프로젝트.json   # 화면을 PNG 로 (창 없음)
$APP --self-test --at 60 프로젝트.json        # 오디오 장치를 열고 -60 dB 로 3초 재생, 위치가 나아가는지
build/engine/music-render realtime 프로젝트.json --from 60 --seconds 15   # 실시간 부하
```

게임처럼 창을 띄웠다 닫는 시험은 하지 않는다. 앱의 창은 저자가 직접 띄운다.
