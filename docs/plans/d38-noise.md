# D38. 잡음 줄이기

> 작성일: 2026-11-16. 계기: [D33 이후의 계획](next-stages.md) 의 순서. 집에서 녹음한 소리에는 넓은 대역의 쉿 소리, 전기 험(50, 60 Hz 와 배음), 클릭이 섞인다.
> 학습된 모델 없이 신호 처리 계산으로 줄인다.

## 1. 목표

- 클립마다 잡음, 험, 클릭을 줄이는 값을 곡에 남기고, 재생과 렌더가 같은 소리를 낸다.
- 잡음만 있는 자리는 20 dB 넘게 줄이고 신호는 1 dB 안에 둔다. 험과 배음은 -40 dB. 클릭은 모두 메우고 원래 신호와의 차이는 -40 dB 아래.
- 음악을 험이나 잡음으로 잘못 보고 깎지 않는다 (실제 녹음으로 확인한다).

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 형식 | 클립의 `"restore": { "noiseDb", "profile": { "seconds", "lengthSeconds" }, "humHz", "declick" }`. `noiseDb` 는 줄이는 양의 상한 (0~40 dB, 0 이면 잡음은 그대로), `profile` 은 잡음만 들리는 구간 (파일의 초, 없으면 자동), `humHz` 는 50, 60 (그 근처에서 잰다) 이나 `"auto"`, `declick` 은 참거짓. 하나도 켜지 않은 값은 쓰지 않는다 | 다른 클립 처리와 같이 파일의 초. 클립을 옮기고, 자르고, 나눠도 같은 녹음에 붙어 있다 |
| 계산하는 때 | 클립을 준비할 때 파일 전체의 소리(렌더 샘플레이트, 뒤집기 반영)를 한 번 고치고 캐시한다 (`clipAudio`, 열쇠는 파일, 샘플레이트, 뒤집기, 복원 값). 재생, 늘이기, 자르기 방식, 높이 재기가 모두 고친 소리를 쓴다 | 늘이기와 같은 길. 실시간과 오프라인이 같은 샘플이다. 클립 경계와 상관없이 같은 결과 |
| 차례 | 클릭, 험, 잡음 | 클릭과 험이 잡음 지문에 섞이지 않게 |
| 잡음 | STFT (2048, 홉 512, 해닝 창 둘, 96 kHz 넘으면 4096). 잡음 지문은 고른 구간의 칸마다 평균, 없으면 소리 안의 가장 조용한 10% 프레임의 칸마다 중앙값 (지수 분포라 ln 2 로 나눈다). 판정 지향 위너 이득 (α 0.98), 주파수 방향으로 [¼ ½ ¼] 두 번, 줄어들 때는 60 ms 에 걸쳐, 아래는 `noiseDb`. 채널은 같은 이득 (스테레오 자리를 지킨다) | 계획의 방식. 이득 다듬기가 음악적 잡음(반짝이는 칸)을 막는다 |
| 자동 지문의 안전 | 큰 쪽 10% 프레임이 조용한 쪽보다 6 dB 넘게 크지 않거나, 잡음 추정이 -30 dBFS 보다 크면 줄이지 않고 까닭을 알린다 (`noiseSkipped`) | 쉬지 않고 이어지는 음(색소폰 루프 샘플)은 조용한 10% 가 음악이라 -6.5 dBFS 를 "잡음"으로 잡았다. 그대로 줄이면 음이 깎인다 |
| 험 | 긴 FFT (빈 0.4 Hz 아래) 의 평균 스펙트럼에서 기본 주파수를 f, 2f, 3f 의 봉우리로 찾는다: 공칭값에서 ±0.3 Hz 안, 둘레(3~20 Hz 밖)의 중앙값보다 10 dB 위, 그리고 0.7초 구간마다 녹음 내내 고르게 (소리가 있는 구간의 4분의 3) 솟아야 한다. 배음 열 개 자리에 노치 (뚜렷한 배음은 잰 주파수, 아니면 k 배). `"auto"` 는 50 과 60 가운데 더 뚜렷한 쪽 | ±0.3 Hz 와 고르게 울리기가 없으면 피아노 B1 (61.7 Hz), 북의 울림 (49.4 Hz), 기타의 낮은 음을 험으로 잡았다 |
| 험 필터 | 배음마다 RBJ 노치 (대역폭 2 Hz) 둘을 앞으로 잇달아. 처음 0.5초에서 잰 험(배음마다 크기와 위상, 최소 제곱)을 1초 앞에 이어 붙여 필터를 데운다 | 앞뒤로 거는 영위상 노치는 음의 시작 앞에 노치 주파수의 울림(프리 에코)을 만들고 처음 0.3초는 험이 남았다 (잡음 지문을 -60 dBFS 로 잘못 잡았다) |
| 클릭 찾기 | 2차 차분이 둘레(256 샘플 칸 중앙값의 아홉 칸 중앙값)의 10배를 넘는 자리, 꼬리는 3배까지. 2 ms 보다 길면 어택으로 보고, ±25 ms 안에 크기가 비슷한(3분의 1 넘는) 튐이 둘 이상이면 되풀이되는 소리(성문 펄스)로 보고, 뒤가 앞보다 12 dB 넘게 크면 소리의 시작으로 보고 두지 않는다. 채널 평균에서 찾고 채널마다 같은 자리를 메운다 | 말소리를 닮은 신호에서 성문 펄스 612곳을 클릭으로 잡았다 (되풀이 검사로 0곳) |
| 클릭 메우기 | 양쪽 2048 샘플이 있으면 최소 제곱 메우기: 예측기는 짧은 예측 40차와 음높이 한 주기 앞(T-2~T+2, 정규화 자기상관 0.6 넘을 때)의 다섯 샘플, 주기가 없으면 짧은 예측 80차. 계수는 모르는 샘플이 없는 자리에서 최소 제곱으로, 빈 곳은 예측 오차 제곱합이 가장 작은 값으로. 문맥이 모자라면 앞쪽 예측과 뒤쪽의 거꾸로 예측을 잇는다 | 앞뒤 예측을 잇는 방법은 -33 dB, 짧은 예측만의 최소 제곱은 -38.5 dB 에서 멈췄다 (비브라토가 있는 유성음 위의 긴 클릭). 음높이 탭을 더해 -44.8 dB |
| 뒤집기 | `withClipReversed` 가 잡음 지문 구간도 거울 자리로 옮긴다 | 뒤집은 클립의 초는 파일 끝에서 센다 |
| 화면 | 클립 메뉴의 "잡음 줄이기": 잡음을 줄이는 양 (끄기, 6, 12, 18, 24 dB), 잡음 지문: 자동, 고른 구간을 잡음 지문으로 (트랙 보기에서 고른 구간의 곡의 초를 클립의 파일의 초로), 험 지우기 (끄기, 50 Hz, 60 Hz, 자동), 클릭 메우기, 모두 끄기. 결과(메운 클릭, 잰 험과 배음, 잡음 크기, 줄이지 않은 까닭)는 뒤 스레드에서 재생 샘플레이트로 재서 상태 줄에 알린다 (재생기와 캐시를 함께 쓴다). 클립 이름 뒤에 "잡음 줄임" | 화면이 멈추지 않는다 |
| 명령행 | `restore <오디오> --output <파일> [--noise dB] [--profile 초:길이] [--hum 50/60/auto] [--declick]` (결과 JSON), `arrange song.json restore <트랙> [--clip n] [같은 옵션, --hum off, --no-declick]` (옵션이 없으면 처음 켤 때 12 dB, 결과를 `restored` 에), `unrestore <트랙> [--clip n]` | 생성기와 에이전트도 쓴다 |

## 4. 확인한 것

- 잡음: 화음(A3, C#4, E4)과 말소리를 닮은 소리(130~170 Hz 를 오가는 기본음, 포먼트 셋, 음절 다섯)에 화음보다 30 dB 아래의 흰 잡음 (채널마다 다르게).
  `noiseDb` 24 로 잡음만 있는 세 자리가 모두 -24.0 dB (자동 지문과 고른 구간 모두). 신호의 크기는 화음 -0.04 dB, 말소리 -0.16 dB (고른 구간 -0.14 dB),
  깨끗한 신호와의 차이는 화음 -42.2 dB (잡음 섞인 것 -30.0 dB), 말소리 -27.7 dB (-24.2 dB). 잰 잡음 크기는 넣은 크기와 1.5 dB 안.
- 험: 60 Hz (자동) 를 60.001 Hz 로, 49.9 Hz (50 근처) 를 49.900 Hz 로 재고, 배음 열 개 가운데 가장 덜 준 것이 -43.9 dB, -45.5 dB. 화음은 0.3 dB 안.
  험이 없는 신호에서는 찾지 않는다.
- 클릭: 한 샘플, 세 샘플, 1 ms 에 사라지는 튐 서른 개를 모두 찾고 (잘못 찾은 곳 0), 메운 뒤 원래 신호와의 차이 -44.8 dB (클릭이 있을 때 -19.5 dB). 클릭 없는 신호에서는 0곳.
- 클립 재생: 곡의 클립으로 렌더한 소리와 같은 값으로 직접 고친 소리의 차이 0 (`restore_runs_inside_clip_playback`). 뒤집으면 10초 파일의 7.5~8.5초 지문이 1.5~2.5초로.
- 명령행: 쉿 소리(-66 dBFS), 60 Hz 험과 2, 3 배음, 클릭 셋이 섞인 2초 녹음에서 클릭 3, 험 59.969 Hz, 잡음 -65.5 dBFS.
- 실제 녹음 (`restore --declick --hum auto --noise 12`):
  - 험: Sonatina 그랜드 피아노 FF B1 과 PP G4, FreePats 기타, VSCO 심벌에서 50.0 Hz 둘레 (49.97~50.06 Hz) 의 험을 찾았다. 녹음 내내 고르게 울리는 실제 험이다.
    고치기 전에는 피아노 B1 의 음 (61.7 Hz) 과 스네어의 울림 (49.4~51.1 Hz) 을 험으로 잡았다.
  - 클릭: 북 셋 0~1곳, 기타 0~1곳. 국립국악원 해금 녹음 (40~50초) 에서 8~12곳: 음 사이의 무음(-76 dBFS)에서 홀로 튀는 5곳은 실제 클릭(편집점),
    활 소리 위의 7곳은 0.1~0.8 ms 의 튐이고 고친 양이 그 자리 소리보다 8~34 dB 작다.
  - 잡음: 쉬지 않는 색소폰 루프 샘플 둘은 조용한 곳이 없어 줄이지 않고 까닭을 알린다.
- 앱: 줄이는 양, 같은 값은 편집이 아님, 험 자동과 클릭, 저장 형식, 고른 구간(곡의 40~40.5박)이 파일의 0~0.25초 지문, 클립 밖의 구간은 지문이 아님, 끄기.
  스냅숏에서 켠 클립의 이름 뒤에 "잡음 줄임".

## 5. 남은 것

- 클립의 파형은 원래 파일로 그린다 (고친 소리의 파형을 그리면 줄어든 잡음과 지운 클릭이 보인다).
- 줄인 양을 듣기 전에 견주는 길 (원래 소리와 번갈아 듣기, 걸러 낸 잡음만 듣기) 이 없다.
- 클릭 찾기의 민감도는 고정이다 (10배). 활 소리처럼 거친 소리에서는 짧은 튐도 메운다.
- 실제 집 녹음 (목소리, 악기) 과 실제 창의 메뉴는 저자가 확인한다.
- 전체 시험 중 한 번, 큰 빌드 직후의 CTest 에서 `unit` 이 실패했고 다시 돌리면 통과했다 (단독 실행 290개 모두 통과). 실패한 확인을 잡지 못했다.
