# D9. 오디오 트랙

> 작성일: 2026-10-22. 계기: 상용 DAW 와 견준 빈자리 표(D8 1절)에서 가장 큰 칸. 지금까지 소리는 음표가 악기를 울려서만 났다.
> 오디오 파일(녹음, 효과음, 다른 곳에서 만든 소리, 레퍼런스 믹스)을 곡에 놓을 길이 없었다.

## 1. 목표

오디오 파일을 트랙의 클립으로 놓고 옮기고 자르고 페이드와 게인을 준다. 클립은 같은 트랙 사슬(효과, 페이더, 센드, 버스, 마스터)을 지나
실시간 재생과 내보내기가 같은 소리를 낸다. 다음으로 오디오 입력을 녹음해 클립으로 넣는다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 곡 형식 | 오디오 트랙은 악기가 `"audio"` (레지스트리에 들어 있는 내장 악기)인 트랙이고 `"clips": [{ "file", "startBeat", "offsetSeconds", "lengthSeconds", "gainDb", "fadeInSeconds", "fadeOutSeconds" }]` 를 쓴다. 파일 경로는 곡 파일의 폴더 기준 | 트랙의 나머지(믹서, 효과, 센드, 컨트롤러 곡선)는 다른 트랙과 같다. 악기 자리에 클립 재생기가 들어가므로 트랙 사슬을 따로 만들지 않는다 |
| 시간 | 자리는 박(템포 지도를 따른다), 길이와 파일 안의 시작은 초. 소리는 템포로 늘거나 줄지 않는다 | 녹음은 초 단위의 소리다. 타임 스트레칭은 뒤로 미룬다 |
| 재생 | 클립 재생기는 곡 위치(샘플)만의 함수: 블록의 첫 샘플에서 클립의 데이터를 읽는다. 멈춘 동안과 카운트인 동안은 조용하다(`setTransportPlaying`). 위치가 끊긴 블록(처음, 탐색, 반복)은 64 샘플 동안 키우고, 클립 양 끝에는 32 샘플 페이드를 늘 건다 | 탐색, 반복, 오프라인 렌더가 같은 샘플을 낸다 (시험으로 지킨다). 잘린 자리의 딸깍 소리를 막는다 |
| 파일 읽기 | 메시지 스레드(재생기 만들기, 편집 반영)에서 파일 전체를 읽어 렌더 샘플레이트의 스테레오로 바꿔 둔다. 같은 파일과 샘플레이트는 한 번만 (수정 시각이 바뀌면 다시). 샘플레이트 변환은 블랙맨 창을 씌운 sinc(양쪽 16 칸, 낮출 때 차단 주파수를 함께 낮춘다)이고 커널은 표로 만든다 | 오디오 스레드는 읽기만 한다. 1분 남짓의 파일이 0.6초 안에 준비된다 |
| 형식 | WAV, AIFF, FLAC, Ogg Vorbis, MP3 (JUCE 의 MP3 디코더를 켰다) | 흔히 쓰는 형식 |
| 편집 반영 | 클립을 바꾸면 `RealtimePlayer::apply` 가 클립 재생기의 목록만 바꿔 끼운다 (재생기를 다시 만들지 않는다) | 바꿔 낀 결과가 새로 만든 재생기와 샘플 단위로 같다 (시험) |
| 편곡 편집 | 시간 넣기와 지우기, 구간 복사와 붙이기, 내용 지우기는 클립을 구간 경계에서 나누고 파일 안의 시작을 옮긴다. 잘린 쪽의 페이드는 지운다. 길이가 적히지 않은 클립은 곡 폴더로 파일 길이를 읽는다 | 음표와 같은 규칙 (덮어쓰기, 구간 밖은 그대로) |
| 가져오기 | 파일 > 오디오 가져오기(⌘⇧A)와 트랙 보기에 끌어 놓기. 곡 폴더 밖의 파일은 곡 폴더의 `audio/` 에 복사한다 (같은 이름의 다른 파일이면 번호를 붙인다). 오디오 트랙 레인에 놓으면 그 트랙에, 아니면 파일마다 새 오디오 트랙. 클립에는 파일 길이를 적는다 | 곡 폴더 하나로 곡이 옮겨진다 |
| 앱의 클립 편집 | 몸통 끌기는 옮기기(⌥ 는 사본), 양 끝은 자르기, 위 모서리의 손잡이는 페이드. 구간 고르기와 같은 격자에 맞추고 ⌘ 는 맞추지 않는다. 오른쪽 클릭: 게인, 정규화(봉우리 -1 dBFS), 재생 위치에서 나누기(⌘T), 바로 뒤에 복제(⌘D), 페이드 지우기, Finder 에서 보기, 지우기(⌫). 놓을 때 편집 하나 | |
| 파형 | 파일을 256 프레임씩 나눈 봉우리 표(채널을 합친 최솟값과 최댓값)를 한 번 재서 그린다. 세로는 데시벨 눈금(-54 dBFS 가 0) | 스템처럼 여린 녹음도 모양이 보인다 |
| 아래 칸 | 오디오 트랙을 고르면 피아노 롤 대신 클립 편집 설명 (음표를 넣지 않는다) | |
| 오디오 녹음 | 오디오 트랙을 고르고 ⌥R (MIDI 녹음과 같은 단추, 카운트인). 입력이 꺼져 있으면 기본 입력의 앞 두 채널을 켠다 (그때 마이크 권한을 묻는다). 오디오 콜백이 블록마다 입력과 그 블록의 곡 위치를 녹음기에 넘기고, 녹음기는 재생 중인 첫 블록부터 받아 뒤 스레드가 곡 폴더의 `audio/<트랙> take N.wav` (24비트)에 쓴다. 재생이 멈추거나 위치가 끊기면(탐색, 반복) 테이크가 끝난다 | 오디오 스레드에서 잠금, 할당, 파일 입출력을 하지 않는다 (JUCE 의 ThreadedWriter, 20초 버퍼) |
| 녹음의 자리 | 클립의 시작 = 첫 블록의 곡 위치 - (재생기의 출력 지연 + 장치의 입력과 출력 지연). 곡 앞으로 넘어가면 파일의 앞을 건너뛴다 | 연주자는 출력에서 들은 소리에 맞춰 연주하고, 그 소리는 입력 지연 뒤에 들어온다 |

## 4. 확인한 것

- 엔진 단위 시험 8건: 120 BPM 에서 2박(1초)에 놓은 클립이 1.0~1.5초에 -6 dB 크기(RMS 0.177)로 울리고 앞뒤는 조용하다. 44.1 kHz 파일을 48 kHz 로
  렌더링해도 440 Hz 가 0.5 Hz 안이다. 길이가 없는 클립은 파일 끝까지 (둘째 초의 880 Hz). 페이드와 트랙 페이더(-12 dB). 실시간 재생이 오프라인 렌더와
  1e-5 안에서 같고, 멈춘 동안은 조용하며, 클립 가운데로 옮기면 처음 64 샘플 뒤부터 같다. 클립을 옮긴 편집을 반영한 재생기가 새로 만든 재생기와 샘플까지
  같다. 없는 파일은 경고와 무음. FLAC, Ogg Vorbis, MP3 를 써서 다시 읽으면 440 Hz. 6박에 두 박을 넣으면 클립이 둘로 나뉘고(뒤는 파일의 1.5초부터),
  다시 지우면 이음매 주변 40 샘플 밖에서 원래 렌더와 1e-5 안으로 같다.
- 엔진 단위 시험 3건 더 (`test_audio_take.cpp`): 카운트인 블록은 받지 않고 1000 샘플부터 세 블록을 받아 그 위치와 샘플 수를 알리며 위치가 끊기면 끝난다,
  파일 내용이 1e-6 안에서 같다(24비트), 모노 입력, 받은 것이 없으면 파일을 지운다, 있는 파일에는 쓰지 않는다. 리미터가 있는 트랙의 재생기는 그 지연을 출력 지연으로 알린다.
- 앱 `--edit-test` 273건 가운데 오디오 31건 (녹음 6건: 재생기가 없으면 시작하지 않는다, 테이크 번호, 2초에서 받은 1초 테이크가 지연 100 ms 앞의 3.8박에, 곡 앞으로 넘어가면 파일의 0.05초를 건너뛴다).
  가져오기와 클립 편집: 곡 폴더 밖의 파일을 가져오면 `audio/tone.wav` 로 복사하고 파일 이름의 트랙과 2초 클립, 같은 파일을 레인에 놓으면
  복사본을 다시 만들지 않고 그 트랙의 12박에. 붙은 두 클립의 경계에서 앞 클립의 끝을 잡는다 (처음에는 뒤 클립의 처음을 잡던 것을 고쳤다).
- `--self-test` (WH-1000XM5, 44.1 kHz): 피아노 두 트랙과 오디오 트랙 둘(59초 레퍼런스 믹스 포함)이 0.63초에 준비되고 3초 재생. 샘플레이트 변환을 표로 바꾸기 전에는
  8.0초가 걸렸다.
- 명령행 렌더: 오디오 트랙이 믹스와 스템(`Vocal_take.wav`, `Reference_mix.wav`)에 들어가고 경고가 없다.

## 5. 남은 것

- 오디오 입력 녹음은 창 없는 시험으로 실제 장치를 열지 않는다 (마이크 권한 창이 뜬다). 녹음기, 지연 계산, 테이크를 클립으로 넣는 길은 시험했고 실제 입력은 저자가 확인한다.
  블루투스 헤드폰의 마이크를 열면 macOS 가 헤드폰 출력을 통화 품질로 바꾼다. 입력 모니터링(입력을 트랙 사슬로 듣기)은 없다 (장치의 직접 모니터링을 쓴다).
- 타임 스트레칭과 음높이 바꾸기, 클립의 반복(루프 클립), 크로스페이드(겹친 클립)는 없다. 겹친 클립은 더해진다.
- 파형 봉우리 표는 처음 그릴 때 메시지 스레드에서 파일을 끝까지 읽는다 (1분 파일에 수십 ms).
- MIDI 내보내기는 오디오 트랙을 쓰지 않는다.
