# D8. 트랙과 편곡

> 작성일: 2026-10-22. 계기: 상용 DAW 에 견줄 만큼의 기능. 지금 앱은 곡 하나를 듣고, 음표와 믹서를 고치고, 녹음하고,
> 내보낼 수 있지만 곡의 뼈대를 바꾸는 길이 없다. 트랙을 더하거나 지울 수 없고, 마디를 넣거나 빼서 곡의 구조를 바꿀 수 없고,
> 여러 트랙에 걸친 구간을 복사할 수 없고, 구간에 이름을 붙일 수 없다. 이 단계는 곡 JSON 을 손으로 고치지 않고 앱에서 곡을 처음부터
> 끝까지 짤 수 있게 한다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 엔진 먼저 | 트랙 목록 편집과 시간 편집은 곡 JSON 트리를 받아 새 트리를 돌려주는 순수 함수(`composition/Arrange`)다. 앱은 바뀐 최상위 속성(tracks, buses, master, tempo, metadata, render, markers)을 편집 하나로 넣는다 | 에이전트와 생성기도 같은 함수를 명령행으로 쓴다. 창 없이 시험한다 |
| 트랙 이름 | 이름은 곡 안에서 하나뿐이다 (스템 이름). 복제와 새 트랙은 "이름 2" 처럼 비어 있는 이름을 고른다. 이름을 바꾸면 압축기의 `sidechain` 이 가리키는 이름도 바꾼다 (트랙, 버스, 마스터의 효과) | 사이드체인 키는 트랙 이름으로 가리킨다 |
| 트랙 지우기 | 지운 트랙을 키로 쓰던 압축기는 `sidechain` 을 지워 보통 압축기가 된다. 마지막 트랙은 지우지 않는다 (곡에는 트랙이 하나 넘게 있어야 한다) | 키가 없는 사이드체인은 곡 검사를 통과하지 못한다 |
| 트랙 색 | 트랙의 선택 필드 `color` ("#rrggbb"). 없으면 지금처럼 순서에 따른 색 | 렌더링에 쓰지 않는다. 사람이 고른 색만 곡에 남긴다 |
| 마커 | 최상위 `markers`: `[{ "beat": 0, "name": "도입" }]` (박 오름차순). 눈금자에 보이고, 재생 위치에 더하기, 끌어 옮기기, 두 번 눌러 이름 바꾸기, 앞뒤 마커로 옮기기. `export-midi` 는 마커 메타 이벤트(FF 06)로 쓰고 가져오기는 읽는다 | 구간 이름은 곡의 것이다. Music IR 의 구간과는 따로 둔다 (IR 은 생성기가 쓴다) |
| 시간 구간 | 트랙 보기에서 레인을 끌면 트랙 범위와 박 범위를 고른다 (격자에 맞춘다). 복사, 잘라내기, 붙이기(재생 위치에, 같은 트랙 순서로), 복제(구간 바로 뒤에), 내용 지우기. 붙이는 자리의 그 트랙들 내용은 지우고 넣는다 (덮어쓰기) | 겹친 음이 쌓이지 않는다. 피아노 롤의 붙이기(더하기)와 다르다 |
| 경계에 걸친 음 | 구간 편집은 구간 안에서 시작한 음만 옮긴다. 지우기와 덮어쓰기는 구간 안에서 시작한 음을 지우고, 구간 앞에서 시작해 안으로 들어오는 음은 구간 시작에서 자른다 | 음을 반으로 쪼개면 공격이 두 번 난다 |
| 곡선 | 구간의 곡선은 구간 처음과 끝의 값을 점으로 넣어 잘라 옮긴다 (그 자리의 값이 바뀌지 않는다). 컨트롤러, 효과 매개변수, 센드 크기 곡선 모두 | 붙인 구간이 원래 자리와 같은 소리를 낸다 |
| 시간 넣기, 지우기 | 곡 전체: 모든 트랙의 음과 곡선, 템포 점, 마커, 반복 구간, `render.endBeat` 를 민다. 시간 지우기는 구간 안의 것을 지우고 뒤를 당긴다 | 곡의 구조를 바꾸는 편집이다 |
| MIDI 가져오기 | 엔진의 `importMidi`: 트랙마다(형식 0 은 채널마다) 트랙 하나, 첫 프로그램 체인지로 악기를 고른다 (GM 번호에서 레지스트리 악기로, 없으면 `grand-piano`), 템포 지도와 첫 박자, CC 곡선, 피치 벤드, 가사, 마커. 앱: 파일 > MIDI 가져오기 (새 곡), 트랙 보기에 .mid 를 끌어 놓으면 지금 곡에 트랙으로 더한다 | 저자가 다른 곳에서 친 연주와 스케치를 가져온다 |
| 자동 저장 | 저장하지 않은 편집이 있으면 2분마다 앱 데이터 폴더에 사본을 쓴다 (곡 파일 곁에 쓰지 않는다: 파일 감시와 생성기를 건드리지 않는다). 열 때 사본이 곡 파일보다 새로우면 되살릴지 묻는다 | |
| 재생기 | 트랙 목록이 바뀌면 재생기를 다시 만든다 (`RealtimePlayer::apply` 가 false). 시간 편집은 템포가 바뀌지 않으면 트랙 바꿔 끼우기로 | 지금 길을 그대로 쓴다 |
| 창 없는 시험 | 엔진 단위 시험, 명령행 끝까지 시험, `--edit-test` 의 트랙 머리 메뉴와 끌기, 레인의 구간 고르기와 명령, 눈금자의 마커, `--snapshot` | |

## 4. 확인한 것

- 엔진 단위 시험 (`test_arrange.cpp`, 9건): 비어 있는 이름 고르기 ("Lead 2" 를 복제하면 "Lead 3"), 이름 바꾸기에 따라가는 사이드체인(트랙과 마스터),
  지운 트랙의 키 풀기, 넣기와 옮기기와 색, 사본이 주석과 가사를 지키기. 마커의 박 순서 검사, 더하기와 옮기기의 새 번호. 곡선의 자르기, 내용 지우기,
  넣기, 지우기가 구간 밖의 값을 1e-6 안에서 지킨다 (step 과 smooth 가 섞인 곡선). 구간 복사와 덮어 붙이기 (14박에서 들어오는 음은 16박에서
  잘리고, 붙인 자리의 CC1, 효과의 cutoffHz, 센드 곡선이 원래 자리와 같다). 시간 넣기 뒤 같은 자리를 지우면 음의 시작, 곡선, 템포(램프 구간 포함),
  마커, 반복 구간, 끝 박이 되돌아온다. 처음(0박)에 넣어도 템포의 첫 점은 0박이다.
- 명령행 (`e2e_cli.py`, 284건): 내보낸 MIDI 를 다시 가져오면 음, 가사, 마커, 제목, 템포 지도, CC11 계단 점이 같다. 있는 파일은 `--force` 없이 덮어쓰지
  않고, MIDI 가 아닌 파일은 `midi` 오류. `arrange` 의 마디 넣기와 같은 마디 지우기가 음의 시작을 되돌리고, 트랙 더하기, 번호로 이름 바꾸기, 구간 복제,
  마커, `--output`, 모르는 트랙과 겹친 이름의 오류. 「유리 회로」(15트랙, 음표 3974개)에 마커 일곱을 붙여 내보내고 가져오니 트랙 이름, 음 수, 한글 마커,
  제목이 같았다 (우리 내보내기는 프로그램 체인지를 쓰지 않아 악기는 모두 그랜드 피아노).
- 앱 `--edit-test` 243건: 트랙 더하기(자리, 이름, 고르기), 이름 칸을 두 번 눌러 고치기와 사이드체인, 겹친 이름 거절, 복제, 머리 끌어 옮기기(끄는 동안은
  편집하지 않는다, 누르기만 하면 고르기만), 색, 지우기와 사이드체인 풀기, 마지막 트랙 지키기, 모두 되돌리면 파일 글자가 같다. 마커 띠 두 번 누르기와
  이름 칸, 끌어 옮기기, 누르면 그 자리로, 앞뒤 마커. 레인을 끌어 두 트랙과 두 마디 고르기, 레인을 누르면 구간이 풀린다, 복제와 덮어쓰기, 곡선 복사,
  재생 위치에 붙이기(격자), 내용 지우기, 시간 넣기와 지우기. MIDI 끌어 놓기로 트랙 더하기(편집 하나), 새 곡으로 가져오기와 덮어쓰지 않기.
  자동 저장의 사본 쓰기, 곡 파일 곁에 쓰지 않기, 다시 열 때 찾기와 되살리기(편집 하나, 실행 취소로 파일 내용), 저장하면 지우기.
- 스냅숏으로 트랙 더하기 단추, 마커 띠(「유리 회로」에 마커 일곱), 트랙 색을 확인했다.

## 5. 남은 것

- **오프라인 렌더의 sfizz 경쟁 상태.** CTest 를 넷씩 함께 돌리는 부하에서 `cli` 의 "같은 입력은 같은 바이트" 가 한 번 실패했다 (다시 돌리면 통과).
  CLAUDE.md 에 적힌 "부하가 크면 sfizz 가 미리 읽은 샘플 앞부분을 지나 음을 끊는다" 와 같은 일이다. 원인: 오프라인 렌더는 sfizz 의 freewheeling 을
  켜서 블록마다 `FilePool::waitForBackgroundLoading()` 이 불러오기를 기다리는데, 이 함수는 배분 스레드가 이미 큐에서 꺼낸 일만 기다린다.
  앞 블록에서 켠 음의 요청이 아직 `filesToLoad` 큐에 있으면 기다리지 않고 지나가 미리 읽은 8192 프레임 뒤에서 음이 끊긴다. 고치려면 sfizz 소스를
  고쳐야 한다 (기다리기 전에 큐에 남은 요청을 그 스레드에서 읽는다). 모든 샘플을 미리 다 읽는 길은 VSCO 만 2.8 GB 라 쓰지 않는다.
  sfizz 를 빌드할 때 고치는 것(`build.sh` 의 패치, `THIRD-PARTY.md` 에 고친 것을 적기)은 저자가 정한다.
- 우리 MIDI 내보내기는 프로그램 체인지를 쓰지 않는다. 다른 DAW 에서 열면 악기가 모두 피아노다 (악기에서 GM 프로그램을 거꾸로 고르는 표가 필요하다).
- 구간 편집은 이어진 트랙만 고른다. 마디 단위의 시간 편집에서 박자는 곡 전체에 하나다 (박자 바꾸기는 D11).
- 피아노 롤의 눈금자에는 마커가 없다 (트랙 보기의 띠만).
- 트랙 목록이 바뀌면 재생기를 다시 만든다 (「붉은 별」 17트랙이 1~2초). 트랙을 더하고 지울 때 재생기의 그 트랙만 바꿔 끼우는 것은 뒤로 미뤘다.
