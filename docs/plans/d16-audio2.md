# D16. 입력 모니터링, 클립의 늘이기와 음높이

> 작성일: 2026-10-23. 계기: 상용 DAW 와 견준 빈자리(D8 1절)의 오디오 칸. 녹음하는 소리를 트랙의 효과로 들을 수 없었고(장치의 직접 모니터링뿐),
> 오디오 클립은 템포를 따르지 않았다.

## 1. 목표

오디오 트랙이 입력을 그 트랙 사슬로 낸다. 오디오 클립이 곡의 템포를 따라 늘거나 줄고, 음높이를 반음 단위로 바꾼다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 입력 모니터링 | 재생기의 `setInputMonitor (트랙)`: 오디오 콜백이 넘긴 입력(앞 두 채널, 하나면 양쪽)을 그 트랙의 악기 자리에 더한다. 효과, 페이더, 밸런스, 센드, 뮤트를 그대로 지난다. 멈춘 동안에도 들린다. 한 번에 한 트랙 | 녹음하며 트랙의 효과와 믹스를 듣는다 |
| 지연 | 재생기의 지연(트랙 정렬, 효과)과 장치의 지연만큼 늦게 들린다 (낮은 지연 모니터링은 없다). 상태 줄에 알린다 | 재생과 같은 사슬이라 녹음한 소리와 같다 |
| 늘이기 | 클립의 `sourceBpm` (파일의 템포: 파일의 한 박이 곡의 한 박에 놓이게, 곡의 템포 지도를 따라 비율이 바뀐다), `stretch` (소리 길이의 배수 0.25~4), `pitchSemitones` (-24~24). `offsetSeconds` 와 `lengthSeconds` 는 늘 파일의 초다. 둘(sourceBpm 과 stretch)을 함께 쓰지 않는다 | 녹음한 루프와 반주가 곡의 템포를 따른다 |
| 계산 | Signalsmith Stretch 1.4.0 (MIT, 머리 파일만, `build.sh` 가 고정 커밋으로 받는다). 재생기와 렌더러가 클립을 준비할 때(메시지 스레드) 클립의 처음부터 끝까지를 한 번 만들어 두고(씨앗 고정, 같은 클립과 템포는 캐시), 재생은 그것을 곡 위치로 읽는다. 블록(256 샘플)마다 곡 위치에 맞는 파일 위치까지 입력을 늘이기의 지연만큼 앞서 넣는다 | 실시간과 오프라인이 같은 샘플, 탐색과 반복도 같다 |
| 시각의 변환 | 엔진의 `clipSourceAt` (곡의 초에서 파일의 초)와 `clipSongSecondsAt` (거꾸로). 클립의 끝, 앱의 경계와 파형, 자르기, 나누기, 편곡 함수의 시간 넣기와 지우기가 모두 이 둘을 쓴다 | 늘인 클립을 잘라도 파일의 자리가 맞다 |
| 앱 | 클립 오른쪽 클릭의 "음높이" (-12~+12 반음)와 "늘이기" (곡의 템포 따르기: 파일의 템포를 지금 곡의 템포로 두고, 그 뒤 곡의 템포를 바꾸면 클립이 따라 늘거나 준다, 또는 길이 0.5~2 배). 늘이기가 없는 빌드는 메뉴를 끄고 알린다 | |
| 앱 | 트랙 메뉴와 오디오 트랙 머리의 "입력 모니터링" (⌥I). 입력이 꺼져 있으면 켠다 (마이크 권한). 트랙 머리에 빨간 "입력 모니터링". 트랙 이름으로 기억해 순서가 바뀌어도 따라가고, 지우면 꺼진다. 재생기를 다시 만들면 다시 건다 | |

## 4. 확인한 것

- 엔진 단위 시험: 클립 없는 오디오 트랙(-6 dB, 밸런스 0.5)에 입력 모니터링을 켜면 출력이 입력에 그 트랙의 좌우 이득을 곱한 것과 1e-5 안에서 같고(멈춘 채),
  끄기 전과 끈 뒤에는 소리가 없다.
- 앱 `--edit-test` 6건: 악기 트랙은 모니터링하지 않는다, 오디오 트랙, 한 번에 한 트랙, 트랙을 옮기면 따라간다, 지우면 꺼진다, 끄기.
- 실제 입력 장치로 듣는 것은 저자가 확인한다 (창 없는 시험은 장치를 열지 않는다).
- 엔진 단위 시험 2건: 440 Hz 클립의 음높이 +12 가 880.5 Hz, 같은 길이. 늘이기 2 는 0.5초가 1초, 440.0 Hz, 다시 렌더링하면 같은 샘플.
  파일의 템포 60 인 2초 클립을 120 BPM 에서 1 박 뒤 60 BPM 인 곡의 0 박에 두면 1.5초에 끝나고 (0.5초 + 1초), 앞은 440 Hz, 1 박부터 파일의 둘째 초 880 Hz,
  실시간 재생이 오프라인과 같다 (재생을 시작한 블록의 처음 64 샘플을 뺀다). 템포를 따르는 클립에 시간을 넣으면 파일의 박으로 나뉜다.
  처음에는 시험이 원본 사인파 파일과 같은 이름으로 렌더 결과를 써서 두 번째 계산이 달라 보였다 (라이브러리는 결정적이다).
- 앱 `--edit-test` 9건: 음높이는 길이를 그대로, 곡에 적힌다, 늘이기 2 는 클립 너비가 두 배, 템포 따르기, 곡을 60 BPM 으로 바꿔도 4 박, 늘인 클립을 2 박에서 나누면 파일의 1초에서, 실행 취소.

## 5. 남은 것

- 낮은 지연 모니터링(지연 보상을 건너뛰기)은 없다.
- 늘인 클립은 편집할 때마다 메시지 스레드에서 다시 만든다 (긴 클립은 잠깐 걸린다). 워프 마커(클립 안의 자리마다 박 맞추기)와 포먼트 보존은 없다.
