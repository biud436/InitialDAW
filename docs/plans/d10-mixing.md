# D10. 오토메이션과 플러그인 효과

> 작성일: 2026-10-22. 계기: 상용 DAW 와 견준 빈자리 표(D8 1절)의 믹싱 칸. 엔진은 효과 매개변수와 센드 크기의 곡선을 읽었지만 앱에서는 그릴 수
> 없었고, 페이더와 밸런스에는 곡선이 없었다. 효과는 내장 효과뿐이다.

## 1. 목표

페이더, 밸런스, 센드, 효과 매개변수, 컨트롤러의 곡선을 앱에서 그린다. 같은 곡선이 실시간 재생과 내보내기에 같게 들린다.
다음으로 VST3 와 AU 효과를 트랙, 버스, 마스터의 효과 칸에 넣는다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 페이더와 밸런스의 곡선 | 믹서 객체의 `"automation": { "gainDb": [점], "pan": [점] }` (트랙, 버스, 마스터). 있으면 고정값 대신 곡선을 쓴다 | 센드의 `automation.levelDb` 와 같은 모양 |
| 읽기 | 곡 위치의 32 샘플 격자(`SampleLane`)에서 두 채널의 게인을 계산하고 격자 사이는 직선. 실시간은 정렬된 신호의 시계로 곡 위치를 읽고 멈춘 동안은 그 자리의 값 | 효과 곡선과 같은 규칙이라 실시간과 오프라인이 같다 (시험) |
| 편집 반영 | 곡선이 바뀌면 `RealtimePlayer::apply` 가 그 채널의 곡선만 바꿔 끼운다 (`Handoff`). 곡선을 지우면 마지막 값에서 고정값으로 잇는다 | 점을 끌 때마다 재생기를 다시 만들지 않는다 |
| 곡선의 열쇠 | `cc1`, `pitchBend`, `mixer/gainDb`, `mixer/pan`, `sends/<버스>`, `effects/<번호>:<종류>/<매개변수>`. 엔진의 `trackAutomationLanes`, `withTrackAutomation`, `automationLaneOf` 와 편곡 함수가 같은 열쇠를 쓴다 | 구간 편집과 시간 넣기, 지우기가 믹서 곡선도 옮긴다 |
| 앱 | 피아노 롤 아래 칸의 상자가 곡선이 있는 대상을 모두 보이고, "곡선 추가..." 는 믹서, 센드, 효과 매개변수(곡선을 둘 수 있는 것), 컨트롤러로 묶어 고른다. 대상마다 눈금: 볼륨과 센드는 믹서의 페이더 눈금, 주파수와 시간은 로그, 그 밖은 직선. 왼쪽에 끄는 점이나 재생 위치의 값 | 피아노 롤의 곡선 편집(두 번 눌러 점 넣고 빼기, 끌기, 오른쪽 클릭의 모양)을 그대로 쓴다 |
| 오디오 트랙 | 아래 칸에 벨로시티 대신 곡선만 (볼륨 곡선 등) | |
| 믹서 화면 | 곡선이 정하는 페이더와 밸런스는 끌 수 없고 (안내 말풍선) 재생 위치의 값을 따라 움직인다 | |
| 플러그인 효과 | 효과 객체 `{ "type": "plugin", "format": "vst3"\|"au", "plugin": "<VST3 파일이나 AU 식별자>", "name", "state", "program", "parameters" }`. 트랙, 버스, 마스터의 효과 칸 어디에나 | 내장 효과와 같은 사슬이라 지연 보상, 우회, 순서 바꾸기가 그대로 된다 |
| 만드는 스레드 | 플러그인은 메시지 스레드에서 만든다. 오프라인 렌더의 버스와 마스터 효과 사슬을 돌리기 단계에서 만들기 단계로 옮겼다 (앱의 내보내기는 만들기를 메시지 스레드에서, 돌리기를 뒤 스레드에서 한다). 앱은 플러그인 효과가 있는 곡의 재생기를 메시지 스레드에서 만든다 | |
| 플레이헤드 | 플러그인에 곡의 샘플, 초, 박(4분음표), 템포, 재생 중인지를 알린다. 효과가 내보내는 소리의 곡 위치(앞 효과와 자기 지연을 뺀 자리)다 | 템포를 따르는 플러그인(딜레이, 게이트)이 곡에 맞는다 (시험 플러그인의 박 게이트로 잰다) |
| 실시간과 오프라인 | 실시간은 플러그인을 실시간 모드로, 오프라인은 non-realtime 으로 준비한다 | |
| 소리 바꾸기 | 효과 객체의 설정(state, program, parameters)만 바뀐 편집은 사슬을 바꾸지 않고 그 플러그인에 넣는다 (지금 값과 다른 것만). 그 밖의 바뀜은 사슬을 바꿔 끼우고 새 플러그인이 된다 | 플러그인 창이 소리를 내는 플러그인을 계속 본다 |
| 창 | 효과 칸의 "매개변수 열기"가 플러그인 자체 화면(없으면 매개변수 목록)을 연다. 바꾼 소리는 0.5초 조용해지면 효과의 state 로 편집 하나. 사슬이 바뀌어 다른 플러그인이 소리를 내면 창을 닫는다 | 악기 창과 같은 방식 |

## 4. 확인한 것

- 엔진 단위 시험 3건 더: 사인파 클립의 트랙 페이더가 0~1초 -24 dB (RMS 0.0223), 2초 뒤 0 dB, 밸런스 곡선이 왼쪽 끝에 닿으면 오른쪽이 0.
  -24 dB 와 소리 없는 점, 모르는 열쇠(`mute`)는 오류. 트랙(밸런스와 smooth 페이더), 버스, 마스터(지수 곡선)에 곡선을 걸어도 실시간 재생이 오프라인과
  1e-5 안에서 같다. 곡선을 바꾼 편집을 반영한 재생기가 새로 만든 재생기와 샘플까지 같다. 시간 넣기와 구간 복사가 트랙과 마스터의 믹서 곡선을 옮긴다.
- 앱 `--edit-test` 285건 가운데 곡선 13건.
- 스냅숏(`--lane mixer/gainDb`): 볼륨 곡선이 페이더 눈금으로, 왼쪽에 재생 위치의 값(0.0 dB).
- 플러그인 효과 엔진 시험 3건 (`test_plugin_effects.cpp`, 시험용 효과 `MusicRender Test Effect`: Gain, Latency, 박 게이트): 트랙의 기본 -6 dB, 상태로 바꾼 소리,
  마스터에서 -6 dB, 검사 오류. 지연 300 샘플을 알리는 플러그인의 트랙이 플러그인 없는 트랙과 1e-4 안에서 같은 자리에 난다 (재생기도 300 샘플로 알린다).
  박 게이트가 120 BPM 에서 박의 뒤 반(1.27~1.48초)을 끈다. 트랙, 버스, 마스터의 플러그인 효과에서 실시간 재생이 오프라인과 1e-5 안에서 같다.
  상태만 바뀐 편집은 같은 플러그인에 그 상태가 들어가고, 효과를 더하면 새 플러그인이 된다.
- 앱 `--plugin-effect-test` 20건: 효과 칸 이름, 재생기의 트랙과 버스 플러그인, 매개변수 목록의 슬라이더를 옮기면 0.9초 뒤 효과의 state 로 편집 하나("효과 소리"),
  반영해도 같은 플러그인, 실행 취소와 다시 실행, 저장한 곡을 다시 열면 같은 값.

## 5. 남은 것

- (2026-10-23 고침) 버스 효과의 지연(리버브의 합성곱, 리미터의 미리보기)을 실시간에서도 맞춘다: 트랙의 직접 신호를 가장 긴 버스 지연만큼, 버스마다 그 차이만큼
  늦춰 마스터에서 만나게 하고, 버스 페이더 곡선은 버스 효과를 지난 소리의 곡 위치로, 마스터의 곡선과 효과와 사이드체인 키는 그만큼 늦은 곡 위치로 읽는다.
  재생기의 출력 지연이 그만큼 는다. 버스 효과의 지연이나 마스터 압축기의 키가 바뀌는 편집은 재생기를 다시 만든다.
  시험: 리미터 버스(지연 480 샘플)와 버스 페이더 곡선, 킥이 키인 마스터 압축기의 곡에서 실시간 출력을 출력 지연만큼 당기면 오프라인과 6e-8 안,
  리버브 버스의 값만 바꾼 apply 뒤에도 1e-5 안 (처음에는 리버브를 EQ 로 바꾼 apply 를 받았으나 이제 다시 만든다).
- 트랙 보기의 레인에는 다이내믹스(CC1, CC11)만 옅게 보이고 볼륨 곡선은 보이지 않는다.
- 버스와 마스터의 곡선은 곡 JSON 으로만 쓴다 (피아노 롤은 트랙의 곡선).
