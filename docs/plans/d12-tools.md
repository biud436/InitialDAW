# D12. 음표 다듬기, 오디오로 굳히기, 실행 취소 기록

> 작성일: 2026-10-22. 계기: 상용 DAW 와 견준 빈자리 표(D8 1절)의 편집과 작업 칸. 피아노 롤의 음표 도구는 격자 맞추기(시작만)와 옥타브뿐이었고,
> 무거운 악기 트랙을 오디오로 굳힐 길과 실행 취소 기록을 볼 곳이 없었다.

## 1. 목표

고른 음표(없으면 트랙의 모든 음표)를 한 번에 다듬는 도구를 엔진의 편집 함수로 만들고 피아노 롤의 메뉴에 올린다. 트랙 하나를 그 트랙 사슬의 소리로
렌더링해 오디오 트랙에 넣는다. 실행 취소 기록을 보고 한 자리로 돌아간다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 음표 도구의 자리 | 엔진의 `NoteEdits` (음표 목록과 고른 번호를 받아 새 목록): `quantizeNotes` (세기, 스윙, 끝), `scaleVelocities`, `rampVelocities`, `humanizeNotes` (씨앗이 같으면 같은 결과), `legatoNotes`, `setLengths`, `snapToScale`, `retrogradeNotes`, `invertNotes` | 앱의 다른 음표 편집과 같은 길 (편집 하나, 가사와 모르는 필드는 원래 객체에 남는다). 생성기와 에이전트도 같은 함수를 쓸 수 있다 |
| 고른 것이 없을 때 | 트랙의 모든 음표 | 격자 맞추기와 같다 |
| 격자 맞추기 | 지금 격자로. 세기 100, 75, 50, 25% (격자까지 거리의 몫), 시작과 끝, 스윙 25~100% (둘째 칸을 격자의 3분의 1까지 늦춘다, 100% 는 셋잇단의 자리). 시작만 옮길 때는 끝을 지킨다 | 사람이 친 녹음을 반만 맞추거나 스윙으로 맞춘다 |
| 벨로시티 | 넓히기와 좁히기는 고른 음의 평균을 가운데로 1.25 배, 0.8 배. 크레셴도와 디미누엔도는 시간 차례로 가장 여린 값과 가장 센 값 사이 (모두 8 안이면 가운데에서 ±16), 같은 시작의 음은 같은 값 | 화음이 한 덩어리로 커진다 |
| 휴머나이즈 | 세기 ±4, ±8, ±14, 시간 ±6, 12, 20 ms (그 자리의 템포로 박으로). 누를 때마다 다른 씨앗 | 엔진 휴머나이즈(재생할 때)와 달리 곡에 적혀 사람이 본다 |
| 길이 | 레가토(다음 시작까지, 같은 시작의 음은 함께), 격자 한 칸, 반 칸 | |
| 음계에 맞추기 | 근음 12 개와 음계 표(엔진의 `scaleTypes`). 밖의 음은 가까운 음계 음으로, 같은 거리면 아래로 | |
| 역행과 반행 | 역행은 고른 음이 차지한 시간 안에서 거꾸로, 반행은 가장 이른 음(같으면 낮은 음)을 축으로 | 동기를 바꿔 쓰는 작곡 도구 |
| 메뉴 | 편집 메뉴와 음표 오른쪽 클릭의 "음표 다듬기". 바뀐 것이 없으면 편집을 만들지 않고 알린다 | |
| 굳히기의 소리 | 그 트랙의 악기와 트랙 효과(페이더 앞, 지연 정렬 뒤)를 렌더링한다. 사이드체인 키 트랙도 함께 울리고 다른 트랙은 끈다. 버스와 마스터의 효과, 목표 LUFS 는 뺀다 (`bounceComposition`) | 페이더, 밸런스, 센드는 새 오디오 트랙에서 그대로 고칠 수 있다 |
| 굳힌 파일 | 곡 폴더의 `audio/<트랙> bounce N.wav` (24비트, 48 kHz). 앞은 첫 소리가 든 마디의 첫 박, 끝은 마지막 소리(-120 dBFS 위) 뒤 0.1초 | 마디에서 시작해 옮기기 쉽고, 클립 재생기와 같은 식으로 샘플을 정해 어긋나지 않는다 |
| 곡에 넣기 | 원래 트랙 바로 뒤에 "<이름> 오디오" (색, 믹서, 센드를 옮기고 솔로와 뮤트는 뺀다), 원래 트랙은 뮤트. 편집 하나 | 되돌리기 쉽다 (뮤트를 풀고 오디오 트랙을 지운다) |
| 굳히는 동안 | 뒤 스레드 (플러그인 악기는 메시지 스레드에서 만든다), 상태 줄에 진행. 끝났을 때 원래 트랙이 없으면 알린다 | 내보내기와 같은 방식 |
| 명령 | 트랙 메뉴와 트랙 머리 메뉴의 "오디오로 굳히기" (⌘⌥B) | |
| 실행 취소 기록 | 편집 메뉴의 "실행 취소 기록 (N개)": 처음 상태, 지난 편집(오래된 것부터, 지금 자리에 표시), 다시 실행할 편집. 고르면 그 자리까지 되돌리거나 다시 실행한다. 최근 60개까지 보인다 (기록은 200 편집) | 편집 이름은 이미 편집마다 있다 ("격자에 맞추기 50%", "오디오로 굳히기: Keys") |
| 한 번에 옮기기 | `Project::jumpHistory`: 걸음마다 JSON 조각만 바꾸고 곡은 끝에 한 번 다시 읽어 알린다 (재생기 반영도 한 번) | 수십 걸음을 옮겨도 재생기를 한 번만 다시 만든다 |

## 4. 확인한 것

- 엔진 단위 시험 (`test_note_tools.cpp`): 세기 50% 는 0.1 박을 0.05 로, 스윙 100% 는 0.6 박의 8분음표를 0.5 + 1/6 박으로, 끝 맞추기는 0.9 를 1.0 으로.
  평균 80 을 가운데로 0.5 배는 60, 100 을 70, 90 으로. 같은 씨앗의 휴머나이즈는 같고, 다른 씨앗은 다르며 범위 안이다. 레가토, C장조에 맞추기(C# 은 C, F# 은 F),
  역행, 반행.
- 앱 `--edit-test` 가운데 음표 다듬기 15건: 반 세기 맞추기, 편집 하나의 이름, 스윙, 고른 음만 좁히기, 디미누엔도, 레가토, 음계, 반행, 역행, 가사와 모르는 필드,
  휴머나이즈의 범위, 바뀐 것이 없으면 편집 없음, 모두 실행 취소.
- 엔진 단위 시험 (`test_bounce.cpp`): 3/4, 120 BPM 에서 12.5 박에 시작하는 리드(EQ, 킥이 키인 압축기, -4 dB, 밸런스 0.4, 에코 버스 센드)를 굳히면 12 박(다섯째 마디)에서
  2.2초, 봉우리 -12.3 dBFS. 원래 트랙을 뮤트하고 같은 믹서와 센드의 오디오 트랙을 더한 곡이 원래 곡과 최대 1.8e-7 차이 (24비트 안). 소리 없는 트랙은 파일을 쓰지 않는다.
- 앱 `--edit-test` 가운데 굳히기 12건: 파일 자리, 첫 소리의 마디(3마디, 8박), 원래 트랙 뒤의 오디오 트랙과 클립, 믹서와 센드와 색(솔로는 빼고), 원래 트랙의 뮤트, 고른 트랙,
  실행 취소, 소리 없음과 이름이 바뀐 트랙.
- 앱 `--edit-test` 가운데 실행 취소 기록 11건: 세 편집(믹서, 트랙 복제, 박자)의 목록, 두 걸음을 한 번에 되돌리면 첫 편집 뒤와 같고 알림은 한 번, 되돌린 뒤의 목록
  (다시 실행할 편집과 그 머리), 두 걸음 앞으로, 처음 상태(저장한 상태와 같아 수정 표시 없음), 처음 앞은 없음, 끝까지 앞으로.
- `--export-test`: 뒤 스레드의 굳히기 파일이 엔진의 굳히기와 바이트까지 같다 (플러그인 악기 트랙 `Tone` 과 플러그인 없는 곡의 `Keys`).

## 5. 남은 것

- 굳히기는 페이더 앞만 앱에 있다 (엔진의 `postFader` 는 명령으로 열지 않았다). 오디오 트랙에서 원래 트랙으로 되돌리는 "풀기" 명령은 없다 (뮤트를 풀고 지운다).
- 구간만 굳히기, 여러 트랙을 한 번에 굳히기는 없다.
