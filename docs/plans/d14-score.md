# D14. 악보

> 작성일: 2026-10-23. 계기: 상용 DAW 와 견준 빈자리 표(D8 1절)의 편집 칸에 남은 "악보 보기".
> 곡을 악보로 보고, 악보 프로그램(MuseScore, Finale, Sibelius, Dorico)에 넘길 길이 없었다.

## 1. 목표

엔진이 곡의 음을 악보 모델(마디, 보표, 음가, 붙임줄, 쉼표, 조표와 임시표)로 옮긴다. 그 모델을 MusicXML 로 쓰고(명령행, 앱의 내보내기),
앱의 악보 보기가 같은 모델을 그린다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 조 | 곡의 선택 필드 `"key": "Bb minor"` 와 `"keyChanges": [{ "beat", "key" }]` (마디 줄). 없으면 고른 트랙의 음 길이로 Krumhansl-Kessler 장조, 단조 표와 상관이 가장 큰 조를 고르고, 곡 끝에 울리는 가장 낮은 음이 나란한조의 으뜸음이면 그쪽 | 철자와 조표가 조에 매인다. 지금 곡들에는 조가 적혀 있지 않다 |
| 조의 길 | MIDI 내보내기는 조표 메타 이벤트(FF 59)를 쓰고 가져오기는 읽는다. 시간 넣기와 지우기는 박자 바꾸기처럼 조 바꾸기를 옮긴다 | |
| 철자 | 조표의 음은 그 글자. 조 밖의 음은 으뜸음에서의 자리로: 장조는 #1 b3 #4 #5 b7, 단조는 b2 #3 #4 #6 #7 (이끎음과 올린 6도는 샵 쪽), 나머지는 조표의 방향 | 화성 단음계, 가락 단음계, 부속 딸림화음, 빌린 화음의 흔한 철자 |
| 임시표 | 마디마다 (글자, 옥타브)의 지금 변화를 세고 다르면 적는다 (제자리표 포함). 붙임줄로 이어진 음은 적지 않는다 | 악보의 관례 |
| 양자화 | 끊어 쓴 음의 끝과 다음 시작 사이의 작은 틈(16분음표 아래이고 두 시작 사이의 30% 아래)은 다음 시작까지 읽는다. 마디 안의 4분음표 칸마다 음의 시작으로 격자를 골라 시작과 끝을 16분음표 격자(어긋나면 32분음표)와 셋잇단 격자(1/6 박) 가운데 거리 합이 작은 쪽에 맞춘다 (셋잇단은 곧은 쪽의 60% 아래일 때만: 조금씩 어긋난 펼친 화음이 셋잇단 32분음표로 잡히던 것을 막는다) | 곡 JSON 의 음은 박 단위로 정확하지만 스트럼, 꾸밈음, 녹음한 음은 어긋난다 |
| 성부 | 보표마다 하나: 모든 음의 시작과 끝, 마디 줄에서 나누고 그 사이에 울리는 음을 화음으로, 이어지는 음은 붙임줄로 | 겹친 음이 많은 피아노도 틀리지 않는다 (붙임줄이 늘어난다). 성부 나누기는 뒤로 |
| 음가 | 온음표(점)부터 32분음표, 셋잇단 4분, 8분, 16분. 박보다 긴 음가는 박에서 시작하고, 짧은 음가는 박을 넘지 않는다 (8분 4분 8분은 붙임줄). 셋잇단 칸은 통째로만 곧은 음가로 덮는다. 박은 4분음표, 3/8 6/8 9/8 12/8 은 점4분음표 | 박의 자리가 보이는 악보 |
| 보표와 자리표 | 건반 악기(grand-piano, piano, harp, celeste, synth.piano, synth.ep, synth.poly-keys)는 음이 가운데 C 위아래에 각각 10% 넘게 있으면 큰보표(가운데 C 부터 위). 그 밖은 평균 높이 57 아래면 낮은음자리표. 건반 이름이 있는 악기는 타악기 보표(GM 드럼 자리와 x 머리) | 선율만 있는 피아노 트랙에 빈 낮은음자리표를 두지 않는다 |
| 높이 | 울리는 높이 (트랙의 `transpose` 포함). 이조 악기의 기보는 하지 않는다 | |
| MusicXML | 4.0 partwise, divisions 24, 마디마다의 조표와 박자, 템포(metronome 과 sound), 마커(rehearsal), 붙임줄(tie 와 tied), 셋잇단(time-modification, tuplet), 가사(이어 부르는 "-" 는 적지 않는다), 음의 세기(dynamics 속성, 벨로시티 90 이 100) | |
| 명령행 | `music-render export-musicxml <곡> --output <곡.musicxml> [--tracks <목록>]` | |
| 펼쳐 친 화음 | 앞 음과 0.05 박 안에 이어 시작한 음은 묶음 전체가 0.2 박 안이면 묶음의 첫 시작으로, 그 묶음의 0.06 박 안의 끝은 가장 늦은 끝으로 읽는다 | 줄마다 12 ms 씩 어긋난 기타 스트럼이 붙임줄 조각과 셋잇단이 되었다 |
| 악보 보기 | 아래 칸을 피아노 롤, 믹서, 악보로 바꾼다 (보기 > 악보, ⌥S). 고른 트랙 하나를 종이색 바탕에 그리고, 마디를 줄 바꿈하며 줄을 채운다. 너비는 음 사이의 길이(제곱근)로, 큰보표는 두 보표의 같은 자리를 맞춘다. 빔은 박(셋잇단은 그 칸) 안의 8분음표보다 짧은 음, 타악기 보표의 기둥은 킥과 페달만 아래 | 읽기 전용. 고치는 것은 피아노 롤에서 |
| 글꼴 | SMuFL 글꼴 Bravura 1.482 (SIL OFL 1.1)를 `build.sh` 가 SHA-256 으로 받아 앱에 넣는다 | 악보 기호의 표준 글꼴. 없으면 악보 보기가 글꼴이 없다고 알린다 |

## 4. 확인한 것

- 엔진 단위 시험 6건: 30 조의 이름 되읽기, Bb단조의 Db, A(이끎음), Gb, E장조의 G#, D#, C장조의 Bb, F#, D단조의 C#, B(올린 6도), C#장조의 B#,
  C장조 음계와 A 화성 단음계의 추정. 4/4 의 4분, 8분, 박을 넘는 점4분이 8분과 4분 붙임줄, 마디를 넘는 온음표가 반음표 둘. 셋잇단 8분 셋의 묶음,
  화음, 마디 전체 쉼표, F# F# F 의 임시표(샵, 없음, 제자리표). 3/4 로 바뀐 마디의 길이 72, E장조로 바뀐 마디의 조표, 큰보표. MusicXML 의 마디 길이 합,
  셋잇단 셋, 붙임줄 하나, 마커와 템포. MIDI 의 Bb단조와 D장조 조표를 되읽기.
- 명령행 끝까지 시험 296건 가운데 MusicXML 6건: 가사 곡의 Eb Ab Bb C 철자(Ab장조 추정), 가사, 적은 조, 모르는 조의 검사 오류.
- 커밋된 34곡을 모두 내보내 모든 마디에서 보표마다 음 길이 합이 마디 길이와 같다 (`checkxml`). 조 추정은 작곡 기록의 조와 대부분 같다:
  처음에는 「붉은 별」(E단조)을 G장조로, 「새벽 세 시」(Eb단조)를 F#장조로 골라 곡 끝의 베이스로 나란한조를 고르게 고쳤다.
  「깃펜의 장난」(C단조, Ab장조 트리오)은 Ab장조, 「소금 바람」(A 도리안)은 D장조로 추정한다 (곡에 `key` 를 적으면 그 조).

- 앱 `--edit-test` 11건: 악보 보기가 피아노 롤 자리에, 고른 트랙의 8마디, 곡의 조(G장조), 두 줄 넘게 줄 바꿈, 셋째 마디를 누르면 8 박으로, 드럼 트랙의 타악기 보표,
  믹서와 서로 바뀌기, MusicXML 내보내기(두 파트, 고른 트랙만).
- 스냅숏: 「못다 한 말」의 선율(F단조 조표, 3/4, 이끎음 E 의 제자리표, 빔, 붙임줄)과 피아노(큰보표), 「새벽 세 시」의 드럼(x 머리, 16분음표 빔)과 기타(펼친 화음).
  처음에는 루바토의 템포 점이 모두 템포 기호로 겹쳐서 첫 템포와 5% 넘게 바뀐 템포만 마디에 하나씩 보이게 했다 (MusicXML 의 재생 템포는 모두 남긴다).
- 「세 목소리」의 지그(12/8, 0.4 박으로 끊어 쓴 8분음표)는 처음에 끝이 셋잇단과 32분음표 자리로 잡혀 셋잇단 410개가 나왔다. 끊어 쓴 끝을 다음 시작까지 읽고
  격자를 시작으로만 고르게 고쳐 0개다.
