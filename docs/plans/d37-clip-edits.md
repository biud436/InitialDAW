# D37. 클립 편집 더하기

> 작성일: 2026-11-11. 계기: [D33 이후의 계획](next-stages.md) 의 순서. D9 의 오디오 클립은 옮기기, 자르기, 페이드(사인 제곱 하나), 게인만 있었다.
> 상용 DAW 가 공통으로 갖춘 클립 편집(거꾸로 재생, 클립 안의 게인 곡선, 페이드 모양, 크로스페이드, 영점에서 자르기)을 더한다. 직접 녹음해 넣은 소리를 다듬는 길이다.

## 1. 목표

- 클립을 같은 자리에서 거꾸로 재생한다.
- 클립 안의 게인을 곡선으로 그린다 (소리에 붙어 있어 클립을 옮기고 잘라도 따라간다).
- 페이드마다 모양을 고른다.
- 겹치거나 맞붙은 두 클립 사이에 크로스페이드를 넣는다.
- 나누고 자르는 자리를 가까운 영점 교차로 맞춘다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 뒤집기의 형식 | 클립의 `"reverse": true`. 클립의 소리는 파일 전체를 거꾸로 돌린 것이고, 클립의 모든 파일의 초(`offsetSeconds`, `lengthSeconds`, `warp`, `pitchEdits`, `gainCurve`)는 거꾸로 돌린 파일의 초(파일 끝에서 센다)다 | 계획은 "클립 구간을 뒤집는다"였다. 구간만 뒤집으면 클립의 초가 파일의 초와 거꾸로 가서 편곡 함수의 나누기(`clipPart`), 앱의 자르기와 나누기, 테이크 고르기, 워프, 높이 편집이 모두 따로 셈을 해야 한다. 파일 전체를 뒤집으면 그 셈이 하나도 바뀌지 않는다 (소리를 주는 곳만 바뀐다) |
| 뒤집기 켜고 끄기 | `withClipReversed (clip, 파일 길이)`: 같은 곡 구간에서 같은 소리 조각을 거꾸로. 시작과 길이는 파일 길이의 거울 자리로 (파일 끝까지 트는 클립은 길이를 적는다), 워프 마커의 초는 거울 자리, 박은 클립 안의 거울 자리 (곡의 박 구간과 `startBeat` 는 그대로), 높이 편집과 게인 곡선도 거울 자리. 페이드는 클립의 양 끝에 남는다. 두 번 켜면 처음과 같다 | 상용 DAW 의 거꾸로 재생처럼 클립이 제자리에 있다 |
| 뒤집은 소리 | 재생: `loadClipAudio (..., reversed)` 가 원래 샘플레이트에서 뒤집은 뒤 바꾼다 (캐시 열쇠가 다르다). 늘이기, 자르기 방식, 높이 재기도 같은 소리를 읽는다. 재기(어택, 템포, 박, 받아 적기, 음 덩어리, 퀵 샘플러, 조각내기, 그루브): `clipSourceFile` 이 거꾸로 돌린 사본을 임시 폴더(`InitialDAW-reversed/<경로, 수정 시각, 크기>/<이름> reversed.wav`, 32비트)에 한 번 쓰고 그 파일을 준다. 퀵 샘플러와 조각내기는 그 사본을 곡 폴더의 `samples/` 에 복사한다 | 재는 함수가 모두 파일을 받는다. 함수 열 개를 고치는 대신 클립의 초가 가리키는 파일 하나를 준다 |
| 게인 곡선 | 클립의 `"gainCurve": [{ "seconds", "value", "curve" }]`. 파일의 초, 데시벨(-96~24), 모양은 컨트롤러 곡선과 같다 (`linear`, `step`, `exponential`, `smooth`). 같은 초의 두 점은 뛰기. 곡선 밖은 끝 점의 값. `gainDb` 에 더한다 | 파일의 초라서 옮기고, 자르고, 나누고(`clipPart` 가 복사한다), 늘여도 같은 소리에 붙어 있다 |
| 게인 곡선의 재생 | 클립 목록을 만들 때(메시지 스레드나 뒤 스레드) 클립 안의 32 샘플마다 게인을 셈해 두고 사이는 곧게 잇는다. 늘인 클립은 곡의 초에서 파일의 초로(`clipSourceAt`) 읽는다 | 오디오 스레드에서 곡선을 찾지 않는다. 엔진 곡선의 32 샘플 격자와 같다. 실시간과 오프라인이 같은 함수다 |
| 페이드 모양 | `fadeInShape`, `fadeOutShape`: `sine`(기본, 사인 제곱), `linear`, `equalPower`(사인), `exponential`(-60 dB 에서 데시벨로 곧게, 처음은 0). 기본값은 쓰지 않는다 | 사인 제곱은 맞선 두 페이드의 크기 합이 1 (같은 소리), 사인은 힘의 합이 1 (다른 소리). 지수는 자연스럽게 잦아드는 끝 |
| 크로스페이드 | `crossfadedClips (a, b, ...)`: 겹쳤으면 겹친 길이, 맞붙었으면(1 ms 안) 두 클립을 파일의 소리로 서로 쪽으로 늘여 `lengthSeconds`(기본 20 ms)만큼 겹치게 한다 (이음매의 앞뒤 반씩, 한쪽 파일에 소리가 모자라면 다른 쪽에서). 겹친 자리에서 두 클립이 같은 파일의 같은 자리를 틀면(나눈 클립) 사인 제곱, 아니면 등전력. 재생 규칙은 그대로다 (겹치면 더한다, 데이터만 고친다) | 나눈 자리를 다시 이으면 나누기 전과 같아야 한다 (같은 소리를 등전력으로 겹치면 가운데가 3 dB 커진다) |
| 영점 | `nearestZeroCrossing (clip, folder, 파일의 초, 10 ms)`: 두 채널 합의 부호가 바뀌는 자리에서 0 에 가까운 샘플 (원래 샘플레이트). 앱 설정 `clipZeroCrossings` (편집 > 클립을 영점에서 자르기)가 켜져 있으면 나누기와 양 끝 끌기가 쓴다 | 늘이지 않은 클립에서 정확하다. 늘인 클립은 파일 쪽의 영점이다 |
| 화면 | 클립 메뉴: 거꾸로 재생, 페이드인 모양, 페이드아웃 모양, 페이드 지우기(모양도), 뒤 클립과 크로스페이드, 게인 곡선 편집, 게인 곡선 지우기. 페이드는 모양대로 그린다. 보기 > 클립 게인 곡선 편집(⌥G): 클립 몸통을 누르면 점을 더해 끌고(위 +12 dB, 아래 -36 dB, 0.1 dB 단위), 점을 끌어 옮기고(이웃 점 사이), ⌥ 누르기는 지운다. 편집 중이 아니어도 곡선이 있으면 옅게 그리고, 파형은 곡선을 곱해 그린다. 뒤집은 클립은 이름 뒤에 "거꾸로" | 손놀림은 워프 마커(⌥ 누르기로 지우기)와 같다 |
| 명령행 | `arrange song.json reverse <트랙> [--clip n]`, `fade <트랙> [--clip n] [--in 초] [--out 초] [--in-shape 모양] [--out-shape 모양]`, `crossfade <트랙> [--clip n] [--ms 20]` (클립과 시작 순서로 다음 클립, `--clip` 이 없으면 모든 이웃) | 생성기와 에이전트도 쓴다 |

## 4. 확인한 것

- 뒤집은 클립의 렌더는 파일을 거꾸로 돌려 쓴 WAV 를 그대로 튼 렌더와 1e-6 안에서 같다 (자르기, 게인, 페이드와 함께, +2 반음 늘이기와 함께). 첫 초 440 Hz, 둘째 초 880 Hz 의
  파일을 뒤집으면 880 Hz 가 먼저 (880.0, 440.0 Hz). 실시간 재생도 오프라인과 1e-5 안. 거꾸로 돌린 사본은 원래 파일을 뒤집은 것과 샘플까지 같고, 봉우리 표도 같다.
- 워프 마커가 셋인 클립을 뒤집으면 마커가 클립 안의 거울 박에 놓이고 클립의 끝은 같은 자리 (1e-6), 다시 뒤집으면 처음과 같다 (`==`).
- 게인 곡선 (파일의 1초 0 dB 에서 3초 -12 dB): 22 주기 창에서 잰 크기가 0.000, -2.997, -5.997, -8.997, -11.998 dB (곡선 0, -3, -6, -9, -12). `gainDb` +6 과 더하고, 파일의 2초부터
  자른 클립과 두 배로 늘인 클립과 곡의 시간을 넣어 나눈 클립에서 같은 소리에 같은 게인. 같은 초의 두 점은 0 dB 에서 -20 dB 로 뛴다. 거울 곡선은 곧은 선, 사인, 뛰기 모두 거울 자리의 값과 1e-9 안.
- 페이드 모양: 크기 0.5 의 곧은 값에 0.4초 페이드를 걸면 페이드인 가운데와 페이드아웃의 4분의 1 자리가 모양의 값과 1e-5 안 (넷 모두). 맞선 사인 제곱의 크기 합, 맞선 사인의 힘 합이 1 (1e-6).
- 등전력 크로스페이드: 서로 상관없는 두 잡음 (같은 크기)이 0.5초 겹치면 겹친 자리의 0.1초 창들이 앞(-15.18 dB)과 뒤(-15.20 dB)의 가운데와 0.08 dB 안.
- 나눈 클립 (같은 파일의 이어지는 소리)의 크로스페이드: 이음매 앞뒤 10 ms 씩 늘이고 사인 제곱. 렌더가 나누기 전의 클립과 가장 크게 2.98e-8 다르다.
- 영점: 100 Hz 사인파에서 찾은 자리는 반 주기 안의 영점이고, 그 샘플의 크기가 한 샘플 걸음보다 작다. 앱의 `--edit-test` 에서 440 Hz 사인파를 1.165초에서 나누면 1.16477초(영점)에서 나뉜다.
- 앱: 클립 게인 곡선 편집에서 몸통 누르기로 점 더하기 (파일의 0.5초, -6 dB 를 0.05초, 1.5 dB 안), 끌기 (끄는 동안 편집이 없다), 둘째 점, ⌥ 누르기로 지우기, 클립은 옮겨지지 않는다.
  거꾸로 재생과 다시 앞으로, 페이드 모양, 영점에서 나누기, 나눈 두 조각의 크로스페이드 (앞뒤 10 ms, 사인 제곱), 모두 실행 취소로 원래 파일의 글과 같다.
- 스냅숏: 뒤집은 클립의 파형(두드림이 커지며 끝난다), 지수 페이드인과 직선 페이드아웃, 등전력 페이드인, 게인 곡선과 그것을 곱한 파형, 겹친 두 클립의 사인 제곱 크로스페이드.

## 5. 남은 것

- 겹친 두 클립에서 앞 클립의 페이드아웃은 뒤 클립 밑에 가려 보이지 않는다 (크로스페이드 자리의 두 곡선을 함께 그리기).
- 페이드는 클립 길이의 반을 넘지 않는다 (지금 규칙). 반보다 긴 크로스페이드는 잘린다.
- 게인 곡선의 점마다 모양 고르기는 JSON 과 명령행 밖에서는 아직 없다 (앱은 곧은 선으로 더한다).
- 실제 녹음과 실제 창의 마우스는 저자가 확인한다.
