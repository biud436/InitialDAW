# D4. 악기와 플러그인

> 작성일: 2026-10-07. 계기: GitHub 이슈 #1 「가상악기 패널 추가」. 가상악기(VSTi)의 패널을 띄우고, 패널에서 주요 값을 조절하고
> (패널에는 그림이 들어 있을 수 있다), 우선 무료 VSTi 를 받아 패널로 잘 동작하는지 확인한다.

## 1. 목표

트랙의 악기가 플러그인이면 그 플러그인의 자체 화면(패널)을 창으로 띄운다. 패널에서 바꾼 소리는 곡 JSON 의 그 트랙에 저장되고,
실행 취소로 되돌아가며, 명령행 렌더도 같은 소리를 낸다. 앱에서 트랙의 악기를 바꾸고(레지스트리의 악기, 찾은 플러그인),
음표의 아티큘레이션을 고른다. 무료 VSTi 로 Dexed 를 `build.sh` 가 받는다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 무료 VSTi | Dexed 1.0.1 (GPL-3.0, DX7 FM 신스, VST3 와 AU). `build.sh --plugins` 가 GitHub 릴리스 zip 을 받아 SHA-256 을 확인하고 `external/plugins/dexed` 에 푼다. 레지스트리 이름 `dexed`, 없으면 `synth.ep` 로 대신한다 | 소스가 열린 무료 플러그인이고, 자체 패널에 DX7 그림과 손잡이가 많다. 엔진 2단계에서 이미 렌더링이 바이트까지 같은 것을 확인했다. 앱과 링크하지 않고 실행 중에 불러오므로 앱의 라이선스와 섞이지 않는다 |
| 트랙의 플러그인 설정 | 트랙에 `"plugin": { "state", "program", "parameters" }`. 레지스트리 항목의 설정 뒤에 적용한다 | 같은 악기(예: dexed)를 트랙마다 다른 소리로 쓴다. 레지스트리를 고치지 않고 곡 하나에 소리가 남는다 |
| 악기 창 | 플러그인의 자체 화면을 따로 창에 띄운다. 자체 화면이 없는 플러그인은 매개변수 목록(JUCE 일반 편집기). 믹서 스트립의 악기 줄 누르기, 트랙 머리의 악기 줄 두 번 클릭, ⌘I (고른 트랙) | 플러그인 화면은 크기가 제각각이고 네이티브 뷰라 앱 칸 안에 넣지 않는다 |
| 소리 저장 | 창이 열려 있는 동안 플러그인이 매개변수 변경을 알리면, 0.5초 조용해진 뒤 플러그인 상태(base64)를 트랙의 `plugin.state` 로 쓴다 (편집 하나, "악기 소리"). 상태를 쓰면 그 트랙의 `program` 과 `parameters` 는 지운다. 창을 닫을 때와 저장할 때도 한 번 확인한다 | 상태가 모든 값을 담는다. program 이 남으면 다시 열 때 상태를 덮는다. 알림을 보내지 않는 플러그인은 닫을 때 잡힌다 |
| 되돌리기 | `RealtimePlayer::apply` 가 트랙의 플러그인 설정이 바뀌면 메시지 스레드에서 플러그인에 다시 넣는다. 지금 상태와 바이트가 같으면 넣지 않는다 | 실행 취소가 소리를 되돌린다. 방금 저장한 상태를 다시 넣어 소리가 끊기지 않는다 |
| 재생기를 다시 만들 때 | 열린 악기 창을 닫고 새 재생기의 플러그인으로 다시 연다 | 플러그인 객체가 바뀐다. 편집기가 플러그인보다 먼저 사라져야 한다 |
| 악기 바꾸기 | 믹서 스트립의 악기 줄을 오른쪽 클릭하면 악기 메뉴 (내장 신스, 샘플, 플러그인, 찾은 플러그인). 바꾸면 그 트랙의 `plugin` 설정은 지운다 | 다른 플러그인의 상태를 새 플러그인에 넣지 않는다 |
| 플러그인 찾기 | 앱이 자기 자신을 `--scan-plugins` 로 따로 실행해 VST3 와 AU 를 찾고 플러그인 캐시를 쓴다 | 찾는 동안 화면이 멈추지 않고, 플러그인이 죽어도 앱은 산다 |
| 곡 안의 악기 정의 | `"instruments"` 배열에 레지스트리 파일 경로뿐 아니라 정의 객체(`{ "이름": { "type": "vst3", ... } }`)를 둘 수 있다. 찾은 플러그인을 고르면 곡에 정의를 더한다 | 곡 파일 하나로 악기가 정해진다. 레지스트리 파일을 따로 만들지 않는다 |
| 아티큘레이션 | 피아노 롤에서 고른 음표를 오른쪽 클릭하면 악기 프로필의 아티큘레이션 메뉴. 음표에 줄임말을 그린다 | 현악의 legato, pizzicato 를 앱에서 고친다 |
| 창 없는 시험 | `--plugin-test` 가 시험용 신스(VST3)를 곡 안의 정의로 불러 재생기를 만들고, 악기 패널을 창 없이 만들어 매개변수를 바꾸고, 상태가 곡에 쓰이고 실행 취소로 플러그인 값이 돌아오는지 본다. Dexed 가 있으면 자체 화면이 만들어지는지(크기)도 본다 | 플러그인의 자체 화면은 네이티브 뷰라 스냅숏에 그려지지 않는다. 실제 창은 저자가 띄워 확인한다 |

## 4. 확인한 것

- 엔진 단위 시험 100건(검사 2064), 명령행, 앱 스냅숏, 믹서 스냅숏, 악기 패널, 편집 시험 모두 통과 (CTest 6개)
- Dexed 1.0.1 zip 의 MD5 가 릴리스에 공개된 `artifact_md5sum.txt` 와 같다. 그 zip 의 SHA-256 을 고정했다. 새로 받기와 체크섬 실패를 빈 폴더에서 시험했다
- 명령행 렌더: `dexed` 악기로 3음 곡을 렌더링 (봉우리 -12.1 dBFS, 0.02초)
- 트랙 설정: 곡 안의 정의(Level 0.5) 뒤에 트랙의 Level 0.25, 프로그램 1, base64 상태(Level 0.9)가 각각 진폭 0.125, 0.125, 0.45 로 렌더링된다
- 재생 중 `apply`: 같은 플러그인 객체에 매개변수를 넣어 진폭이 0.25 에서 0.125 로 바뀌고, 같은 설정을 다시 반영하면 상태가 바이트까지 그대로, 트랙 설정을
  지우면 곡 안의 정의 상태로 돌아간다. 없는 매개변수는 거절하고 아무것도 바꾸지 않는다. 악기 정의를 바꾸면 false (다시 만든다)
- `--plugin-test` 검사 23건: 일반 편집기의 Level 슬라이더를 0.3 으로 옮기면 0.5초 조용해진 뒤 상태가 곡에 들어가고("악기 소리" 편집 하나),
  실행 취소가 플러그인의 Level 을 0.5 로 돌리고 새 편집을 만들지 않으며, 다시 실행이 0.3 으로, 저장한 곡을 다시 열면 0.3. Dexed 의 자체 화면이 866x674 로 만들어진다
- 플러그인 찾기(따로 실행): 1.3초에 플러그인 41개, 악기 4개 (Dexed VST3, 애플 DLSMusicDevice, AUMIDISynth, AUSampler)
- `--self-test`: Dexed 와 내장 신스 두 트랙 곡이 0.5초에 준비되고 3.04초 진행
- Dexed 의 상태는 8340 바이트, base64 로 11120 글자 (트랙 하나에 한 줄)
- `--edit-test` 검사 67건: 아티큘레이션을 고른 음표에 쓰고 트랙 기본값으로 되돌리기, 악기 바꾸기가 앞 악기의 플러그인 설정을 지움, 찾은 플러그인을 고르면 곡에 정의가 들어감, 모두 되돌리면 처음 글과 같음
- 고친 것: 앱에 플러그인 호스트 세션이 없어 플러그인 악기가 든 곡은 앱에서 재생기를 만들지 못했다. JUCE `MemoryBlock` 의 base64 는 표준이 아니라서
  플러그인 상태를 표준 base64 로 바꿨다 (지금까지 레지스트리의 `state` 를 쓴 곳은 없었다)

## 5. 남은 것

- 실제 Dexed 패널을 창으로 띄워 보는 확인 (자체 화면은 네이티브 뷰라 스냅숏에 그려지지 않는다. 앱 창은 저자가 띄운다)
- 플러그인 효과 (믹서 효과 슬롯의 VST3, AU)
- 설치하지 않은 AU (`external/plugins/dexed/Dexed.component`)는 찾지 못한다. AU 는 Components 폴더에 설치해야 시스템이 안다
- 매개변수 변경을 알리지 않는 플러그인은 창을 닫거나 저장할 때 상태를 잡는다
- 플러그인 상태가 큰 플러그인(샘플러)은 곡 JSON 이 커진다. 따로 파일로 두는 선택지(`stateFile`)는 레지스트리에만 있다
- 악기를 바꾸면 재생기를 다시 만든다 (다른 트랙의 악기도 다시 읽는다)
- 피아노 롤의 음표마다 아티큘레이션 표시는 음표가 넓을 때만 보인다

## 6. 덧붙임: 내장 신스 패널

> 2026-10-07. 플러그인처럼 내장 신스에도 손잡이와 그래프가 있는 패널을 띄운다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 매개변수 | 엔진이 프리셋의 엔진(감산, 피아노, 플럭, 드럼)마다 매개변수 표를 내놓는다. 감산: 디튠 폭, 잡음, 필터(켜기, 컷오프, 레조넌스, 엔벨로프 양과 감쇠, 벨로시티, 키 추적), 앰프 엔벨로프(ADSR), 비브라토(빠르기, 깊이, 지연), 출력(드라이브, 벨로시티 곡선, 스테레오 폭, 레벨). 피아노와 플럭: 저음과 고음의 울림 시간, 릴리스, 출력. 드럼: 레벨 | 프리셋 구조체에 이미 있는 값이다. 새 합성 방식을 만들지 않고 있는 값을 손잡이로 꺼낸다 |
| 곡 형식 | 트랙에 `"synth": { "cutoffHz": 900, "release": 1.2 }`. 레지스트리와 곡 안의 정의도 `"type": "synth"` 항목에 `"parameters"` 를 둘 수 있다 (그 뒤에 트랙 값) | 곡 하나에 소리가 남고, 이름 붙인 신스 소리를 곡 안에 정의할 수 있다 |
| 재생 중 반영 | `apply` 가 바뀐 값으로 프리셋을 메시지 스레드에서 새로 만들어 넘기고, 오디오 스레드가 블록 처음에 맞바꾼다 (할당 없음). 울리는 음의 릴리스와 필터 감쇠도 새 값으로 | 손잡이를 돌리는 동안 바로 들린다. 재생 전에 반영하면 새로 만든 재생기와 샘플 단위로 같다 |
| 패널 | 앱이 그린다 (네이티브 뷰가 아니라 스냅숏에 그려진다): 프리셋 이름 표시, 단면마다 손잡이, 파형(오실레이터 한 주기), 필터 응답(기본과 엔벨로프 끝), ADSR 모양, 피아노와 플럭은 건반에 따른 울림 시간. 그래프는 엔진이 계산한다 (같은 수식) | 엔진에 없는 것을 앱에서 흉내 내지 않는다 |
| 편집 | 끄는 동안은 재생기에만, 손을 떼면 편집 하나. 두 번 클릭은 기본값(그 키를 지운다), 초기화는 트랙의 `synth` 를 지운다 | 믹서와 같은 조작 |

체크리스트:

- [x] 엔진: 프리셋마다 매개변수 표(합성 방식별 손잡이, 기본값은 프리셋의 값), 레지스트리와 곡 안의 정의의 `parameters`, 트랙의 `synth`, 검사(모르는 키와 범위)
- [x] 엔진: 재생 중 바꿔 끼우기 (`Instrument::setSynthParameters`, 할당 없는 맞바꿈, 울리는 음의 릴리스와 필터 감쇠도 새 값으로), `apply` 가 트랙의 synth 가 바뀌면 부른다
- [x] 엔진: 그래프 계산 (섞은 오실레이터의 한 주기, SVF 필터 응답)
- [x] 앱: 신스 패널 (표시창, 단면, 손잡이, 파형, 필터 응답, ADSR, 울림 시간, 세기 곡선, 키트 설명), 악기 창에서 플러그인 패널과 함께, 실행 취소로 악기가 바뀌면 닫기
- [x] 시험: 기본값을 모두 적어도 모든 프리셋이 샘플까지 같음, 값이 소리를 바꿈, 재생 전 반영이 새 재생기와 같음, 곡 안의 정의, 필터 응답 수식, `--edit-test` 의 손잡이 조작, CTest `app_synth_snapshot`
- [x] 문서: README 두 개의 신스 패널 절과 스크린샷, 스키마의 `synth`

확인한 것:

- 엔진 단위 시험 106건(검사 2685). 모든 프리셋(18개)에서 기본값을 모두 적은 곡과 적지 않은 곡이 샘플까지 같다

### 7.3 잰 것 (고친 판)

- 층 고르기와 이어 섞기 (첫 판에서 잼): 섞는 자리(CC1 42, 72, 100)에서 이웃 건반의 크기 차이 최대가 고르기 3.4, 3.9, 2.5 dB, 이어 섞기 10.8, 8.0, 3.5 dB.

- 공격과 릴리스 (첫 판에서 잼, 바꾸지 않음): -3 dB 까지 벨로시티 127 이 10~45 ms, 100 이 50~80, 64 가 25~135, 30 이 75~175 ms. legato 의 첫 음을 뗀 뒤 -20 dB 210~490 ms
- 스타카토: -20 dB 까지 낮은 음(C2~A3) 0.55~0.88초, 높은 음(D4~A5) 0.22~0.38초. 피치카토는 녹음 넷이 0.5 dB 안 (바꾸지 않음)
- 비교 파일 (`build/compare/cello/`, 커밋하지 않음, 목록은 그 폴더의 README.txt): 같은 방 울림, 모두 -18.0~-18.1 LUFS, 다섯 구간이 여섯 판 사이에서 0.5 LU 안.
  cello-solo 판(B, C, D)은 건반 보정 CC11 이 없다. 「못다 한 말」 첼로판의 처음 75초는 곡 그대로와, 첼로만 cello-solo 로 바꿔 Sonatina 건반 보정 CC11 을 빼고
  트랙 게인을 13.0 에서 9.6 dB 로 낮춘 사본(첼로 스템이 둘 다 -36.8 LUFS)

### 7.4 남은 것

- 루프 되풀이는 Sonatina 보다 낮지만 남는다 (포락선 자기상관 0.80~0.89). 음높이와 크기가 고른 자리만 쓰려고 루프가 짧아졌다 (중앙값 2.1초, 1.5초 아래 39개).
  긴 음은 생성기가 3~5초마다 활을 바꾸거나 CC1, CC21 곡선을 주면 덜하다
- 건반 83~86 (C6 녹음) 은 녹음 자체가 흔들려 12초 음 안에서 음높이가 최대 18.6 센트 오르내린다 (첫 판 32.4)
- legato 파일은 겹음(동시에 누른 두 음)을 레가토로 읽어 앞 음을 끈다. 겹음은 sustain 으로 쓴다
- Sonatina 에 맞춰 쓴 CC1 곡선(「못다 한 말」 처음 75초는 CC1 점의 93 % 가 43~72, 음 68개 가운데 67개가 mp 층)은 이 악기에서 거의 mp 층 하나다. 이 악기로 옮기는 곡은 CC1 곡선을 다시 본다
- 스타카토와 피치카토는 적은 길이와 상관없이 녹음의 끝까지 울린다. 범위 밖의 음은 경고 없이 소리가 없다 (엔진이 알리지 않는다)
- sfizz 의 확인된 성질: 둘 이상의 LFO 가 `_oncc` 로 음높이 깊이를 바꾸면 깊이 키가 겹친다. 무작위 CC136(양극)은 변조 행렬에서 0~1 로 잘린다.
  flex EG 의 시간을 CC141 로 바꾸려면 `egN_dynamic=1`. keydelta(CC140, 141)는 곡선이 걸리지 않는 날값이고, 음을 켤 때 리전 조건(`locc141`)에 들어가지 않는다.
  같은 그룹의 같은 음은 `off_by` 로 끄지 않는다 (`note_polyphony` 가 끈다)
- 무거운 부하에서 sfizz 가 미리 읽은 샘플 앞부분(8192 프레임, 0.19초)을 지나 음을 끊는다. 고치는 동안 렌더 100번 남짓 가운데 3번에서 음 4개가 끊겼고
  (부하 평균 13~17, 함께 돌린 렌더 셋), 다시 렌더링하면 없었다. 잴 렌더는 `cutcheck` 로 0.1~0.35초에 갑자기 소리가 사라진 음을 찾는다. 엔진에서 고칠 거리다
