# D7. 작곡 도구

> 작성일: 2026-10-11. 계기: 앱에는 새 곡을 만드는 길이 없었다 (열기만 있었다). 앱에서 곡을 처음부터 쓰려면 편성과 믹스가
> 갖춰진 빈 곡에서 시작해야 하고, 그 값은 지금까지 만든 곡에서 재고 고친 것을 쓴다. 장르별 템플릿으로 둔다.

## 1. 목표

파일 > 새 곡 (⌘N) 에서 장르 템플릿을 골라 빈 곡을 만든다. 템플릿은 편성(악기, 아티큘레이션), 믹스(게인, 밸런스, 센드, 효과),
버스, 마스터(목표 음량, 리미터), 템포와 박자, 되풀이 곡이면 반복 구간을 갖추고 음표는 없다. 음표는 저자가 그린다.
이어서 코드 트랙, 마커와 구간 이름, 작곡 생성기 실행과 결과 비교를 같은 단계에서 다룬다 (아래 4절).

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|

| 템플릿 폴더 | `MUSIC_RENDER_TEMPLATES` 환경 변수, 없으면 저장소의 `templates/` (레지스트리와 같은 방식) | |

## 4. 확인한 것

- 템플릿 13개가 모두 `music-render validate` 를 오류 없이 지난다 (경고는 트랙에 음표가 없다는 것뿐).
- 단위 시험: 템플릿마다 새 곡이 파싱되고, 제목, 트랙 수, 반복 구간이 템플릿과 같고, 음표가 없고, `metadata.template` 이 id 이다.
  있는 파일에는 만들지 않는다. 명령행 시험: 목록의 순서, 새 곡의 검사, 반복 구간, 덮어쓰기 거절, 비슷한 id 제안, 빈 곡 렌더링.
- 앱 `--new-test` 10건: 대화상자의 만들기로 「관현악 전투」 곡을 만들어 열고, 트랙 수와 반복 구간이 템플릿과 같고, 저장할 편집이 없고,
  같은 파일에는 다시 만들지 않는다. `--snapshot --new` 로 대화상자를 그려 확인했다.

## 7. 덧붙임: 음표의 가사 (2026-10-19)

계기: 노래를 염두에 둔 곡은 음표에 가사를 붙여 두어야 한다. 노래하는 소리는 아직 없다 (오디오 생성 모델은 쓰지 않는다).
가사는 음표마다 부르는 음절로 곡 JSON 에 남기고, 피아노 롤과 MIDI 에서 보인다.

| 항목 | 결정 |
|---|---|
| 형식 | 음표의 선택 필드 `"lyric"`: 그 음에서 부르는 음절 (UTF-8 문자열, 한글 글자 하나가 보통 음표 하나). `"-"` 는 앞 음절을 이어 부르는 음표 (멜리스마). 빈 문자열과 문자열이 아닌 값은 오류. 스키마의 음표에 더했다 |
| 소리 | 가사는 재생, 렌더링, 연주 처리에 쓰지 않는다. 재생기가 트랙 바꿔 끼우기를 정하는 음 비교(`sameNotes`)에도 넣지 않는다 |
| 편집과 저장 | `Note::lyric`. `withNotes` 가 원래 객체의 가사를 지키고 바뀐 가사만 고쳐 쓴다. 옮기기, 길이, 세기는 원래 객체에 쓰므로 가사가 남고, 복사와 붙여 넣기의 새 객체에는 `Note` 의 가사를 쓴다. 새로 그린 음, 코드와 스케일 넣기, 녹음한 음에는 없다 |
| MIDI | `export-midi` 가 가사가 있는 음의 음 켜짐 자리(연주 처리를 거치면 옮겨진 자리)에 가사 메타 이벤트(FF 05, UTF-8)를 음 켜짐보다 앞에 쓴다. `-` 는 쓰지 않는다. 명령행 결과에 `lyrics` (쓴 수)를 더했다 |
| 피아노 롤 | 음절을 음표 안 왼쪽에 굵게 쓴다 (12 px, 음표 줄 높이가 낮으면 줄 높이에 맞춘다). 들어가지 않으면 8 px 까지 한 칸씩 줄이고, 그래도 넘치면 음표 바로 아래, 그다음 바로 위의 빈자리에 밝은 글자로 쓴다. 두 자리가 모두 다른 음표나 먼저 쓴 가사와 겹치면 쓰지 않는다. 음절 뒤에 자리가 남으면 음 이름을 흐리게 쓴다. `-` 는 음표를 가로지르는 선이고 넓으면 보이는 오른쪽 끝에 음 이름을 쓴다. 끄는 동안의 미리보기도 같다. 줄 높이가 9 px 아래면 음절을 쓰지 않는다 |
| 가사 편집 | 이번에는 만들지 않는다. 곡 JSON 과 작곡 생성기로 쓴다 |

확인:

- 단위 시험 3건: 파싱(한글 음절, `-`, 가사 없는 음, 숫자와 빈 문자열은 오류), 옮기기와 길이와 세기 뒤에 원래 객체의 가사와 주석이 남는지, 저장 왕복이
  같은 글인지, 복사와 붙여 넣기의 새 객체에 가사가 가는지, 새로 그린 음에는 없는지, 가사를 바꾸고 지우기 (`lyrics_are_parsed_kept_through_edits_and_saved`).
  MIDI 의 가사 이벤트가 음 켜짐의 틱에, 음 켜짐보다 앞에, UTF-8 바이트로 있고 `-` 와 가사 없는 음은 빠지는지, 연주 처리로 옮겨진 음 켜짐을 따라가는지
  (`midi_export_writes_lyrics_at_note_ons`). 가사를 지운 곡과 렌더링이 바이트까지 같은지 (`lyrics_do_not_change_the_rendered_sound`).
- 명령행 시험 4건 (가사 없는 곡의 `lyrics` 0, 가사 있는 곡의 검사에 경고 없음, `lyrics` 수, 파일 안의 UTF-8 바이트). `--edit-test` 에 피아노 롤의 마우스로
  늘인 음에 가사가 남고 ⌥ 끌기 사본에 가고 새로 그린 음에는 없는지 1건.
- 「늦은 편지」 3판의 사본(scratchpad)에 `songs/late-letter/lyrics.txt` 를 붙였다: Lead 의 음 320개, 쉼으로 나뉜 프레이즈 28개가 가사의 묶음 28개와
  모두 맞았다. `export-midi` 가 가사 이벤트 319개(음절 320 에서 `-` 하나를 뺀 수)를 썼고, 따로 읽어 보니 모두 음 켜짐의 틱에 있고 바로 뒤가 그 음 켜짐이며
  연주 처리를 거친 판도 같았다. 17~24마디 렌더링이 원본과 바이트까지 같았다.
- `--snapshot --bars 17-24` 로 후렴 1 을 그려 보았다: 16분음표 남짓한 음은 음절을 바로 아래나 위에 쓰고, 넓은 음은 음절 뒤에 음 이름을 쓰며 겹치는 글자가 없었다.
  끝의 `-` 는 음표를 가로지르는 선과 오른쪽 끝의 음 이름(D#3)으로 보였다.
- Music IR: 음표 지문(`note_key`)에 가사가 있으면 더한다. 가사만 고친 칸도 생성기 출력과 다른 칸으로 잡혀 `plan` 이 알리고, `apply` 는 대상 밖의 그 칸을
  디스크 그대로 둔다 (「유리 회로」의 음 하나에 가사를 넣어 다른 칸 0 에서 1 이 되는 것을 보았다). 가사가 없는 곡의 지문은 그대로라 지금 곡들의 IR 은 신선하다.
