# D15. 마스터 분석

> 작성일: 2026-10-23. 계기: 상용 DAW 와 견준 빈자리의 다음 갈래. 라우드니스는 렌더 리포트로만 알 수 있었고, 재생하며 볼 미터는 봉우리뿐이었다.

## 1. 목표

재생하며 마스터의 라우드니스(EBU R128: 순간, 단기, 통합, 트루 피크)와 스펙트럼을 본다. 값은 오프라인 렌더의 측정과 같아야 한다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 측정기 | 엔진의 `LoudnessMeter`: K 가중(오프라인 분석과 같은 `KWeighting`), 100ms 칸, 순간은 마지막 네 칸, 단기는 서른 칸, 통합은 400ms 블록(100ms 씩 겹친다)을 0.1 LU 칸의 막대그래프에 쌓아 절대(-70)와 상대(-10) 게이트. 트루 피크는 오프라인과 같은 4배 보간 | 오디오 스레드에서 할당과 잠금 없이 (막대그래프는 801 칸) |
| 재는 자리 | 재생기의 마스터 미터 자리 (리미터 뒤, 메트로놈과 카운트인 앞). 멈춘 동안의 무음은 게이트에 걸린다 | 들리는 곡의 소리, 클릭은 곡이 아니다 |
| 다시 재기 | 어느 스레드든 요청하고 다음 처리에서 지운다. 재생기를 다시 만들면 새로 잰다 | |
| 스펙트럼 | 재생기가 마스터의 좌우 평균을 32768 샘플 고리에 쓰고, 메시지 스레드가 마지막 4096 샘플에 한 창을 씌워 FFT (juce_dsp). 20 Hz ~ 20 kHz 로그 눈금, -90 ~ 0 dB (0 dBFS 사인파가 0 dB), 오를 때 바로, 내릴 때 프레임마다 1.5 dB | |
| 화면 | 믹서의 마스터 스트립 오른쪽 (믹서가 900 px 넘게 넓을 때): 스펙트럼, 순간, 단기, 통합(곡의 목표 LUFS 에서 1 LU 안이면 초록, 밖이면 주황), 트루 피크(-1 dBTP 위면 빨강), 잰 시간, 다시 재기 | |

## 3. 체크리스트

- [x] 엔진: `analysis/KWeighting.h` (오프라인과 실시간이 함께), `analysis/LoudnessMeter`, 재생기의 `loudness()` 와 `copyMasterSamples`
- [x] 시험: 기준 사인파, 오프라인 통합 라우드니스와 트루 피크, 재생기의 출력
- [x] 앱: `AnalyzerPanel` (믹서), 타이머의 갱신, 다시 재기, `--edit-test`, 스냅숏
- [x] 문서: README 두 판(믹서 사진), `docs/plans/index.md`

## 4. 확인한 것

- 엔진 단위 시험 3건: 두 채널 -20 dBFS 1 kHz 사인파의 순간, 단기, 통합이 -19.99 LUFS, 트루 피크 -20.00 dB. 크기가 바뀌고 앞이 게이트에 걸리는 12초 소리의
  통합이 실시간 -11.688, 오프라인 -11.688 LUFS, 트루 피크 -3.101 과 -3.101 dB (블록 300 샘플). 재생기의 통합 값이 그 재생기 출력을 오프라인으로 잰 값과 0.1 LU 안이고,
  스펙트럼에 주는 마지막 4096 샘플이 출력과 1e-6 안에서 같다.
- 앱 `--edit-test` 3건: B5 (987.8 Hz) 사인파의 스펙트럼 봉우리가 그 주파수에 (8% 옥타브 안), 크기, 패널의 통합 값이 재생기의 값.
- 스냅숏: 「네온 비」 1분 15초의 믹서에서 순간 -12.4, 단기 -12.9, 통합 -13.1 LUFS (8초 잼), 트루 피크 -1.0 dBTP, 목표 -11 에서 -2.1.

## 5. 남은 것

- 라우드니스 범위(LRA), 미터 기록(시간에 따른 곡선), 트랙과 버스마다의 분석은 없다.
