# D39. 효과 더하기

> 2026-11-17 완료. [다음 단계 계획](next-stages.md) 의 D39.

## 1. 목표

- 리버브의 컨볼루션을 지연 없이 하고, 임펄스 응답 파일을 어떤 샘플레이트로 녹음했든 쓸 수 있게 한다 (프리딜레이와 응답 줄이기).
- 피치 시프터 `pitch`: 길이를 바꾸지 않고 음높이만 옮긴다 (더블링, 화음 겹치기). 실시간과 오프라인이 같다.
- `stereo` 에 채널의 위상 뒤집기, 좌우 바꾸기, 저역 모노.

## 2. 결정

| 무엇 | 정한 것 | 까닭 |
|---|---|---|
| 컨볼루션 | 이미 있던 균일 분할 FFT (오버랩 세이브) 에서 IR 의 첫 분할 (512 샘플) 을 샘플마다 직접 계산 (`dsp::convolve`, vDSP_conv) 하고, 나머지 분할은 한 분할 앞의 입력으로 FFT 가 미리 계산한다 (첫 분할 뒤의 q 번째 분할은 q + 1 분할만큼 늦은 자리라 지금까지의 입력으로 다음 분할의 꼬리가 모두 정해진다) | 지연이 0 이 된다. 분할 1024 에서 512 로 줄여 직접 계산 (샘플마다 512 곱셈) 과 주파수 영역 곱셈의 합이 가장 작다 |
| IR 파일 | 렌더 샘플레이트로 sinc 리샘플 (`dsp/Resample`, 오디오 클립과 같은 함수). 적힌 `preDelayMs` 만큼 앞을 비우고, 적힌 `decaySeconds` 에 -60 dB 가 되도록 뒤쪽을 지수로 줄인다. 적지 않으면 파일 그대로 | 전에는 샘플레이트가 다르면 오류였다. 적지 않은 값의 기본값 (20 ms, 2.2 s) 이 파일에 걸리면 지금까지의 곡이 바뀐다 |
| 피치 시프터 | Signalsmith Stretch 의 실시간 처리 (입력과 출력 길이가 같다), 블록 0.2초와 간격 15 ms, 계산을 간격마다 나눈다 (`splitComputation`). 지연 = 입력과 출력 지연 + 64 샘플 조각 (48 kHz 에서 10384 샘플, 216 ms) | 기본 설정 (0.12초, 30 ms) 은 순음을 2~10 센트 어긋나게 옮겼다 (같은 Stretch 를 따로 컴파일한 견줌에서 블록과 간격에 따라 바뀌었다). 0.2초와 15 ms 는 열 가지 옮김에서 1.8 센트 안 |
| 블록 크기와 상관없이 | Stretch 에 늘 64 샘플 조각으로 넘긴다 | Stretch 의 무음 판정이 넘긴 조각마다라서, 블록 크기가 다르면 결과가 달라진다 |
| 실시간과 오프라인 | (1) 입력의 곡 위치가 처음 0 에 닿을 때 Stretch 를 시작한다 (`followsPosition`, 실시간의 버스는 트랙 정렬만큼 곡 앞의 무음을 먼저 받아 분석 프레임의 격자가 어긋났다). (2) 시작한 뒤 지연만큼은 젖은 소리를 내지 않는다 (분석 창이 앞을 내다봐 음 머리가 곡 앞으로 번져 나오는 자리, 오프라인은 이 샘플을 버리는데 실시간은 뒤의 IIR 효과가 받아 상태가 갈렸다) | 트랙과 버스에 피치 시프터를 둔 곡이 실시간과 오프라인에서 샘플까지 같다 |
| 섞기 | `mix` (곡선 가능) 는 옮긴 소리와 지연만큼 늦춘 원음. `formant` 는 포먼트를 지킨다 | 더블링과 화음 |
| 저역 모노 | `monoBelowHz` 에서 링크위츠-라일리 8차 (버터워스 4차 두 번) 로 나누고 낮은 쪽의 가운데만 남긴다 | 4차로는 150 Hz 의 1.3 옥타브 아래 (60 Hz) 에서 좌우 차이가 -32 dB 에 머물렀다. 8차는 -63.7 dB, 두 쪽을 더하면 평평한 올패스 |
| 위상과 좌우 | `invertLeft`, `invertRight`, `swap` 은 폭과 위치 앞에 | |
| 프리셋 | 저역 모노 (120 Hz), 한 옥타브 아래 겹치기 (포먼트), 한 옥타브 위 겹치기, 5도 위 화음 | |

## 4. 확인한 것

- 컨볼루션: 직접 계산한 합성곱과 들쭉날쭉한 블록 크기에서 같다 (`convolution_matches_direct_convolution`, 지연 0). 원음은 제자리, 리버브의 지연 0.
- IR 파일: 44.1 kHz 의 평평한 응답을 48 kHz 에: 길이 48000, 프리딜레이 10 ms 에 480 샘플이 비고, 0.1초에 -12 dB, 0.5초에 -60 dB (0.5 dB 안).
  명령줄에서 44.1 kHz IR 파일을 쓴 곡이 48 kHz 로 렌더링된다.
- 피치 시프터 (영점 교차로 잰다, 옮기지 않은 사인파는 0.1 센트 안으로 잰다): 220 Hz +7 반음 +0.04, 440 Hz -11 반음 -50 센트 +1.77,
  220 Hz +7 반음 +30 센트 +0.51, 880 Hz -24 반음 -1.49, 110 Hz +12 반음 +1.79, 196 Hz -7 반음 +0.64 센트. 지연 10384 샘플 (216 ms).
  섞기 0 은 지연만큼 늦춘 원음과 정확히 같다. 블록 512, 들쭉날쭉한 블록, 128 에서 같은 소리 (차이 0, 중간의 무음 구간 포함).
- 실시간: 트랙의 피치 시프터 (-12 반음 +5 센트, 섞기 0.5, 포먼트) 와 그 트랙이 보내는 버스의 피치 시프터 (+7) 가 든 곡을 출력 지연 (트랙과 버스의 지연, 트랙은 10384 샘플) 만큼 당기면 오프라인과 1e-5 안.
- 저역 모노 150 Hz: 왼쪽에만 있는 60 Hz 의 좌우 차이 -63.7 dB, 한쪽 크기 -6.02 dB (가운데로 모였다), 5 kHz 는 왼쪽에 남는다 (오른쪽이 왼쪽의 2% 아래).
- 실시간 부하 (「밤 고속도로」 90초부터 10초, 블록 256, 리버브 버스 둘): 평균 0.26~0.27, 알고리즘 리버브로 바꾸면 0.23~0.25.
  늦은 블록 (45~67개) 은 알고리즘 리버브판과 선율을 뺀 판에도 비슷하게 있어 컨볼루션 때문이 아니다.
- 단위 295건 (8247 확인), 명령줄 573건 (플러그인 인자 없이), CTest 12/12. 앱의 효과 칸 스냅숏에 피치 시프터 (반음, 센트, 효과음 비율, 포먼트 지키기) 와 스테레오의 새 줄.

## 5. 남은 것

- 피치 시프터의 블록 0.2초는 북 같은 짧은 소리의 머리를 번지게 한다. 타악기용 설정 (짧은 블록) 이 필요하면 매개변수로 더한다.
- 실시간에서 곡 중간으로 옮긴 뒤 피치 시프터의 분석 격자는 오프라인 (곡 처음부터) 과 다르다 (옮긴 뒤의 다른 효과처럼 지연만큼의 이음).
- 실제 녹음한 목소리의 포먼트 지키기는 저자가 듣고 판정한다.
