# D35. 구간 트랙

> 작성일: 2026-10-31. 계기: [D33 이후의 계획](next-stages.md) 의 셋째 단계. 곡의 구간(도입, 1절, 후렴)을 덩어리로 옮겨 순서를 바꾼다.
> 지금까지는 마디 구간의 복사와 시간 넣기, 지우기를 손으로 엮어야 했고, 템포와 박자 바꾸기, 조, 마커가 따라오지 않았다.

## 1. 목표

- 마커에서 다음 마커까지를 구간으로 보이고 (새 형식 없음), 끌어서 순서를 바꾼다.
- 구간을 바로 뒤에 복제하고, 지우고 뒤를 당긴다.
- 옮긴 곡이 원래 곡의 구간들을 이어 붙인 것과 같은 소리를 낸다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 구간 | 마커마다 그 마커에서 다음 마커까지, 마지막은 곡의 끝 (`render.endBeat`, 없으면 가장 늦은 음표와 클립의 끝을 마디 줄로 올린 박). 첫 마커 앞과 곡의 끝 뒤는 그대로 둔다. 같은 박의 마커는 길이 0 이라 구간이 아니다 | 곡의 형식을 바꾸지 않는다 |
| 엔진 | 일반 함수 `withSpansArranged (root, spans, tailFrom)`: 원래 곡의 박 구간들을 차례로 0 박부터 이어 붙인다. 옮기기, 복제, 지우기 (`withSectionMoved`, `withSectionDuplicated`, `withSectionDeleted`)는 구간 순서만 정한다 | 시간 넣기와 지우기를 엮으면 박자 바꾸기와 템포 경계가 엉킨다 (지운 자리의 박자를 그 자리 처음으로 옮기는 규칙 등) |
| 따라가는 것 | 트랙의 음과 클립 (`copyRange`, `withClipPasted`, 클립은 경계에서 나눈다), 트랙, 버스, 마스터의 곡선, 템포, 박자 바꾸기, 조 바꾸기, 마커 (복제하면 둘), 반복 구간 (빠진 구간에 있었으면 지운다), `render.endBeat`. 영상은 초에 남는다 | |
| 구간 처음 | 구간마다 그 처음에 쓰이던 박자, 조, 템포를 다시 세운다 (원래 그 박에 바꾸기가 있으면 그 객체를 옮기고, 없으면 새로). 앞과 같은 바꾸기는 지운다. 0 박의 값은 곡의 처음 값 (`timeSignature`, `key`, 첫 템포) | 옮긴 구간이 제 박자와 조와 빠르기로 들린다 |
| 곡선 | 구간마다 잘라(`sliceLane`, 처음의 값과 끝의 값을 점으로) 이어 붙인다. 이음매는 같은 박의 두 점(다가가는 값, 그 뒤의 값). 자르며 생긴 점 가운데 소리를 바꾸지 않는 것(평평한 자리, 직선 위의 점, 같은 박 같은 값)만 지운다 (생성기가 일부러 둔 마지막 점 같은 사람의 점은 남긴다). 원래와 같은 곡선은 원래 JSON 그대로 | 되돌리면 같은 곡 |
| 템포 | 곡선처럼 이어 붙이고 같은 박의 점은 뒤의 것 (템포 점은 박이 엄격히 올라야 한다). 앞 점에서 다가가는 ramp 가 다른 값에 닿는 이음매는 뒤의 점을 1e-6 박 뒤로 | |
| 경계 | 구간의 처음과 끝이 마디 줄이어야 한다 (아니면 하지 않고 이유를 알린다). 구간 경계에 걸친 음은 끝에서 자른다 (구간 편집의 규칙) | 박자가 바뀌어도 마디가 깨지지 않는다 |
| 명령행 | `arrange song.json move-section <구간> --before <구간|end>`, `duplicate-section <구간>`, `delete-section <구간>`. 구간은 번호 (1부터) 나 마커 이름. 결과에 구간 목록 (이름, 첫 마디, 마디 수) | |
| 화면 | 트랙 보기의 마커 띠 아래 구간 띠 (늘 보인다). 덩어리를 끌면 가까운 경계에 놓일 자리가 보이고 놓으면 옮긴다. 누르면 그 처음으로, 두 번 누르면 모든 트랙의 그 구간을 고른다. 오른쪽 클릭: 여기서 재생, 모든 트랙의 이 구간 고르기, 바로 뒤에 복제, 앞으로, 뒤로 옮기기, 지우기. 편집 하나씩 | |

## 4. 확인한 것

- 세 구간 (A 4/4 두 마디 120 BPM, B 3/4 두 마디 90 BPM 의 A minor, C 4/4 90 BPM) 에서 B 를 A 앞으로: 곡이 3/4 로 시작하고 6박에 4/4, 조는 A minor 로 시작해
  6박에 C major, 14박에 A minor (C 에 쓰이던 조), 템포는 B 와 A 가 120 (B 의 템포 점이 C 에 있었다), C 가 90, B 의 linear 곡선과 버스 곡선과 반복 구간이 B 를 따라간다.
  다시 옮기면 곡 JSON 이 같다 (숫자의 0 과 0.0, 적지 않은 기본 곡선 같은 모양만 맞추고).
- 소리: 곡 전체에 걸친 오디오 클립 하나 (반 초마다 반음씩 오르는 소리) 의 곡에서 B 를 옮긴 렌더가 원래 렌더의 B, A, C 조각을 이어 붙인 것과 새 경계의 앞 10 ms 와
  뒤 2초를 빼고 샘플까지 같다 (차이 0). 경계의 차이는 나뉜 클립 양 끝의 32 샘플 페이드다. 내장 신스는 음마다 시작 샘플을 씨앗에 넣어 위상을 정하므로 옮긴 음의
  파형이 같지 않다 (그래서 신스로는 이 기준을 잴 수 없다, 신스를 바꾸면 지금 곡들의 소리가 바뀐다).
- 「밤 장터」의 후렴 1 을 벌스 1 앞으로 옮기면 검사를 통과하고 구간이 전주, 후렴 1, 벌스 1 순서다. 되돌리면 smooth 곡선이 구간 경계를 가로지르던 자리 셋에
  자른 점이 남는다 (smooth 하나를 둘로 나누면 같은 모양이 아니다, linear 는 그대로 이어진다). 다른 칸은 같다.

## 5. 남은 것

- 경계를 가로지르는 smooth 곡선은 자른 자리에서 두 smooth 가 된다 (모양이 조금 다르다).
- 구간 띠에서 여러 구간을 한 번에 고르거나 구간 이름을 바꾸는 일은 마커 띠에서 한다.
