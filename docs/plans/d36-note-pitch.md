# D36. 음마다 높이와 시간 편집

> 작성일: 2026-11-10. 계기: [D33 이후의 계획](next-stages.md) 의 순서. D28 의 자동 교정은 클립 전체에 걸린다.
> 상용 DAW 는 단선율 녹음(노래, 독주 악기)을 음 덩어리로 보여 주고, 음 하나하나의 높이, 흔들림, 비브라토, 시작과 끝을 고친다.
> 직접 녹음해 넣은 소리를 고치는 길이다. 오디오 생성 모델이 아니라 신호 처리(음높이 재기와 늘이기)다.

## 1. 목표

- 녹음을 음 덩어리(시작, 끝, 가운데 높이, 높이 곡선)로 나눠 피아노 롤에 보인다.
- 음마다 높이를 반음이나 센트 단위로 옮기고, 느린 흔들림을 펴고, 비브라토를 줄이거나 키운다.
- 음의 시작과 끝을 끌어 시간을 고친다 (D27 의 워프 마커).
- 명령행으로도 같은 편집을 한다.

## 2. 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 음 나누기 | D22 받아 적기의 나누기(쉼, 높이 바뀜, 다시 치는 어택)를 그대로 쓰고, 음마다 프레임(5 ms)의 높이 곡선을 붙인다 (`analysis/NoteSegments`). 가운데 높이는 잰 높이의 중앙값(소수) | 받아 적기에서 실제 클라리넷과 피아노로 잰 나누기다. 비브라토의 가운데를 중앙값이 잡는다 |
| 형식 | 클립의 `"pitchEdits": [{ "seconds", "lengthSeconds", "semitones", "flatten", "vibrato" }]`. 파일의 초, 옮기는 반음(소수), `flatten` 0~1, `vibrato` 0~2 (1 이 그대로). 시작 순서이고 겹치지 않는다 | 파일의 초라서 클립을 옮기고, 자르고, 나누고, 늘여도 같은 소리에 붙어 있다 |
| 흔들림 나누기 | 음 안의 높이 곡선(높이 없는 프레임은 이웃을 잇고 옥타브 튐은 접는다)을 0.2초 이동 평균 두 번으로 느린 흔들림과 나머지(빠른 흔들림, 비브라토)로 나눈다 | 두 번 거른 0.2초 평균은 5.5 Hz 비브라토를 1% 남짓만, 1 Hz 흔들림은 88% 를 남긴다 |
| 높이 | 프레임마다 `semitones - flatten x (느린 - 가운데) + (vibrato - 1) x 빠른`. 느린 쪽은 ±3, 빠른 쪽은 ±1.5 반음으로 묶는다 (잘못 잰 프레임이 튀지 않게) | 가운데 높이는 그대로 두고 흔들림만 편다 |
| 이어 붙이기 | 반음 옮김은 음 경계의 앞뒤 10 ms 에 걸쳐 들어오고 나간다 (맞붙은 두 편집은 서로 넘겨준다). 펴기와 비브라토는 음 안의 처음과 끝 20 ms 에서 들어오고 나간다 | 경계에서 높이가 뛰지 않는다 |
| 렌더 | 클립 렌더(`renderStretched`)의 256 샘플마다의 높이에 더한다. 교정(D28)과 함께면 편집한 음 안에서는 편집이 이긴다. 포먼트는 교정의 `formant` 를 따르고, 교정이 없으면 지킨다 (잰 기본 주파수를 준다) | D28 과 같은 길이라 실시간과 오프라인이 같다 |
| 함께 쓰기 | `warpMode: slice` 와 함께 쓰지 않는다 (자른 조각은 늘이지 않는다). 워프 마커, 템포 따르기, `pitchSemitones`, 교정과는 함께 | |
| 시간 | 음의 시작과 끝을 끌면 그 자리에 워프 마커를 넣고(없으면 음의 양 끝에 함께) 옮긴다 (D27 의 `withWarpMarkerAdded`, `withWarpMarkerMoved`) | 새 형식이 없다. 끈 경계의 둘레만 늘고 준다 |
| 화면 | 오디오 트랙을 피아노 롤에서 열면 음 덩어리(가운데 높이의 막대와 높이 곡선)가 높이 줄에 보인다. 위아래로 끌면 가운데 높이가 반음에 맞고, ⌥ 끌기는 센트 단위. 고른 음 위의 손잡이 둘로 펴기와 비브라토를 끈다. 양 끝을 끌면 워프 마커가 옮겨진다 (격자에 맞추고 ⌘ 는 맞추지 않는다). 오른쪽 클릭 메뉴: 높이 되돌리기, 반음에 맞추기, 펴기와 비브라토 값. ↑↓ 는 고른 음을 반음씩. 음은 뒤 스레드에서 재고 파일마다 한 번만 | 상용 DAW 의 음 덩어리 편집과 같은 손놀림 |
| 명령행 | `music-render notes <오디오> [--from 초] [--seconds 초]` (음 목록), `arrange song.json pitch-edit <트랙> [--clip n] --note k [--semitones x \| --to E4] [--flatten 0~100] [--vibrato 0~200] [--clear]` | 생성기와 에이전트도 쓴다 |

## 4. 확인한 것

- 만든 목소리 (배음 15, 700, 1200 Hz 의 포먼트 둘, 음 다섯: 느린 흔들림 ±30 센트, 비브라토 ±30 센트, 둘 다, 이어 부르기):
  - 음 덩어리: 다섯 음의 시작과 끝이 5 ms 안 (이어 부른 3, 4번 사이는 15 ms), 가운데 높이가 2 센트 안 (E4 +10 이 64.12, G4 -20 이 66.81).
    흔들림만 있는 음은 흔들림 18.8, 비브라토 5.3 센트, 비브라토만 있는 음은 3.7, 19.5 센트로 갈린다 (1.25 Hz 흔들림은 0.2초 평균 두 번을 19% 남짓 빠져나간다).
  - 셋째 음 +2 반음: +200.7 센트, 이웃 넷은 0.0~0.2 센트. 경계 둘레 15 ms 의 2차 차분의 최댓값이 음 안보다 작다 (안 0.0062, 시작 0.0020, 끝 0.0054).
  - 펴기 100%: 흔들림 21.3 에서 3.9 센트 (4분의 1 은 5.3). 비브라토 0: 20.2 에서 4.6 센트 (4분의 1 은 5.05). 흔들림과 비브라토가 함께 있는 음을 펴기만 하면
    흔들림 14.2 에서 2.3, 비브라토 16.8 에서 16.3 센트. 비브라토 200%: 16.7 에서 31.1 센트 (1.86 배). 펴면 가운데 높이가 3 센트 남짓 옮겨진다: 편집은 음 전체의
    중앙값으로 펴는데, 잰 구간(음 안쪽, 비브라토 주기가 딱 떨어지지 않는다)의 중앙값과 그만큼 다르다.
  - 교정(빠르게)과 함께: 편집한 음은 +200.5 센트, 편집하지 않은 다섯째 음은 교정으로 G4 의 -0.6 센트.
  - 실시간 재생이 오프라인과 1e-5 안. 앱의 재생기처럼 뒤 스레드에서 준비해 바꿔 낀 뒤에도 1e-5 안.
- 명령행: 만든 흥얼거림의 G4, B4, D5 를 찾고 `--to C5` 가 1.00 반음, 셋째 음 -2 반음을 렌더한 소리를 다시 `notes` 로 재면 G4, C5, C5 (5 센트 안).
- 실제 녹음 (「새벽 세 시」의 테너 색소폰만 9~16마디, 21.3초, 43음, FreePats 샘플이라 음마다 0 센트 둘레):
  - 4번 F4 +2 반음은 +204.6 센트 (0.8초 창 FFT 의 배음 봉우리로 재도 +4.4), 22번 A#4 를 `--to C5` 로 +201.0 센트. 손대지 않은 40음은 모두 2 센트 안 (가장 크게 0.7).
  - Signalsmith 의 옮김 자체가 녹음에 따라 어긋난다: 편집 없이 클립 전체를 `pitchSemitones` +1, +2, +3, -2 로 옮겨도 네 음이 -0.3~+5.2 센트 (F4 가 가장 크다).
    포먼트를 지키지 않아도 같다 (+4 센트).
  - 처음 판은 음 머리의 넘어오는 높이(앞 음 G#4 에서 C5 로)를 흔들림에 넣어, 27번 음의 비브라토 0 이 처음 100 ms 를 8 센트 끌어내렸다 (이 음은 비브라토가 ±2 센트뿐이다).
    음의 처음과 끝에서 가운데와 반음의 반 넘게 다른 프레임을 흔들림 나누기에서 빼도록 고친 뒤 꺼짐이 없고, `notes` 가 잰 그 음의 비브라토도 13.9 에서 0.8 센트가 됐다.
- 편집 시간: 171초 클립(색소폰 녹음을 여덟 번 이은 것)에 높이 편집 하나를 넣은 렌더가 4.9초 (높이 재기 1초 남짓, 늘이기 3.5초 남짓).
  앱의 재생기는 고친 클립을 뒤 스레드에서 준비하고 (준비하는 동안 앞 소리), 높이 프레임은 최근 여덟 클립을 캐시해 두 번째 편집부터 다시 재지 않는다.
- 앱 (`--edit-test`): 세 음의 녹음에서 음 셋, 두 줄 위로 끌면 가운데가 B3 (57.2 에서 1.8 반음), ⌥ 끌기 30 센트, 비브라토 손잡이 80 픽셀이 0, 펴기 손잡이 40 픽셀이 50%,
  ↑ 가 반음, 반음에 맞추기, 셋째 음의 시작을 4.27 박에 놓으면 워프 마커가 4.25 박 (격자)이고 둘째 음은 제자리, 되돌리기, 자르기 방식의 클립은 높이를 고치지 않기,
  실행 취소로 파일 글자가 같다. 스냅숏 `--audio-note 0:2` 로 음 덩어리, 높이 곡선, 손잡이, 정보 칸을 확인했다.

## 5. 남은 것

- 편집마다 클립 전체를 다시 렌더링한다 (171초 클립이 4.9초, 앱은 뒤 스레드). 편집한 음 둘레만 다시 만들려면 늘이기의 상태를 나눠 두어야 하고, 오프라인 렌더와 샘플 단위로 같아야 한다.
- 재생기를 다시 만들 때(템포, 트랙 목록이 바뀔 때) 뒤 스레드가 준비 중인 클립이 있으면 그것이 끝나기를 메시지 스레드가 기다린다.
- Signalsmith 옮김의 0~5 센트 오차를 다시 재서 되먹이는 길은 없다.
- 음 덩어리를 손으로 나누거나 합치기, 음 사이 미끄러짐의 모양, 음의 크기, 포먼트만 옮기기는 없다.
- 여러 음을 함께 고르고 고치기(⇧, 사각형)는 없다. 한 번에 한 음이다.
- 음 덩어리는 녹음의 높이에 편집을 더해 그린다. 클립의 자동 교정이 바꾼 높이는 그리지 않는다.
- 실제 목소리 녹음으로는 재지 않았다 (저자가 녹음해 확인한다).
