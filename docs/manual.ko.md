## DAW 사용법

파일 > 새 곡(⌘N)으로 곡을 시작하거나 파일 > 열기(⌘O)로 곡 파일을 엽니다. 위쪽은 트랙 보기이고, 아래쪽은 선택한 트랙의 피아노 롤이나 믹서입니다(X로 전환). 악기는
백그라운드에서 불러오며(17트랙 곡 기준 1~2초), 불러오기가 끝나면 재생할 수 있습니다.

| 키 또는 동작 | 기능 |
| :--- | :--- |
| 스페이스 | 재생, 정지 |
| Z X C V B N M , . / 와 S D G H J L ; | 컴퓨터 키보드로 선택한 트랙을 연주합니다. C4부터 흰건반이고 윗줄이 검은건반입니다(마스터 키보드 없이 화음도 연주할 수 있습니다) |
| Q W E R T Y U I O P [ ] 와 2 3 5 6 7 9 0 = | 한 옥타브 위의 같은 배열(Q가 C5) |
| ⌘K, ⌥↑, ⌥↓ | 키보드 연주 켜기/끄기(트랜스포트의 버튼과 같음), 옥타브 올리기, 내리기. 키보드 연주가 켜져 있으면 Q와 X는 격자 맞추기와 믹서 전환 대신 음을 냅니다(두 기능은 메뉴에서 실행할 수 있습니다) |
| ⇧ 스페이스 | 피아노 롤에서 음표를 선택한 경우, 선택한 음표 중 가장 이른 시작부터 가장 늦은 끝까지 모든 트랙을 재생합니다. 끝에서 멈추고 구간의 처음으로 돌아갑니다(다시 누르면 정지) |
| ⌥R | 선택한 트랙에 녹음합니다(아래 녹음 절 참고). 정지 상태면 카운트인 후 재생 위치부터, 재생 중이면 바로 시작합니다. 다시 누르면 녹음을 끝내고, 스페이스를 누르면 녹음을 끝내고 재생도 멈춥니다 |
| ⌥L, ⌥M | 곡의 반복 구간(`metadata.loop`) 반복 재생, 메트로놈 |
| 눈금자에서 ⌥ 드래그, 반복 구간 띠의 끝 드래그 | 반복 구간 새로 지정, 시작과 끝 이동(편집 한 번으로 기록되고 `metadata.loop`에 저장) |
| 리턴, 홈 | 곡의 처음으로 이동 |
| ⌘N | 템플릿으로 새 곡 만들기 |
| ⌘O, ⌘R | 열기, 다시 불러오기 |
| ⌘E | WAV, FLAC, Ogg Vorbis, MP3로 내보내기 |
| ⌘=, ⌘-, ⌘0 | 확대, 축소, 곡 전체 보기 |
| X | 아래 패널을 피아노 롤과 믹서 사이에서 전환 |
| ⌘I, 트랙 헤더 더블클릭 | 선택한 트랙의 악기 패널 열기(플러그인 악기) |
| 트랙 헤더 우클릭 | 이름 바꾸기, 복제, 지우기, 위로 옮기기, 아래로 옮기기, 색, 악기 바꾸기, 아래에 새 트랙 |
| ⌘⇧T, ⌘⇧D, ⌘⌫, ⌘⌥↑, ⌘⌥↓ | 새 트랙(악기 선택), 트랙 복제, 트랙 삭제, 선택한 트랙을 위나 아래로 이동 |
| 트랙 이름 더블클릭, 트랙 헤더 드래그 | 트랙 이름 바꾸기, 순서 바꾸기 |
| ⇧⌘M, ⌥←, ⌥→ | 재생 위치의 마디에 마커 추가, 이전 마커나 다음 마커로 이동 |
| ⌘⇧I | MIDI 파일을 새 곡으로 가져오기(`.mid` 파일을 창에 드래그해 놓으면 열린 곡에 트랙으로 추가) |
| ⌘⇧A, 오디오 파일을 트랙 보기에 드래그 앤 드롭 | 오디오를 클립으로 가져오기(오디오 레인에 놓으면 그 트랙에, 다른 곳에 놓으면 파일마다 새 오디오 트랙에 추가) |
| 클립 드래그, ⌥ 드래그, 끝 드래그, 위 모서리 드래그, ⌘T | 이동, 복사, 길이 자르기, 페이드, 재생 위치에서 분할(우클릭 메뉴에 게인과 노멀라이즈) |
| ⌥G를 켠 뒤 클립에서 클릭, 포인트 드래그, ⌥ + 포인트 클릭 | 클립 게인 곡선의 포인트 추가, 이동, 삭제 |
| 위, 아래 화살표 | 위나 아래 트랙 선택(선택한 음표가 있으면 반음 단위로 조옮김, 오디오 트랙에서는 선택한 녹음의 음) |
| 피아노 롤의 녹음 음에서 드래그, ⌥ + 드래그, 핸들 드래그, 끝 드래그 | 중심을 반음에 맞춰 옮기기, 센트 단위로 옮기기, 흔들림 평평하게 하기와 비브라토 크기, 시작이나 끝 옮기기(워프 마커) |
| ⌘, | 오디오 장치 설정 |
| 눈금자 클릭, 드래그 | 재생 위치 이동 |
| 휠, 시프트 휠, ⌘ 휠, 핀치 | 세로 스크롤, 가로 스크롤, 확대 |
| 피아노 롤에서 ⌥ 휠 | 건반 높이 조절 |
| 트랙 헤더의 M, S | 뮤트, 솔로(다른 편집처럼 곡에 저장되고 ⌘Z로 되돌릴 수 있습니다) |

### 편집

음표는 피아노 롤에서 편집합니다. 드래그하는 동안에는 결과를 미리 보여 주기만 하고, 마우스를 놓으면 편집 한 번으로 기록되어 ⌘Z 한 번으로
되돌릴 수 있습니다. 재생 중에 편집하면 해당 트랙만 다음 오디오 블록부터 바뀐 음으로 재생되며, 악기를 다시 불러오지 않습니다.
음표나 건반을 클릭하면 정지 상태든 재생 중이든 그 음을 트랙의 악기, 효과, 페이더를 거쳐 들려줍니다. 트랙의 트랜스포즈 설정과 음표의 아티큘레이션이
반영되고, 음표를 드래그해 옮기면 바뀐 음높이를 들려줍니다.

| 키 또는 동작 | 기능 |
| :--- | :--- |
| 건반 클릭, 드래그 | 해당 건반을 트랙의 악기로 들려주기(오른쪽을 클릭할수록 세게). 드래그하면 지나가는 건반의 소리로 바뀝니다 |
| 빈 곳 더블클릭 | 음표 추가(길이는 마지막으로 클릭한 음표와 같음) |
| 빈 곳 우클릭 | 해당 건반을 근음으로 하는 코드나 그 건반에서 시작하는 스케일 삽입(아래 참고) |
| 클릭, 시프트 클릭 | 음표 선택, 선택에 추가하거나 제외 |
| 빈 곳 드래그 | 사각형 영역 안의 음표 선택 |
| 음표 드래그, ⌥ 드래그 | 이동(가로는 격자, 세로는 반음 단위), 복사 |
| 음표 오른쪽 끝 드래그 | 길이 변경 |
| 음표 더블클릭, 백스페이스 | 삭제 |
| ⌘A, ⌘C, ⌘X, ⌘V, ⌘D | 모두 선택, 복사, 잘라내기, 재생 위치에 붙여넣기, 바로 뒤에 복제 |
| 시프트 위, 시프트 아래 | 옥타브 단위 조옮김 |
| 왼쪽, 오른쪽 화살표 | 선택한 음표를 격자 한 칸 이동 |
| Q | 음표 시작을 격자에 맞추기(선택한 음표, 선택이 없으면 트랙 전체) |
| 편집 > 음표 다듬기, 음표 우클릭 | 격자에 맞추기(강도 25~100%, 스윙, 시작과 끝), 벨로시티 범위 넓히기, 좁히기, 크레셴도, 디미누엔도, 휴머나이즈(벨로시티 ±4~±14, 타이밍 ±6~±20ms), 레가토와 길이, 음계에 맞추기, 화음 펼치기(아르페지오 상행, 하행, 상하행, 격자마다 한 음, 스트럼은 음마다 15~60ms), 역행, 반행(선택한 음표, 선택이 없으면 트랙 전체. 도구마다 편집 한 번) |
| 편집 > 스텝 입력(⌘⇧E) | 정지 상태에서 컴퓨터 키보드나 MIDI 건반으로 연주한 음과 화음을 재생 위치에 격자 길이로 입력하고 한 칸 앞으로 이동합니다. 선택한 음표가 없을 때 →는 쉼표, ←는 한 칸 뒤로, 백스페이스는 마지막 칸 삭제입니다 |
| 드래그 중 ⌘ | 격자 무시 |
| 벨로시티 레인 | 막대 드래그(여러 음표를 선택했으면 함께 바뀝니다) |
| 컨트롤러 레인 | 더블클릭으로 점 추가, 삭제, 점 드래그, 우클릭으로 곡선 모양 선택. 레인은 레인 메뉴에서 추가합니다 |
| 템포 더블클릭 | 템포와 박자 변경 |
| 편집 > 재생 위치의 마디부터 박자 | 해당 마디부터 박자를 바꾸거나(2/4~12/8) 바뀐 박자를 삭제합니다. 박자 변경은 눈금자에 표시됩니다 |
| ⌘Z, ⌘⇧Z | 실행 취소, 다시 실행 |
| 보기 > 악보(⌥S) | 아래 패널에 선택한 트랙의 악보 표시(읽기 전용, 마디를 클릭하면 재생 위치가 그 마디로 이동) |
| 파일 > MusicXML 내보내기 | MuseScore, Finale, Sibelius, Dorico에서 열 수 있는 악보 파일로 내보내기 |
| 편집 > 실행 취소 기록 | 처음 상태, 지난 편집(오래된 순, 현재 위치 표시), 다시 실행할 수 있는 편집을 보여 줍니다. 항목을 선택하면 그 상태로 바로 이동합니다 |
| ⌘S, ⌘⇧S | 저장, 다른 이름으로 저장 |

격자는 왼쪽 트랙 정보 아래에서 선택합니다(4분음표부터 32분음표까지, 셋잇단음표).

**피아노 롤의 다른 트랙.** 아래 칸의 "다른 트랙..." 버튼(편집 > 피아노 롤의 다른 트랙, 트랙 헤더의 "피아노 롤에 함께"도 같습니다)으로 편집 중인 트랙 뒤에
다른 트랙의 음표를 그 트랙 색으로 흐리게 표시하거나("함께 보기"), 더 진하게 표시해 함께 편집합니다("함께 고치기"). 함께 고치는 트랙이 있으면 사각형 선택이
그 트랙의 음표도 선택하고, 이동, 길이 조절, 삭제, 조옮김, 격자 이동, 음표 다듬기가 모든 트랙에 한 번에 적용됩니다(편집 한 번, ⌘Z 한 번). 새 음표,
벨로시티, 아티큘레이션, 복사와 붙여넣기는 편집 중인 트랙에만 적용됩니다. 다른 트랙의 음표를 더블클릭하면 그 트랙으로 전환하고, 원래 트랙은 전환한 트랙의
보기 방식을 이어받습니다. 곡의 조(`key`, `keyChanges`는 그 박부터)에 속한 줄은 밝게, 으뜸음 줄은 더 밝게 표시하며, 피아노 롤 눈금자에 마커가 표시됩니다.

**드럼 보기.** 건반에 이름이 붙은 악기의 트랙(드럼 세트, 내장 드럼 신스, 관현악 타악기)은 드럼 보기로 열립니다. 이름이 있는 건반과 그 트랙에서 사용한 건반이
한 줄씩 표시되고, 타격은 벨로시티에 따라 크기가 다른 마름모로 그려집니다. 빈 칸을 클릭하면 타격을 추가하고(격자 한 칸, 마지막 벨로시티), 타격을 드래그해
옮기고(위아래는 줄 단위), 더블클릭해 삭제합니다. 왼쪽의 "드럼 보기" 버튼을 끄면 전체 건반 보기로 돌아가며, 이 설정은 트랙마다 저장됩니다.

**코드와 스케일 삽입.** 피아노 롤의 빈 곳을 우클릭하면 마우스 아래 건반을 근음으로, 격자에 맞춘 그 위치를 시작점으로 삽입합니다.
편집 > 코드 넣기, 스케일 넣기는 같은 메뉴를 재생 위치에서 열고, 근음은 C4~B4 중에서 선택합니다. 화음 66개는 아홉 그룹(3화음, 6화음,
7화음, 부가음 화음, 9화음, 11화음, 13화음, 변화 딸림화음, 증6화음과 4도 화음)으로, 음계 54개는 아홉 그룹(장음계와 교회 선법,
단음계와 화성 장음계, 가락 단음계와 화성 단음계의 선법, 평조와 계면조, 일본 음계를 포함한 5음 음계, 블루스, 대칭 음계, 비밥,
더블 하모닉, 헝가리, 나폴리 등 기타 음계)으로 나뉩니다. 항목마다 코드 기호(이름은 한국어)나 음계 이름(영어, 예: E Dorian)과 실제 구성음이 표시됩니다.
코드는 자리바꿈(기본형부터 셋째 자리바꿈까지)과 길이(격자 한 칸, 한 박, 두 박, 한 마디, 기본값은 한 마디)를, 스케일은 방향(상행, 하행,
상하행)과 범위(1~3옥타브)를 선택합니다. 스케일의 음 하나는 격자 한 칸 길이입니다. 삽입한 음표는 편집 한 번(⌘Z)으로 기록되고 선택된 상태로 남아
바로 옮기거나 조옮김할 수 있으며, 코드는 삽입할 때 소리가 납니다. 화음표와 음계표는 엔진에 있으며 `music-render chords`, `music-render scales`로 확인할 수 있습니다.

### 트랙, 마커, 편곡

곡의 구조는 트랙 보기에서 편집하며, 모든 변경은 편집 한 번(⌘Z)으로 기록됩니다.

- **트랙.** 마지막 트랙 아래의 "+ 트랙 더하기", 트랙 > 새 트랙(⌘⇧T), 트랙 헤더 메뉴의 "아래에 새 트랙"에서 악기를 선택하면 악기 이름으로
  빈 트랙("Grand Piano", 그다음은 "Grand Piano 2")이 생성됩니다. 복제(⌘⇧D)는 음표, 오토메이션, 효과, 플러그인 설정까지 바로 아래에 복사합니다.
  트랙 이름을 더블클릭해 바꾸면 그 트랙을 사이드체인 키로 쓰는 컴프레서도 새 이름으로 바뀝니다. 헤더를 드래그해 순서를 바꾸고, ⌘⌥↑, ⌘⌥↓로 선택한 트랙을
  이동합니다. 삭제(⌘⌫)해도 마지막 한 트랙은 남고, 삭제한 트랙을 키로 쓰던 컴프레서는 일반 컴프레서가 됩니다. 헤더 메뉴에서 선택한 색은 트랙에
  `"color": "#rrggbb"`로 저장되며, 색을 지정하지 않으면 트랙 순서에 따라 색이 정해집니다.
- **폴더와 그룹.** 트랙 헤더 메뉴의 폴더는 해당 트랙(선택한 구간에 포함되어 있으면 구간의 모든 트랙)을 새 폴더나 기존 폴더에 넣습니다. 폴더에 속한 트랙 위에는 이름과
  트랙 수가 표시되는 헤더가 생기고, 클릭하면 접거나 펼칩니다. 폴더 헤더 메뉴에는 이름 바꾸기, 모두 뮤트, 같은 이름의 버스로 묶기(버스가 없으면 생성)가 있으며,
  버스로 묶으면 그 버스 스트립이 폴더의 페이더와 효과 역할을 합니다. 모든 트랙은 헤더 메뉴의 출력에서 마스터 대신 버스로 보낼 수 있고(`"output": "Drums"`, 서브그룹),
  버스 이름을 바꾸거나 버스를 삭제하면 출력 설정도 함께 바뀝니다. 폴더는 트랙의 `"folder": "Drums"`이며 소리에는 영향을 주지 않습니다.
- **VCA.** 믹서의 "+ VCA"로 VCA 스트립(이름, 페이더, 뮤트, 소속 채널 수)을 추가하고, 트랙이나 버스 이름 메뉴의 VCA에서 채널을 VCA에 넣거나 새 VCA를 만듭니다.
  VCA로는 오디오 신호가 지나가지 않습니다. VCA의 게인과 게인 오토메이션은 소속 채널의 페이더에 더해지고, VCA를 뮤트하면 소속 채널이 모두 뮤트되며, 채널별 페이더 값은 그대로 유지됩니다
  (`"vcas": [{ "name": "Strings", "gainDb": -4 }]`와 트랙, 버스의 `"vca": "Strings"`). 소속 트랙의 오토메이션 레인에는 "VCA 게인"이 있고, VCA 이름을 바꾸거나 VCA를 삭제하면
  소속 채널의 설정도 함께 바뀝니다.
- **마커.** 마디 번호 아래의 마커 띠에 이름이 있는 위치를 표시하며, 곡의 `"markers": [{ "beat", "name" }]`에 저장됩니다. 띠를 더블클릭하면 가까운 마디에
  마커를 추가하고 이름을 입력할 수 있습니다. 마커를 더블클릭하면 이름을 바꾸고, 드래그하면 이동하고, 클릭하면 그 위치로 이동합니다. 우클릭 메뉴에는 이름 바꾸기, 여기서
  재생, 지우기가 있습니다. ⇧⌘M은 재생 위치의 마디에 마커를 추가하고, ⌥←, ⌥→로 마커 사이를 이동합니다. `export-midi`는 마커를 MIDI 마커 이벤트로 저장하고,
  MIDI 가져오기에서 다시 읽어 들입니다.
- **마커 구간.** 마커 띠 아래의 구간 띠에 마커에서 다음 마커까지(마지막은 곡 끝까지)를 블록으로 표시합니다. 블록을 드래그해 다른 구간 경계에 놓으면 그 자리로
  구간을 옮기고, 클릭하면 그 구간의 처음으로 이동하며, 더블클릭하면 모든 트랙에서 그 구간을 선택합니다. 우클릭 메뉴에는 여기서 재생, 구간 선택, 바로 뒤에 복제,
  앞으로/뒤로 옮기기, 지우기(뒤를 당김)가 있습니다. 구간을 옮기면 음표, 오디오 클립(경계에서 분할), 트랙과 버스와 마스터의 오토메이션, 템포, 박자 변경,
  조 변경, 마커가 함께 이동하고, 옮긴 자리에서 그 구간의 박자, 조, 템포로 시작하며 뒤의 음악도 원래의 박자, 조, 템포를 유지합니다. 구간의 경계는 마디 줄이어야 합니다.
- **구간.** 레인을 드래그하면 트랙 범위와 마디 범위를 선택합니다(충분히 확대하면 박 단위). 구간을 선택한 상태에서 ⌘C, ⌘X, ⌘V, ⌘D, 백스페이스는 선택한 트랙들의
  구간을 복사, 잘라내기, 붙여넣기, 바로 뒤에 복제, 내용 삭제합니다. 붙여넣기는 선택한 구간의 시작 위치에, 선택한 구간이 없으면 재생 위치와 선택한 트랙부터
  붙여 넣으며, 그 위치의 기존 내용은 삭제됩니다(음이 겹쳐 쌓이지 않습니다). 구간 안에서 시작한 음은 함께 옮겨지고(구간 끝을 넘는 부분은 잘림),
  구간 앞에서 시작해 붙여넣을 위치까지 이어지는 음은 그 위치의 시작점에서 잘립니다. 컨트롤러, 효과, 센드 오토메이션은 양 끝의 값을 점으로 추가한 뒤 잘라 붙이므로 구간
  밖의 값은 바뀌지 않습니다. 피아노 롤에서 음표를 선택하면 구간 선택이 해제되고, 구간을 선택하면 음표 선택이 해제됩니다.
- **시간 삽입과 삭제.** 편집 메뉴의 "고른 구간 길이만큼 시간 넣기", "고른 구간의 시간 지우기", "재생 위치의 마디에 빈 마디 넣기"(1, 2, 4, 8,
  16마디)는 곡 전체에 적용됩니다. 모든 트랙의 음표와 오토메이션, 버스와 마스터의 오토메이션, 템포 포인트, 마커, 반복 구간, `render.endBeat`가 함께 이동합니다.
- **MIDI 가져오기.** 파일 > MIDI 가져오기(⌘⇧I)는 표준 MIDI 파일(형식 0, 1)로 새 곡을 만듭니다. MIDI 트랙과 채널마다 트랙이 하나씩 생성되고,
  악기는 General MIDI 프로그램 번호에 맞춰 선택됩니다(채널 10은 `drum-kit`, 맞는 악기가 없으면 그랜드 피아노). 템포 맵, 첫 박자, 마커, 음표 가사를 읽어 오고,
  컨트롤러, 피치 벤드, 애프터터치는 계단형 오토메이션이 됩니다. `.mid` 파일을 창에 드래그해 놓으면 열린 곡에 트랙으로 추가됩니다(곡의 템포는 유지).
- **자동 저장.** 저장하지 않은 편집이 있으면 2분마다 앱 데이터 폴더에 사본을 저장합니다(곡 파일과 다른 폴더이므로 파일 감시와 작곡 스크립트에
  영향을 주지 않습니다). 사본이 곡 파일보다 최신이면 곡을 열 때 복구할지 묻습니다. 복구도 편집 한 번으로 기록되므로 ⌘Z로 파일 내용으로 되돌릴 수 있습니다.
  저장하거나 편집을 버리면 사본은 삭제됩니다.

같은 편집을 명령줄(`music-render arrange`, `music-render import-midi`, 아래 참고)에서도 할 수 있으므로, 작곡 스크립트와 AI 에이전트도 앱과 같은 방식으로 곡의
구조를 바꿉니다.

### 오디오 트랙

오디오 트랙은 오디오 파일(WAV, AIFF, FLAC, Ogg Vorbis, MP3)의 클립을 재생합니다. 다른 트랙과 같은 신호 체인(효과, 페이더, 센드, 버스, 마스터)을 거치므로
재생과 내보내기 결과가 같습니다.

- **가져오기.** 파일 > 오디오 가져오기(⌘⇧A)는 재생 위치의 마디에, 트랙 보기에 드래그 앤 드롭하면 놓은 위치(격자 기준)에 클립을 넣습니다. 오디오 트랙의 레인에 놓으면
  그 트랙의 클립이 되고, 다른 곳에 놓으면 파일마다 파일 이름으로 새 오디오 트랙이 생성됩니다. 곡 폴더 밖의 파일은 곡 폴더의 `audio/`로 복사되므로
  곡에서 사용하는 파일이 모두 곡 폴더 하나에 모입니다. 새 트랙 메뉴의 "오디오 트랙"은 빈 오디오 트랙을 추가합니다.
- **클립 편집.** 클립을 드래그해 옮기고(⌥를 누르면 복사), 왼쪽이나 오른쪽 끝을 드래그해 자르고(파일 안의 시작 위치도 함께 바뀜), 위 모서리의 작은 핸들을 드래그해
  페이드 인과 페이드 아웃을 적용합니다. 이동과 자르기는 구간 선택과 같은 격자를 따르며, ⌘를 누르면 격자를 무시합니다. 우클릭 메뉴에는 게인(지정 값과
  ±1dB), 노멀라이즈(클립 피크를 -1dBFS로), 재생 위치에서 나누기(⌘T), 바로 뒤에 복제(⌘D), 페이드 지우기, Finder에서 보기, 지우기(백스페이스)가 있습니다.
  모든 변경은 편집 한 번으로 기록됩니다. 파형은 데시벨 눈금으로 그리므로 작게 녹음된 소리도 모양을 확인할 수 있습니다.
- **리버스, 페이드 모양, 게인 곡선, 크로스페이드.** 클립 메뉴의 "거꾸로 재생"은 같은 자리에서 파일의 같은 부분을 거꾸로 재생합니다(`"reverse": true`).
  이때 클립의 파일 기준 초는 파일 끝에서부터 세므로 자르기, 나누기, 워프 마커, 음별 피치 편집이 그대로 동작하고, 어택 찾기, 템포 측정, 채보, 퀵 샘플러 같은
  분석은 거꾸로 돌린 사본을 읽습니다. 페이드마다 모양을 선택할 수 있고 클립 위에 그 모양대로 그려집니다: S자(기본, 마주 보는 두 페이드의 크기 합이 1),
  직선, 등전력(마주 보는 두 페이드의 파워 합이 1), 지수(-60dB부터 데시벨로 직선). 보기 > 클립 게인 곡선 편집(⌥G)을 켜면 클립을 클릭해 게인 포인트를
  추가하고(위가 +12dB, 아래가 -36dB), 드래그해 옮기고, ⌥를 누른 채 클릭해 삭제합니다. 곡선은 파일 기준 초에 놓이므로(`"gainCurve": [{ "seconds": 1, "value": 0 }, { "seconds": 3, "value": -12 }]`)
  클립을 옮기거나 자르거나 나눠도 같은 소리에 붙어 있고, 파형도 곡선을 따라 그려집니다. "뒤 클립과 크로스페이드"는 겹친 구간에 크로스페이드를 넣고,
  맞붙기만 한 두 클립(나눈 클립)은 파일의 소리로 서로 10ms씩 늘여 겹칩니다. 같은 소리가 이어지는 두 조각은 S자(나눈 클립을 다시 크로스페이드하면 나누기 전과
  3e-8 이내로 같음), 다른 소리는 등전력 페이드(서로 상관없는 두 잡음이 겹친 구간에서 0.08dB 이내)를 사용합니다. 편집 > 클립을 영점에서 자르기를 켜면
  나누기와 끝 자르기 위치를 10ms 안의 가장 가까운 영점 교차로 옮깁니다. 명령줄에서는 `arrange song.json reverse Vocal --clip 2`,
  `fade Vocal --clip 2 --in 0.1 --out-shape exponential`, `crossfade Vocal [--clip 1] [--ms 20]`을 사용합니다.
- **시간.** 클립의 위치는 박 단위이지만 소리는 초 단위로 재생됩니다. 템포를 바꾸면 시작 위치만 이동하고 재생 속도는 그대로입니다. 구간 편집과 시간 삽입, 삭제는
  클립을 경계에서 나누고 파일 안의 시작 위치를 조정합니다.
- **오디오 녹음.** 오디오 트랙을 선택하고 ⌥R을 누릅니다(MIDI 녹음과 같은 버튼이며 카운트인도 같습니다). 입력이 꺼져 있으면 기본 입력의 첫 두 채널을 켭니다(처음에는
  macOS가 마이크 권한을 요청합니다. 다른 입력은 설정 > 오디오 장치에서 선택합니다). 녹음하는 동안 `audio/<트랙> take N.wav`에 24비트 WAV로 저장하며, 재생이
  멈추거나 위치가 건너뛰면(탐색, 반복) 테이크가 끝납니다. 각 테이크는 클립 하나로 들어가고, 믹스의 출력 지연과 장치의 입출력 지연만큼 앞당겨 배치되므로 실제로 연주한
  위치와 맞습니다. 녹음 중에는 빨간 띠와 입력 레벨이 표시됩니다.
- **테이크와 컴핑.** 반복 재생 중에 오디오를 녹음하면 반복할 때마다 이어서 녹음합니다. 반복마다의 소리가 한 파일에 담기고, 반복 구간 위에 반복마다 클립이 하나씩 생깁니다
  (마지막 테이크가 재생되고, 이전 테이크는 뮤트되어 레인 아래 띠에 표시됩니다). 클립 메뉴의 테이크에는 그 클립과 겹치는 클립이 나열되고, 하나를 선택하면 그 위치에서
  해당 테이크가 재생되고 나머지는 뮤트됩니다. 트랙 보기에서 구간을 선택한 상태로 테이크를 선택하면 그 구간만 바뀌므로(경계에서 클립을 나눔) 좋은 부분만 골라 이어 붙일 수 있습니다.
  클립 메뉴에서 클립을 직접 뮤트할 수도 있습니다(`"muted": true`).
- **템포 감지와 슬라이스.** 클립 메뉴 > 템포 재기는 클립이 재생하는 구간의 템포를 분석해 클립의 `sourceBpm`에 저장하고, 클립이 곡 템포를 따르도록 설정합니다(스펙트럴 플럭스로 찾은 어택, 그 자기상관의 콤(comb) 점수, 어택 쌍이 박의 배수에 맞는 정도로 보정, 정수 마디로 자른 루프는 그 길이에 맞춤). 클립 메뉴 > 어택으로 조각내기(새 악기와 트랙)는 클립을 어택 바로 앞마다 잘라 C2부터 건반에 하나씩 배치한 SFZ를 곡 폴더에 생성하고, 그 조각들을 클립이 소리 내던 위치에서 연주하는 트랙을 추가합니다. 이렇게 하면 템포를 바꾸거나 음을 옮겨 루프를 다시 구성할 수 있습니다. 앱이 생성하는 SFZ(조각과 퀵 샘플러)는 `volume=11.51`로 sfizz의 기본 감쇠를 상쇄하므로, 벨로시티 127에서 녹음된 크기 그대로 재생됩니다. 명령줄에서는 `music-render tempo loop.wav`, `music-render slice loop.wav --output kit.sfz [--root C2]`를 사용합니다.
- **워프 마커와 오디오 퀀타이즈.** 클립의 `warp` 마커는 파일의 한 시점(초)을 곡의 한 박에 고정하고, 클립은 마커 사이를 곡의 템포 맵에 맞춰 늘이거나 줄입니다. 클립 메뉴 > 어택을 격자에 맞추기(1/4, 1/8, 1/16과 셋잇단, 강도 100~25%)는 어택을 찾아 격자로 당기는 마커를 생성합니다(클립의 양 끝은 고정). 마커는 클립 아래 모서리의 삼각형입니다. 마커를 드래그하면 그 위치의 소리가 이동하고(⌘를 누르면 격자 무시), ⌥를 누른 채 클릭하면 삭제되며, 클립을 더블클릭하면 마커가 추가됩니다. 워프 방식은 늘이기(음높이 유지)와 슬라이스 두 가지입니다. 슬라이스는 마커의 10ms 앞마다 잘라 조각을 늘이지 않고 제자리에서 재생하므로 타악기의 어택이 그대로 유지됩니다. 스윙으로 연주한 드럼 세트의 킥, 스네어, 하이햇 스템을 슬라이스 방식으로 곧은 1/16 격자에 맞추면 타격 61개가 모두 정확히 격자에 놓입니다. 명령줄에서는 `music-render arrange song.json quantize-audio Drums --grid 1/16 [--strength 100] [--mode slice]`, `unwarp Drums`를 사용합니다.
- **음높이 교정.** 클립 메뉴 > 음높이 교정은 보컬이나 악기의 음높이를 분석해 가장 가까운 반음이나 곡의 조에 속한 음(곡에 조가 없으면 음표로 추정한 조)으로 보정합니다. 속도는 빠르게(0ms, 비브라토도 평평해짐), 보통(30ms), 자연스럽게(80ms, 꾸밈음과 비브라토 유지) 중에서 선택하고, 강도 100~25%와 포먼트 유지도 설정할 수 있습니다. 클립의 `pitchCorrection`(`strength`, `speedMs`, `key` 또는 `scale`과 `root`)은 클립과 함께 렌더링되므로 재생과 내보내기 결과가 같습니다. 30센트 높게 옮긴 실제 테너 색소폰 녹음에서 반음 ±10센트 안에 드는 프레임이 교정 전 1%에서 교정 후 93%로 늘었습니다. 명령줄에서는 `music-render arrange song.json tune Vocal --key "A minor" [--speed 30]`, `untune Vocal`을 사용합니다.
- **음별 피치 편집.** 오디오 트랙을 선택하면 피아노 롤에 녹음의 음이 덩어리로 표시됩니다: 음마다 중심 음높이의 막대와 측정한 피치 곡선이 피치 줄 위에 놓입니다(멜로디 채보와 같은 방식으로 음을 나누고, 파일마다 한 번 백그라운드에서 분석). 음을 위아래로 드래그하면 중심 음높이가 반음에 맞고, ⌥ 드래그는 센트 단위로 옮깁니다. 선택한 음 위의 핸들 두 개로 느린 피치 흔들림을 중심으로 평평하게 하는 정도(0~100%)와 비브라토 크기(0~200%)를 조절합니다. ↑와 ↓는 반음씩 옮기고, 우클릭 메뉴에서 되돌리기, 가까운 반음에 맞추기, 값 선택을 할 수 있습니다. 음의 시작이나 끝을 드래그하면 그 음의 양 끝과 이웃 음에 워프 마커를 넣고 옮기므로 그 둘레의 음만 늘어나거나 줄어듭니다. 편집은 클립의 `pitchEdits`(파일 기준 `seconds`, `lengthSeconds`, `semitones`, `flatten`, `vibrato`)에 저장되고 음높이 교정처럼 클립과 함께 렌더링됩니다. 편집한 음 안에서는 클립의 음높이 교정보다 편집이 우선합니다. 43음짜리 테너 색소폰 녹음에서 두 음을 2반음 옮겼을 때 나머지 40음은 0.7센트 안에서 그대로였습니다. 명령줄에서는 `music-render notes take.wav`로 녹음의 음 목록을, `music-render arrange song.json pitch-edit Vocal --note 3 --to E4 [--flatten 100] [--vibrato 0]`로 음 하나를 편집합니다.
- **그루브.** 그루브는 한 주기 동안 격자 칸마다의 타이밍 오차와 강세를 기록한 것입니다. 기본 그루브(16분음표 스윙 54~66%, 8분음표 스윙 55~67%, 느긋하게, 서두르게, 2, 4박 강세)가 제공되며, 사용자 그루브는 음표 다듬기 > 그루브 입히기 > 이 음표로 그루브 저장, 또는 클립 메뉴 > 어택으로 그루브 저장(16분음표 격자에서 벗어난 양과 크기)으로 만듭니다. 그루브는 음표(시간과 세기, 반만, 시간만, 세기만 중 선택)나 오디오 클립(어택을 격자에 맞추기 > 그루브로, 워프 마커 사용)에 적용합니다. 16분음표 스윙(0.042박)으로 연주한 실제 드럼에서 엇박의 어긋남을 +0.033~+0.043박으로 추출합니다. 명령줄에서는 `music-render groove list`, `groove extract song.json --track Kit`, `groove extract-audio loop.wav --bpm 94`, `arrange song.json groove Hat --groove swing-16-58`을 사용합니다.
- **곡 템포를 녹음에 맞추기.** 클립 메뉴 > 곡 템포를 이 녹음에 맞추기는 메트로놈 없이 연주한 녹음에서 모든 박을 찾고(어택 세기에 대한 동적 계획법, 가까운 어택으로 보정), 박마다 템포 포인트를 추가해 곡의 마디가 연주를 따라가게 합니다. 클립은 늘이지 않고, 첫 박이 마디의 시작에 놓이며, 다른 트랙의 음은 원래 박에 남습니다. 90BPM에서 110BPM으로 빨라지는 연주에서 모든 박이 곡의 정수 박에서 0.003박 이내에 놓입니다(맞추기 전에는 0.494박). 명령줄에서는 `music-render beats take.wav`, `music-render arrange song.json follow-tempo Drums`를 사용합니다.
- **트랙 템플릿.** 트랙 헤더 메뉴 > 트랙 템플릿으로 저장은 트랙의 악기와 사운드(`synth`, 플러그인 상태), 효과, 믹서, 센드, 출력, 색을 저장합니다. 음표, 클립, 오토메이션은 저장하지 않습니다. 곡 안에서 정의한 악기는 그 정의를 절대 경로와 함께 담습니다. 트랙 더하기 > 템플릿에서는 기본 템플릿(보컬, 드럼 세트, 그랜드 피아노, 베이스 기타, 신스 리드, 신스 패드, 현악)이나 사용자 템플릿(`InitialDAW/TrackTemplates/`)으로 새 트랙을 만들며, 곡에 없는 버스로 가는 센드와 사이드체인 키는 제외합니다. 명령줄에서는 `music-render track-template list`, `track-template save song.json Lead --output lead.json`, `arrange song.json add-track --template vocal`을 사용합니다.
- **멜로디를 음표로.** 클립 메뉴 > 멜로디를 음표로(새 트랙)는 클립이 재생하는 단선율(노래나 허밍 녹음, 독주 악기)을 음표로 변환해 클립 아래의 새 트랙에 넣습니다. 5ms마다 음높이를 분석하고(YIN), 쉼, 음높이 변화, 같은 음을 다시 치는 어택에서 음을 나누며, 클립의 위치와 늘이기, 음높이 변경을 반영해 곡의 박에 배치합니다. 음표는 연주한 타이밍을 그대로 유지하므로(`"humanize": false`) 필요하면 피아노 롤에서 퀀타이즈합니다. `music-render transcribe hum.wav --output melody.json --bpm 96`은 같은 작업을 해서 새 곡 파일을 만듭니다.
- **입력 모니터링.** 트랙 > 입력 모니터링(⌥I, 오디오 트랙 헤더 메뉴에도 있음)은 입력 소리를 그 트랙의 효과, 페이더, 밸런스, 센드를 거쳐 들려줍니다(재생 중이든 정지 상태든,
  한 번에 한 트랙만). 재생 엔진과 장치의 지연만큼 늦게 들리므로, 지연 없이 들으려면 오디오 인터페이스의 다이렉트 모니터링을 사용하세요.
- **트랙을 오디오로 굳히기(바운스).** 트랙 > 트랙을 오디오로 굳히기(⌘⌥B, 트랙 헤더 메뉴의 "오디오로 굳히기")는 선택한 트랙의 악기와 효과를 거친 소리(페이더 앞)를 백그라운드에서
  `audio/<트랙> bounce N.wav`로 렌더링합니다. 사이드체인 키 트랙도 함께 렌더링하므로 컴프레션이 그대로 적용됩니다. 범위는 첫 소리가 있는 마디부터 마지막 소리 뒤 0.1초까지입니다.
  파일은 원래 트랙 바로 아래의 새 오디오 트랙에 들어가고, 새 트랙이 색, 페이더, 밸런스, 센드를 이어받으며 원래 트랙은 뮤트됩니다. 따라서 믹스 결과가 같고
  (24비트 반올림 오차 이내) 한 번에 되돌릴 수 있습니다.
- **타임 스트레치와 음높이.** 클립 우클릭 메뉴에서 음높이(-12~+12반음, 길이 유지)와 늘이기를 설정합니다. 늘이기는 곡 템포 따르기(현재 위치의 곡 템포를 클립의 템포로 지정해 두고,
  나중에 곡 템포를 바꾸면 클립의 박이 곡의 박에 맞도록 늘어나거나 줄어듦)와 길이 0.5~2배 중에서 선택합니다. 곡 파일에는 `"sourceBpm": 92`, `"stretch": 1.5`,
  `"pitchSemitones": -2`로 저장됩니다(파일 안의 위치와 길이는 항상 파일 기준의 초). 늘인 소리는 클립을 준비할 때 한 번 생성해 두므로(Signalsmith Stretch)
  재생, 탐색, 반복, 내보내기가 모두 같은 샘플을 출력합니다.
- **곡 파일 형식.** 오디오 트랙은 `"instrument": "audio"`와
  `"clips": [{ "file": "audio/take.wav", "startBeat": 16, "offsetSeconds": 0.5, "lengthSeconds": 12, "gainDb": -3, "fadeInSeconds": 0.05, "fadeOutSeconds": 1 }]`로
  정의합니다. 오디오 파일은 한 번 읽어 재생 샘플레이트로 변환한 뒤 여러 클립이 공유하며, 재생 엔진은 클립을 곡 위치만으로 읽으므로 탐색, 반복, 내보낸 파일이 같은 샘플을 출력합니다.

### 영상

파일 > 영상 붙이기...(또는 창에 .mp4, .mov, .m4v 파일을 드래그 앤 드롭)로 곡에 영상을 붙여 화면에 맞춰 음악을 작성합니다. 곡 파일에는
`"video": { "file": "clips/promo.mp4", "offsetSeconds": 2 }`로 저장됩니다(`offsetSeconds`는 영상의 첫 프레임이 놓이는 곡의 초, 곡 폴더 안의 파일이면
곡 폴더 기준 상대 경로). 영상은 소리에 사용하지 않으며, 템포를 바꾸거나 마디를 삽입해도 영상은 같은 초에 있습니다.

- **영상 레인.** 트랙 위에 타임코드(시:분:초:프레임, 29.97과 59.94fps는 `;`로 표시하는 드롭 프레임)와 백그라운드에서 읽은 섬네일이 표시됩니다. 레인을
  드래그하면 영상 위치가 바뀝니다(격자 기준, ⌘를 누르면 프레임 단위, 첫 마디보다 왼쪽으로 드래그하면 영상이 곡보다 먼저 시작). 레인을 클릭하면 재생 위치가
  이동하고, 우클릭하면 아래 메뉴가 열립니다.
- **영상 창.** 보기 > 영상 창(⌥V)은 재생 위치의 프레임을 표시합니다. 정지 중에는 그 시각의 프레임을 정확히 읽고, 재생 중에는 미리 디코딩하면서 재생기와
  오디오 장치의 출력 지연을 빼므로 들리는 소리와 화면이 맞습니다.
- **장면 전환.** 레인 메뉴의 "장면 바뀜 찾기"는 컷이 바뀌는 지점(이웃 프레임의 밝기 히스토그램 차이가 주변보다 크게 튀는 지점)을 찾아 표시합니다. 후보는
  곡에 저장되지 않습니다. 후보를 더블클릭하면 그 박에 "장면 N" 마커를 추가하고, "장면 바뀜을 모두 마커로"는 모든 후보를 마커로 추가합니다.
- **영상의 소리.** "영상의 소리를 오디오 트랙으로"는 소리를 `audio/<영상> 소리.wav`로 저장하고, 영상이 시작하는 위치에 클립이 놓인 "영상 소리" 오디오
  트랙을 추가합니다(곡보다 앞선 부분은 잘라냅니다).
- **영상에 음악 입히기.** 내보내기 대화상자에서 형식 "영상 (MP4)"를 선택하면 영상에 음악을 입혀 출력합니다. 화면은 다시 인코딩하지 않고 그대로 복사하며,
  소리는 영상 길이만큼의 AAC(128~320kbps)입니다. 영상의 t초에는 곡의 t + offset초가 재생됩니다. "영상의 원래 소리 섞기"를 선택하면 영상에 있던 소리를 함께 섞습니다.

### 악기와 플러그인

플러그인 악기를 사용하는 트랙에는 악기 패널이 있습니다. 플러그인 자체 UI(Dexed는 DX7 전면 패널)를 별도 창으로 띄우고, 자체 UI가 없는
플러그인은 파라미터 목록을 표시합니다. 믹서 스트립의 이름 아래 악기 줄을 클릭하거나, 트랙 헤더를 더블클릭하거나, ⌘I로 엽니다.
노브를 돌린 뒤 0.5초 동안 변화가 없으면 플러그인 상태를 트랙에 저장합니다(`"plugin": { "state": "..." }`, 표준 base64). 이것도 편집 한 번이므로
⌘Z로 이전 사운드로 되돌릴 수 있습니다. 명령줄 렌더링에서도 같은 소리가 나므로, 패널에서 만든 사운드는 앱 설정이 아니라 곡 파일에 남습니다.

- **내장 신스 패널.** 내장 신스(`synth.*`)를 사용하는 트랙에서는 앱 자체 패널이 열립니다. 프리셋 이름 아래에 노브가 섹션별로 배치되어 있습니다: 오실레이터(디튠 폭, 노이즈), 필터(켜기, 방식, 컷오프, 레조넌스, 엔벨로프 양과 디케이, 벨로시티, 키 트래킹), 앰프 엔벨로프(ADSR), 비브라토, 피치(피치 벤드 범위), 출력(드라이브, 벨로시티 커브, 스테레오 폭, 레벨). 필터 방식(로우패스, 하이패스, 밴드패스)은 필터 섹션 위의 목록에서 선택하며, 곡에는 이름으로 저장됩니다. 드럼 키트는 키트의 건반, 피치 섹션(반음 단위 튜닝과 피치 벤드 범위), 레벨을 표시합니다. 그래프는 오실레이터를 합친 파형 두 주기, 음을 누르고 있을 때와 막 시작할 때의 필터 응답, 엔벨로프 모양을 그리고, 피아노와 플럭 프리셋에서는 건반별 감쇠 시간을 그립니다. 그래프는 엔진이 실제로 연주할 때 쓰는 계산식 그대로 계산합니다. 노브를 돌리면 바로 들리고, 손을 떼면 편집 한 번으로 기록됩니다. 트랙에는 `"synth": { "cutoffHz": 600 }`처럼 프리셋과 다른 값만 저장됩니다. 노브를 더블클릭하면 프리셋 값으로 돌아가고, 초기화하면 바꾼 값이 모두 삭제됩니다. 레지스트리 항목이나 곡 안의 악기 정의에서도 신스 프리셋에 `"parameters"`를 지정할 수 있습니다.
- **퀵 샘플러.** 트랙 > 오디오로 악기 만들기...는 오디오 파일 하나를 건반 전체에서 연주할 수 있는 악기로 만들고, 클립 메뉴에서는 그 클립이 재생하는 파일 구간으로 같은 작업을 합니다(건반 전체에 피치를 바꿔 배치하거나, 드럼과 효과음용 원샷: 모든 건반이 같은 소리). 소리의 음높이를 분석해(어택 이후 구간을 YIN으로 분석하고, 음높이가 뚜렷한 구간의 중앙값 사용) 가장 가까운 건반을 루트 키로 삼고 남은 차이를 센트 단위로 보정합니다. 그래서 E5로 입력한 음이 실제로 E5로 재생됩니다. 오디오 파일은 곡 폴더의 `samples/`에 복사되고 같은 위치에 SFZ가 생성됩니다. 악기 정의는 곡의 `"instruments"`에 추가되고, 그 악기를 연주하는 새 트랙과 함께 편집 한 번으로 기록됩니다. `music-render sampler <오디오> --output <악기.sfz> [--root C3] [--one-shot]`은 같은 SFZ를 생성하고 분석한 주파수를 출력합니다.
- **악기 바꾸기.** 트랙 헤더나 믹서 스트립의 이름을 우클릭합니다. 목록에는 내장 신스, 샘플 악기, 레지스트리의 플러그인, 이 컴퓨터에서 찾은 플러그인이 나옵니다. 찾은 플러그인을 선택하면 그 정의도 곡에 저장됩니다(`"instruments": [ { "이름": { "type": "vst3", ... } } ]`). 따라서 레지스트리 파일을 따로 만들 필요가 없습니다. 이전 악기의 플러그인 설정은 삭제됩니다.
- **플러그인 찾기.** 트랙 메뉴의 플러그인 찾기는 별도 프로세스에서 VST3(표준 폴더와 `external/plugins`)와 AU를 검색합니다. 검사 중에 멈추는 플러그인이 있어도 앱은 종료되지 않습니다. 결과는 `music-render plugins scan`과 같은 플러그인 캐시에 저장됩니다.
- **불러오는 플러그인.** 플러그인은 불러오는 순간 실행되는 코드이므로, 곡이 플러그인 파일을 함께 가져올 수 없습니다. 곡이나 레지스트리가 가리키는 VST3는 설치된 플러그인 폴더(`/Library/Audio/Plug-Ins`, `~/Library/Audio/Plug-Ins`), `external/plugins`, `MUSIC_RENDER_PLUGIN_PATH`에 적은 폴더(콜론으로 구분), 플러그인 찾기와 `music-render plugins scan`이 저장한 플러그인 캐시에 있는 것만 불러오고, 그 밖의 경로는 이유와 함께 거부합니다. 명령줄에 직접 지정한 플러그인(`plugins describe`, `plugins save-state`)은 불러옵니다.
- **아티큘레이션.** 피아노 롤에서 선택한 음표를 우클릭해 악기 프로필의 아티큘레이션(`legato`, `pizzicato` 등)이나 트랙 기본값을 선택합니다. 음표에는 음 이름 옆에 아티큘레이션이 표시됩니다.
- **밴드 악기.** `drum-kit`은 어쿠스틱 록 드럼 세트(MuldjordKit, CC BY 4.0, 출처 "MuldjordKit by Lars Muldjord")이며 GM 건반 배치를 따릅니다: 36 킥, 38 스네어, 42 클로즈드 하이햇, 46 오픈 하이햇, 49와 57 크래시, 51 라이드, 53 라이드 벨, 50 48 47 45 탐, 43 41 플로어 탐. 벨로시티로 샘플 레이어를 선택하고, 레이어마다 네 번 녹음한 샘플 중 하나가 재생됩니다. 건반 배치는 레지스트리의 `"keymap": { "36": 48 }`(트랜스포즈를 적용한 뒤의 건반 번호에서 악기의 건반 번호로)로 바꿀 수 있습니다. `"keyNames"`로 건반에 이름을 붙이면 피아노 롤이 건반과 음표에 이름을 표시하고, 이름이 있는 줄만 밝게 칠합니다(드럼 세트, 내장 드럼 신스, 관현악 타악기). `bass-guitar`(핑거 주법, `pick` 아티큘레이션은 피크 주법), `electric-guitar`(클린), `jazz-guitar`, `tenor-sax`는 CC0 FreePats 음원이며, `engine/instruments/calibration/`에 건반별 음량 보정표가 있습니다(색소폰과 기타는 건반 간 음량 차이가 6~10dB입니다).
- **독주 첼로.** `cello-solo`는 Karoryfer x bigcat 첼로(CC0, Copyright 2016 Karoryfer Lecolds and bigcat instruments, 연주 Kamila Borowiak) 샘플을 이 저장소에서 만든 SFZ로 연주합니다. CC0라서 출처 표기 의무는 없지만 밝혀 둡니다. SFZ는 `tools/make-cello-sfz.py`가 샘플 폴더에 생성합니다. `build.sh`는 `--samples`로 샘플을 내려받은 뒤와 빌드할 때마다 이 도구를 실행하며, 샘플을 다른 위치에 두었다면(`MUSIC_RENDER_KARORYFER`) 그 폴더를 대상으로 도구를 직접 실행하면 됩니다. 활 연주는 건반 34~86(Bb1~D6), 피치카토는 34~75이고, 그 밖의 음은 소리가 나지 않습니다. SFZ가 샘플마다 튜닝과 음량을, 어택 이후의 음량 변화까지 맞추므로 건반 보정이 필요 없습니다(반음계에서 이웃 건반 차이 평균 0.65~1.3dB). CC1은 음을 시작할 때 네 다이내믹 레이어 중 하나를 선택하고(42까지 p, 72까지 mp, 100까지 mf, 그 이상은 f), 음이 울리는 동안에는 음량(24dB 폭)과 밝기(기음의 3.5배 주파수에 둔 셸빙 필터)를 함께 바꿉니다. 두 레이어가 만나는 지점에서도 밝기가 갑자기 변하지 않습니다. 긴 음은 음높이가 2센트 이내로 맞고 크로스페이드에서 음량이 꺼지지 않는 구간을 루프하며, 음마다 다른 느린 음량 변화 네 개가 더해집니다. 녹음에 비브라토가 없어서 음마다 5.2~5.9Hz의 비브라토를 추가합니다. 새로 시작하는 음은 0.15~0.25초 뒤부터, 레가토로 이어지는 음은 처음부터 비브라토가 걸리며, 깊이는 CC21로 음이 울리는 동안에도 조절할 수 있습니다(기본값 64에서 ±12센트, 127에서 ±20센트, 0이면 없음). 기본 아티큘레이션 `legato`는 겹친 음을 새 어택 없이 잇고, 음정의 5분의 1만큼 떨어진 음높이에서 미끄러져 들어옵니다(목표 30센트 이내까지 온음 13ms, 옥타브 40ms). 같은 음을 다시 켜면 활을 새로 긋습니다. `sustain`은 음마다 활을 새로 긋고 릴리스가 짧아 겹음에 사용합니다. `staccato`와 `pizzicato`는 음표 길이와 상관없이 녹음 끝까지 울립니다.
- **Dexed.** `./build.sh --plugins`는 Dexed 1.0.1(GPLv3)을 GitHub 릴리스에서 내려받아 SHA-256을 확인하고 `external/plugins/dexed`에 압축을 풉니다. 앱과 엔진은 실행 중에 불러올 뿐 링크하거나 함께 배포하지 않습니다. 내려받지 않았으면 `dexed` 악기 대신 `synth.ep`로 재생됩니다.

### 믹서

믹서는 별도의 상태를 갖지 않습니다. 페이더, 밸런스, 뮤트, 솔로, 센드, 효과가 곧 곡의 `mixer`, `sends`, `effects`이므로
앱에서 만든 믹스가 명령줄 렌더링에도 그대로 적용됩니다. 드래그하는 동안에는 재생 엔진에만 반영해 들려주고, 마우스를 놓으면 편집 한 번으로 기록되어 ⌘Z
한 번으로 되돌릴 수 있습니다. 재생 중에 바꾸면 바로 들립니다. 페이더와 센드는 오디오 블록 하나에 걸쳐 부드럽게 바뀌고, 교체한 효과는
이전 효과의 상태를 이어받으므로 리버브 테일과 딜레이 에코가 끊기지 않습니다. 템포, 트랙이나 버스 목록, 사이드체인 키,
트랙 효과의 지연이 바뀌면 재생 엔진을 다시 준비합니다(큰 곡에서 1~2초).

효과 추가 메뉴에는 필터와 덕킹도 있습니다. 곡에 오토메이션이 있는 파라미터는 이름 뒤에 (곡선)이 붙고 노브가 비활성화됩니다.
노브에는 오토메이션이 없을 때 쓰는 고정값이 표시되며, 다른 파라미터를 바꿔도 오토메이션은 그대로 남습니다. 레벨 오토메이션이 있는 센드는 레벨
대신 곡선으로 표시되고, 드래그하거나 0dB로 되돌릴 수 없습니다. 딜레이의 박 단위 시간을 켜면 밀리초 시간이 지워지고, 끄면 곡의 첫
템포에서 같은 길이가 되는 밀리초 값이 입력됩니다.

**오토메이션.** 피아노 롤 아래 레인에 선택한 트랙의 오토메이션 곡선이 표시됩니다. 곡선 추가 메뉴에서 믹서(볼륨, 밸런스), 센드, 오토메이션을 지원하는
효과 파라미터, MIDI 컨트롤러 중 대상을 선택합니다. 대상마다 눈금이 있고(볼륨과 센드는 페이더 눈금, 주파수와 시간은 로그 눈금), 드래그 중인 포인트나
재생 위치의 값이 표시됩니다. 더블클릭으로 포인트를 추가하거나 삭제하고, 드래그해 옮기고, 우클릭으로 곡선 모양을 선택합니다. 레인 목록에는 항상 템포(곡 전체)가
있습니다. 템포 포인트는 계단형이나 램프형이고, 첫 포인트는 0박에 고정되며, 눈금은 곡의 가장 느린 템포와 가장 빠른 템포에 맞춰집니다. 오토메이션이 있는 페이더와
밸런스는 믹서에서 드래그할 수 없고, 재생하는 동안 오토메이션을 따라 움직입니다. 보기 > 곡선 쓰기(⌥A)를 켜면 반대로 손으로 조작한 움직임을 오토메이션으로 기록합니다. 재생하면서 채널의
페이더나 밸런스를 움직이면 그 움직임이 오토메이션이 되고(그동안은 기존 오토메이션 대신 손으로 조작한 값이 들림), 손을 떼면 원래 오토메이션으로 돌아갑니다(터치 모드).
오디오 트랙에서는 벨로시티 레인 대신 오토메이션 레인을 사용합니다. 오토메이션은 곡의 `automation` 객체이며 곡 위치의 32샘플 격자에서 읽으므로 재생과 내보내기 결과가 같고,
오토메이션을 고치면 재생 엔진을 다시 만들지 않고 교체합니다.

| 버스 이름 더블클릭, 우클릭 | 이름 바꾸기(센드도 함께 바뀜), 지우기(그 버스로 가는 센드도 삭제) |
| + 버스 | 리버브가 들어 있는 버스 추가 |

파라미터 패널은 엔진의 파라미터 표로 만들어지므로 값의 범위가 곡 파일 파서의 범위와 같습니다. EQ는 엔진이 쓰는 필터 계수로 계산한
주파수 응답을 그립니다. 바이패스한 효과도 지연은 그대로 유지하므로 바이패스를 켜고 꺼도 트랙의 타이밍이 밀리지 않습니다. 트랙과 버스의 미터는
페이더 뒤, 마스터 미터는 모니터 게인 뒤(실제로 들리는 소리)의 레벨을 표시합니다.

저장할 때 앱이 수정하지 않은 부분은 그대로 유지됩니다. 주석, 앱이 모르는 필드, 키 순서, 음표에 붙은 다른 필드도 보존합니다.
파일에는 음표 하나를 한 줄로 저장하므로, 수정한 곡의 diff를 사람이 쉽게 읽을 수 있습니다.

- 파일이 바뀌면 다시 불러오고, 재생 중이었으면 같은 위치에서 이어서 재생합니다. 저장하지 않은 편집이 있으면 먼저 확인합니다. 이 기능은 파일 메뉴에서 끌 수 있습니다.
- 곡의 생성 스크립트(`compose.py`)를 다시 실행하면 JSON을 새로 생성하므로 그 파일에서 한 편집이 사라집니다. 직접 수정한 버전은 다른 이름으로 저장해 두세요(⌘⇧S).
- 모니터 게인은 재생할 때만 적용되는 음량입니다. 기본값은 0dB이고, 곡에 목표 라우드니스(`master.targetLufs`)가 있으면 앱이 백그라운드에서 곡을 렌더링해 내보내기에 적용될 게인과 같은 값으로 맞춥니다. 그래서 재생 음량이 내보낸 파일과 같습니다. 슬라이더를 직접 움직이면 그 값이 유지됩니다.
- 오디오 장치와 최근 파일 목록은 `~/Library/Application Support/InitialDAW.settings`에 저장됩니다.

창 없이 실행할 수도 있으며, 스크린샷과 테스트에 사용합니다.

```bash
APP=build/app/InitialDAW_artefacts/Release/InitialDAW.app/Contents/MacOS/InitialDAW
$APP --snapshot screen.png --size 1440x900 --track 3 --at 40 --bars 9-16 --lane cc1 song.json   # 화면을 PNG로 저장하고 종료합니다
$APP --snapshot mixer.png --size 1440x900 --track 13 --at 75 --effect 13:0 song.json   # 효과 파라미터 패널을 연 믹서 (--effect master:0, bus1:0. 효과 없이 믹서만 보려면 --mixer)
$APP --edit-test song.json              # 곡의 사본에서 편집(음표, 오토메이션, 템포, 악기, 아티큘레이션), 실행 취소, 다시 실행, 저장 후 다시 읽기를 실행하고, 피아노 롤과 믹서의 마우스 동작을 시뮬레이션해 확인합니다
$APP --plugin-test path/to/Synth.vst3   # 창 없이 플러그인 패널을 만들어 슬라이더를 움직이고, 상태가 곡에 저장되고 실행 취소로 되돌아오는지 확인합니다
$APP --snapshot synth.png --instrument 8 song.json   # 8번 트랙의 내장 신스 패널을 PNG로 저장합니다
$APP --snapshot export.png --export song.json        # 내보내기 대화상자를 PNG로 저장합니다
$APP --snapshot new.png --new --track 4              # 다섯 번째 템플릿을 선택한 새 곡 대화상자를 PNG로 저장합니다
$APP --new-test [--png new.png]                      # 창 없이 새 곡 대화상자로 곡을 만들어 열고 템플릿과 같은지 확인합니다 (결과는 JSON 한 줄)
$APP --export-test [path/to/Synth.vst3] [--png done.png]   # 창 없이 대화상자의 내보내기를 실행해 WAV가 엔진 렌더링과 바이트 단위로 같은지 확인하고, 스템, MIDI, Ogg 반복 구간, MP3 마디 구간, 중지, 플러그인 곡도 확인합니다 (결과는 JSON 한 줄)
$APP --scan-plugins cache.json [폴더]   # VST3와 AU를 검색해 플러그인 캐시를 저장합니다 (앱의 플러그인 찾기가 이 명령을 별도 프로세스로 실행합니다)
$APP --self-test --at 60 song.json      # 오디오 장치를 열고 확인합니다: 정지 상태에서 음 하나와 키보드 연주가 들리는지, -60dB로 3초 재생하며 위치가 진행되는지, 두 박 구간 재생이 끝에서 멈추고 처음으로 돌아오는지, MIDI 입력 경로로 녹음한 음이 음표 하나로 들어가는지 (결과는 JSON 한 줄)
$APP --self-test --loudness song.json   # 백그라운드 라우드니스 측정이 끝나기를 기다렸다가 모니터 게인도 함께 출력합니다
```

### 템플릿으로 새 곡 만들기

파일 > 새 곡(⌘N)은 `templates/`의 장르 템플릿 목록을 보여 줍니다: 빈 곡, 피아노 독주, 관현악 전투, 보스 전투, 던전, 마을 춤곡(6/8),
스케르초(3/4), 관현악 주제곡, 노래 형식, 전자 음악, 리퀴드 드럼앤베이스, 덥스텝, 미니멀 전자 음악. 템플릿은 음표만 없는 일반
곡 파일입니다. 악기와 아티큘레이션을 지정한 트랙, 믹스(게인, 밸런스, 센드, 효과), 버스, 마스터(목표 라우드니스, 리미터), 템포와 박자, 그리고 게임용
루프 곡이면 반복 구간(4마디 인트로 뒤 32마디)이 들어 있습니다. 제목을 입력하고 만들기...를 눌러 저장 위치를 선택하면 곡이 열리고 바로 음표를 입력할 수
있습니다. 열린 곡에 저장하지 않은 편집이 있으면 먼저 확인하고, 이미 있는 파일은 덮어쓰지 않습니다.

템플릿은 `tools/make-templates.py`가 이 저장소의 곡에서 생성합니다. 그래서 믹스 값은 해당 곡에서 실제로 사용한 값입니다. 음표, 템포 변화, 곡의
반복 구간, 주석은 제거합니다. 컨트롤러 오토메이션(CC1, CC11, CC21, CC74)은 트랙 게인이 그 값에 맞춰져 있으므로 레인마다 곡 안의 중앙값 한 포인트로
남깁니다. 페달과 피치 벤드 오토메이션은 제거합니다. `tools/make-templates.py --check`는 원래 곡과 달라진 템플릿을 알려 줍니다.

### 내보내기

파일 > 내보내기(⌘E)는 현재 앱에 열린 곡을 그대로(저장하지 않은 편집 포함) 파일로 내보냅니다. 대화상자의 설정 항목은 다음과 같습니다.

| 항목 | 선택 사항 |
| :--- | :--- |
| 형식 | WAV(16, 24비트, 32비트 부동소수점), FLAC(16, 24비트), Ogg Vorbis(품질 0~10, 기본값 6, 약 192kbps), MP3(128~320kbps CBR) |
| 샘플레이트 | 44100, 48000Hz |
| 범위 | 곡 전체, 반복 구간(`metadata.loop`: 처음부터 반복 끝까지, 루프 지점을 파일에 기록), 마디 구간(A~B 마디와 그 뒤 2초 페이드아웃) |
| 함께 내보내기 | 스템(트랙과 버스마다 WAV와 `master.wav`, `<이름>_stems` 폴더, 곡 전체일 때만), MIDI(`<이름>.mid`) |
| 저장 위치 | 기본값은 마지막으로 내보낸 폴더(처음에는 음악 폴더)와 곡 파일 이름이며, 구간이면 이름 뒤에 `_loop`나 `_bars17-32`가 붙습니다. 바꾸기...로 다른 위치와 이름을 지정합니다 |

내보내기는 재생과 같은 트랙 신호 체인을 거치는 엔진의 오프라인 렌더링을 사용합니다. 그래서 앱에서 들은 소리와 같고, 저장한 곡을
`music-render render`로 렌더링한 파일과도 같습니다. 곡에 목표 라우드니스(`master.targetLufs`)가 있으면 곡 전체를 기준으로 맞추므로,
구간만 내보내도 곡 안에서와 같은 음량으로 나옵니다. 백그라운드에서 렌더링하는 동안 진행 막대가 표시되고(중지를 누르면 파일을 저장하지 않음), 끝나면
길이, 라우드니스, 트루 피크, 클리핑 여부를 보여 주며, 반복 구간이면 반복 끝과 반복 시작 직전의 소리 차이도 보여 줍니다. 플러그인 악기는 메인 스레드에서
생성하고 렌더링은 백그라운드에서 합니다. 선택한 형식, 품질, 폴더는 다음 내보내기에도 그대로 사용됩니다.

- **게임용 루프 파일.** WAV에는 smpl 청크(시작 샘플과 끝 샘플 포함)를, Ogg Vorbis와 FLAC에는 샘플 단위의 `LOOPSTART`, `LOOPLENGTH` 태그를 기록합니다. 끝의 20ms는 `tools/make-loop.py`와 같은 방식으로 반복 시작 직전의 소리와 크로스페이드합니다. MP3는 인코더가 앞뒤에 빈 샘플을 붙이므로 샘플 단위로 정확하게 반복할 수 없습니다. 그래서 대화상자에서 이를 안내하고 MP3로 반복 구간을 내보내지 못하게 하며, 명령줄도 이 조합을 거부합니다.
- **태그.** Ogg Vorbis와 FLAC에는 곡의 `title`을 `TITLE` 태그로, MP3에는 UTF-8 ID3v2.4 `TIT2` 태그로 기록합니다. MP3는 맨 앞에 LAME 정보 프레임을 넣으므로, 이 프레임을 지원하는 플레이어는 인코더가 붙인 빈 샘플을 빼고 곡과 같은 길이로 디코딩합니다.
- **같은 곡이면 같은 파일.** 날짜를 기록하지 않고 Ogg 스트림 번호를 고정하므로, 같은 곡을 두 번 내보내면 바이트 단위까지 같은 파일이 만들어집니다.

### 녹음

⌥R(트랜스포트의 둥근 버튼)로 선택한 트랙에 녹음합니다. 정지 상태면 카운트인(재생 메뉴에서 없음, 1마디, 2마디 중 선택, 기본값 1마디) 후 재생 위치부터
재생하면서 녹음하고, 재생 중이면 바로 녹음을 시작합니다. ⌥R을 다시 누르면 녹음을 끝내고, 스페이스를 누르면 녹음을 끝내고 재생도 멈춥니다. 녹음 한 번은 편집 한 번("녹음",
⌘Z로 되돌리기)으로 기록됩니다. 음표는 `humanize: false`로 입력되므로 엔진의 휴머나이즈가 사람이 연주한 타이밍을 다시 흔들지 않으며, 서스테인 페달이나
모듈레이션 같은 컨트롤러는 트랙 오토메이션의 포인트가 됩니다. 녹음한 음표는 선택된 상태로 남습니다.

- **입력.** MIDI 입력 장치는 기본적으로 모두 켜져 있습니다(설정 > MIDI 입력에서 장치별로 켜고 끌 수 있으며, 새로 연결한 장치는 2초 안에 열립니다).
  컴퓨터 키보드 연주(⌘K)도 녹음됩니다. 연주한 음은 녹음하지 않을 때도 선택한 트랙의 악기, 효과, 페이더를 거쳐 들립니다(페달과 피치 벤드도 마찬가지입니다).
- **타이밍.** MIDI 메시지마다 수신 시점의 재생 샘플 위치(마지막 오디오 블록 기준으로 추정)를 기록하므로, 화면 처리가 늦어도 음의 위치가 밀리지 않습니다.
  재생 메뉴 > "녹음할 때 격자에 맞추기"를 켜면 녹음을 끝낼 때 음의 시작을 피아노 롤의 격자에 맞춥니다(길이는 연주한 그대로).
- **메트로놈.** ⌥M으로 켜면 박마다 소리가 나고, 마디의 첫 박은 높은 소리입니다. 템포 맵을 따르며, 리미터와 모니터 게인 뒤에서 더해지므로 내보낸 파일에는
  포함되지 않습니다. 음량은 재생 메뉴 > "메트로놈 음량"에서 선택합니다.
- **반복과 오버더브.** ⌥L은 곡의 반복 구간(`metadata.loop`, 내보내기 대화상자의 반복 구간과 같은 값)을 반복 재생합니다. 반복 구간은 눈금자에 띠로 표시됩니다.
  눈금자를 ⌥ 드래그해 새로 지정하고(박 단위, 축소했을 때는 마디 단위), 띠의 끝을 드래그해 옮기고, 편집 메뉴 > "고른 음표 구간을 반복 구간으로", "반복 구간
  지우기"로 변경합니다. 재생 메뉴 > "반복 이음매 듣기"는 반복 끝의 두 마디 앞부터 반복해 들려줍니다. 반복을 켠 채 녹음하면 반복할 때마다 음이
  쌓이고(오버더브), "반복 구간 안에서만 녹음 (펀치)"를 켜면 구간 안에서 시작한 음만 남깁니다. 반복 시작으로 돌아갈 때 엔진은 울리던 음을 끄고 반복 시작 지점의
  컨트롤러 값을 다시 보내므로, 돌아간 뒤의 소리는 그 위치에서 재생을 새로 시작한 것과 같습니다(엔진 테스트에서 확인).
- **창 없는 테스트.** `--edit-test`는 녹음 결과를 편집 한 번으로 넣어 보고, 두 눈금자에서 반복 구간을 드래그해 봅니다. `--self-test`는 실제 오디오 장치에서
  녹음을 켜고 MIDI 입력 경로로 음을 0.3초 눌러, 그 길이의 음표 하나가 재생 위치에 입력되는지 확인합니다.

## 음악 엔진(music-render)

엔진은 명령줄 도구로도 사용할 수 있습니다. 표준 출력에는 JSON 하나만 출력하고 로그는 표준 오류로 보냅니다. 따라서 AI 에이전트가 사람의
도움 없이 렌더링하고, 결과를 분석하고, 곡을 다시 수정할 수 있습니다. 종료 코드는 0이 성공, 1이 입력이나 렌더링 오류, 2가 사용법 오류입니다.
설계 문서는 [docs/plans/engine.md](plans/engine.md)에 있습니다.

```bash
MR=build/engine/music-render

$MR validate engine/examples/piano_demo.json          # 오류와 경고를 JSON 경로, 해결 방법과 함께 출력합니다
$MR render engine/examples/piano_demo.json --output out/piano_demo.wav
$MR render song.json --output song.wav --sample-rate 44100 --bit-depth 16 --seed 7
$MR render song.json --output song.wav --stems out/stems   # 트랙과 버스마다 파일 하나, 그리고 master.wav
$MR render song.json --output song.mp3 --measure song.measure.json   # 스템 파일 없이 트랙, 버스, 마스터마다 마디의 크기, 12대역, 사이드와 음표 머리의 크기를 측정합니다
tools/mix-report.py song.measure.json --melody Lead --sections verse:1-8 chorus:9-16   # 구간 크기, 400Hz 위 선율 대 나머지, 대역 몫, 저역, 음 크기를 표로 출력합니다
```

곡 파일에는 트랙, 음표, 버스, 마스터를 정의합니다. 한 박은 4분음표 하나이고, 음높이는 MIDI 번호나 `E4` 같은 음 이름으로 지정합니다.

```json

  "tempo": 76,
  "performance": { "timingHumanizeMs": 12, "velocityHumanize": 8, "humanizeSeed": 12345 },
  "tracks": [
    { "name": "Violins", "instrument": "violins", "mixer": { "gainDb": -3, "pan": -0.4 },
      "sends": [ { "bus": "hall", "levelDb": -9 } ],
      "cc1": [ { "beat": 0, "value": 30 }, { "beat": 8, "value": 100, "curve": "smooth" } ],
      "notes": [ { "pitch": "E4", "startBeat": 0, "durationBeat": 4, "velocity": 70, "articulation": "legato" },
                 { "pitch": "B3", "startBeat": 4, "durationBeat": 0.5, "velocity": 80, "articulation": "pizzicato" } ] }
  ],
  "buses": [ { "name": "hall", "effects": [ { "type": "reverb", "mix": 1, "decaySeconds": 2.6, "preDelayMs": 25 } ] } ],
  "master": {
    "targetLufs": -16,
    "effects": [ { "type": "eq", "lowCutHz": 30 }, { "type": "compressor", "thresholdDb": -18, "ratio": 2 },
```

- **악기.** 곡에는 악기 이름만 지정하고, 실제로 무엇으로 연주할지는 레지스트리([engine/instruments/registry.json](../engine/instruments/registry.json) 또는 `--registry`)가 정합니다. 각 항목은 내장 신스, SFZ 파일, VST3 플러그인, AU 중 하나를 가리킵니다. 악기를 찾을 수 없으면 그 항목의 `fallback`이 대신 연주합니다. 곡에서 악기를 직접 정의할 수도 있습니다: `"instruments"`에 레지스트리 파일 경로와 정의 객체를 섞어서 넣습니다.
- **트랙별 플러그인 설정.** 트랙의 `"plugin": { "state": "<base64>", "program": 3, "parameters": { "Cutoff": 0.4 } }`는 레지스트리 항목의 설정을 덮어씁니다. 그래서 같은 플러그인 악기로 트랙마다 다른 소리를 낼 수 있습니다.
- **트랙별 신스 설정.** `"synth": { "cutoffHz": 600, "release": 1.2 }`로 내장 신스 프리셋의 값을 바꿉니다(필터, 엔벨로프, 비브라토, 출력, 그리고 피아노와 플럭은 저음 건반과 고음 건반의 감쇠 시간). `"filterMode": "highpass"`나 `"bandpass"`는 감산 합성 프리셋의 필터를 하이패스나 밴드패스로 바꾸고, CC74는 어느 방식에서든 컷오프를 움직입니다(노이즈 라이저는 `synth.noise`에 `"filterMode": "highpass"`와 올라가는 CC74 오토메이션을 사용합니다). `"bendRange": 12`이면 `pitchBend` 1이 한 옥타브입니다(기본값 2반음. 감산 합성 프리셋, 피아노, 드럼 키트). 드럼 키트는 반음 단위의 `"tune"`을 지원하고, 피치 벤드가 이미 울리고 있는 드럼의 음높이까지 바꾸므로 스네어 롤의 음높이를 끌어올릴 수 있습니다. 값의 이름과 범위는 곡을 읽을 때 검사하며, 해당 프리셋이 쓰지 않는 값(패드의 `tune` 등)에는 경고를 출력합니다.
- **건반 보정.** 샘플 라이브러리는 건반마다 녹음된 음량이 달라서, 같은 벨로시티로 연주해도 이웃 건반 사이에서 몇 dB씩 차이가 납니다(VSCO 업라이트 피아노는 최대 14dB). `tools/calibrate-keys.py <악기> [--low 28] [--high 96]`은 건반마다 벨로시티 일곱 단계로 렌더링해 어택의 음량을 측정하고(좌우 채널의 에너지로 측정합니다. 모노로 합치면 좌우 위상이 어긋난 샘플이 작은 건반으로 잘못 측정됩니다) `engine/instruments/calibration/<악기>.json`에 저장합니다. 작곡 스크립트는 이 표를 참고해 음마다 해당 건반에서 의도한 음량이 나오는 벨로시티를 선택합니다. 어택이 느리고 CC1이 음량을 정하는 악기(Sonatina 현악과 호른)는 지속음을 측정합니다. `--length 1.5 --window 0.5 1.3`은 음을 1.5초 동안 연주하고 0.5~1.3초 구간을 측정하며, `--articulation legato`는 해당 아티큘레이션으로 측정해 `<악기>-<아티큘레이션>.json`에 저장합니다. 이런 악기는 작곡 스크립트가 벨로시티 대신 CC11로 선율 음마다 음량을 맞춥니다. `--registry <파일>`은 악기 정의를 추가로 읽어 레지스트리에 넣기 전에 테스트 중인 악기를 측정할 수 있게 합니다. `--cc1 <값>`은 측정하는 동안 CC1을 그 값으로 고정하고(Sonatina 금관은 CC1에 따라 샘플 레이어가 바뀝니다), `--name <표>`는 보정표의 이름을 지정합니다. 짧게 끊어 부는 호른 선율은 `--length 0.6 --window 0.06 0.32 --cc1 90 --name horns-short`처럼 짧은 음으로 측정합니다(짧은 음에서는 C5~D5가 가장 크고, 지속음 보정표에서는 A4와 B4가 가장 큽니다).
- **게임용 루프 파일.** `music-render render 곡.json --output loop.ogg --loop`(또는 앱의 내보내기)는 게임에서 반복 재생할 파일을 바로 만들고 이음매를 측정합니다. `tools/make-loop.py <곡.json> <렌더링.wav>`는 이미 렌더링한 파일에서 같은 루프 파일을 잘라 내고, 미리 듣기 파일을 만들고, 스템마다 이음매를 측정합니다. 루프 지점은 곡의 `metadata.loop`(`startBeat`, `endBeat`)를 템포 맵으로 샘플 위치로 변환해 정합니다. 반복 끝 직전 마디가 반복 시작 직전 마디와 같은 음이면 이음매가 들리지 않습니다(`songs/forgotten-glyphs/compose.py`의 `threshold` 참고). 이 도구는 두 지점의 소리 차이를 측정하고(`--stems`를 지정하면 스템별로), 반복 끝의 20ms를 반복 시작 직전의 소리와 크로스페이드한 뒤 `--output`(smpl 청크에 루프 지점을 기록한 WAV), `--ogg`(`LOOPSTART`, `LOOPLENGTH` 태그를 넣은 Ogg Vorbis), `--preview`(곡을 한 번 재생하고 반복 시작으로 돌아가 `--preview-beats`박을 더 재생한 뒤 `--fade`초 동안 페이드아웃하는 미리 듣기 파일)를 생성합니다.
- **아티큘레이션.** 음표나 트랙에 `legato`, `pizzicato` 같은 이름을 지정합니다. 악기 프로필이 그 이름을 키스위치, SFZ 파일, 프로그램 체인지, 컨트롤러로 변환합니다.
- **가사.** 음표에 그 음에서 부르는 음절을 지정합니다: `"lyric": "늦"`(UTF-8 문자), 앞 음절을 이어 부르는 음표는 `"lyric": "-"`. 가사는 소리에 영향을 주지 않습니다. `export-midi`는 음절마다 노트 온 위치에 가사 메타 이벤트(FF 05, UTF-8)를 기록하고(`-`는 제외), 기록한 개수를 `lyrics`로 출력합니다. 피아노 롤은 음표 안에 음절을 표시하고(짧은 음표는 글자를 줄이고, 그래도 넘치면 공간이 있을 때 음표 바로 아래나 위에 표시), `-`는 음표를 가로지르는 선으로 그립니다. 음표를 옮기고, 늘이고, 복사하고, 붙여 넣어도 가사가 따라가며, 새로 그린 음표에는 가사가 없습니다.
- **조.** `"key": "Bb minor"`(으뜸음과 major 또는 minor, 샵이나 플랫 일곱 개까지)와 마디줄 위치의 `"keyChanges": [ { "beat": 64, "key": "A major" } ]`로 지정합니다. 조는 소리에 영향을 주지 않습니다. 악보는 조를 조표와 음 이름 철자에 사용하고(Bb단조에서는 C#이 아니라 Db, 이끎음은 제자리표 A), MIDI 내보내기는 조표 이벤트로 기록하며, MIDI 가져오기는 이를 읽어 옵니다. 조가 없으면 악보에서 음표를 분석해 조를 추정합니다(Krumhansl-Kessler 프로필을 사용하고, 나란한조 중에서는 곡 끝의 가장 낮은 음으로 결정).
- **악보(MusicXML).** `export-musicxml`은 곡을 악보로 변환합니다. 박자와 조가 바뀌는 마디, 보표마다 4분음표 한 박을 16분음표(또는 32분음표)나 셋잇단음표 격자에 맞추기, 음의 시작과 끝에서 나눈 화음과 붙임줄, 박이 드러나는 음가 표기, 마디별 임시표, 가운데 C 위아래를 모두 쓰는 건반 파트의 큰보표, 드럼 세트의 타악기 보표, 템포, 마커, 가사를 지원합니다. 음높이는 실음으로 표기합니다.
- **박자 변경.** `"timeSignature": [4, 4]`는 처음 박자이고, `"meterChanges": [ { "beat": 64, "timeSignature": [3, 4] } ]`는 이전 박자의 마디줄 위치에서 박자를 바꿉니다(곡을 읽을 때 위치를 검사합니다). 마디 번호를 세는 모든 곳(눈금자, `--bars`, `arrange`, 메트로놈 강박, 내보내기의 마디 구간)이 바뀐 박자를 따릅니다. MIDI 내보내기는 박자 변경을 기록하고 가져오기는 읽어 오며, 마디를 삽입하거나 삭제하면 박자 변경도 음악과 함께 이동합니다.
- **컨트롤러 오토메이션.** `cc1`, `cc11`, `cc64`, `pitchBend` 같은 오토메이션을 트랙에 포인트로 기록하고, 포인트마다 `curve`(linear, step, exponential, smooth)를 지정합니다.
- **다이내믹스.** VSCO 현악은 벨로시티 레이어가 두 개뿐입니다. 그래서 트랙에 CC1 오토메이션이 있으면 엔진이 모든 음을 두 레이어로 함께 재생하고 CC1로 크로스페이드합니다. 게인과 밝기도 CC1을 따릅니다.
- **효과.** `eq`, `compressor`, `reverb`(합성한 홀 임펄스 응답이나 `ir` 파일), `delay`(스테레오나 핑퐁, `timeMs` 또는 템포 맵을 따르는 `timeBeats`, 가장 느린 템포 기준 최대 16초), `limiter`(`"truePeak": 1`이면 샘플 사이의 피크까지 제한), `gain`, `stereo`(좌우 위치와 폭), `filter`, `ducker`, `chorus`, `flanger`, `phaser`, `tremolo`, `gate`를 트랙, 버스, 마스터에 순서대로 지정합니다. `"bypass": true`는 효과를 건너뛰되 지연은 유지합니다. 버스에 `"mixer": { "mute": true }`를 지정하면 그 버스는 소리를 내지 않습니다.
- **필터.** `{ "type": "filter", "mode": "highpass", "slope": 24, "cutoffHz": 20, "resonance": 0 }`은 지연이 없는 스테이트 배리어블 필터입니다. `lowpass`, `highpass`, `bandpass`, `notch`와 옥타브당 12dB 또는 24dB를 선택합니다. `resonance`는 0(평탄한 버터워스)부터 1(Q 10, 피크 +20dB)까지이며, `mix`도 있습니다.
- **MIDI 런.** 보기 > MIDI 배우기(⇧⌘L)를 켜면 믹서의 컨트롤마다 테두리가 생기고, 연결된 컨트롤에는 CC 번호가 표시됩니다. 페이더, 밸런스 노브, 뮤트나 솔로 버튼, VCA, 열려 있는 효과의 숫자 파라미터를 클릭한 뒤
  MIDI 컨트롤러의 노브나 페이더를 움직이면 그 CC가 연결됩니다(우클릭하면 연결 해제). 연결 정보는 앱 설정에 저장되고 채널을 순서로 가리키므로("트랙 1 페이더") 어느 곡에서나
  사용할 수 있습니다. 연결된 컨트롤러는 마우스로 드래그할 때와 같은 과정을 거칩니다. 첫 값이 들어오면 드래그가 시작되어 미리 들려주고, 0.4초 동안 값이 들어오지 않으면 손을 뗀 것으로 보고 편집 한 번으로 기록합니다(곡선 쓰기가 켜져 있으면 오토메이션으로).
  효과 파라미터는 각자의 눈금(주파수와 시간은 로그)을 따르고, 버튼은 값이 64를 넘어 올라갈 때 전환됩니다.
- **프리셋.** 효과 편집기의 프리셋 버튼으로 기본 프리셋(내장 효과용 31개: 보컬 EQ, 드럼 버스 컴프레션, 플레이트와 홀 리버브, 점8분음표 딜레이, 16분음표 트레몰로,
  드럼 게이트 등)이나 사용자 프리셋을 적용하고, 현재 값을 사용자 프리셋으로 저장합니다(앱 데이터 폴더의 `InitialDAW/Presets/Effects/<형식>/`). 프리셋을 적용하면 값이 곡에
  그대로 저장되므로 곡이 프리셋 파일에 의존하지 않습니다. 효과의 바이패스, 주석, 사이드체인 키, 그리고 프리셋을 적용한 뒤에도 유효한 오토메이션은 그대로 남습니다. 효과 슬롯의 "+" 메뉴는
  채널의 효과 체인 전체를 저장하고, 저장한 체인을 어느 채널에나 불러옵니다(`Presets/Chains/`).
- **모듈레이션과 게이트.** `chorus`와 `flanger`는 지연 시간을 `delayMs`와 `delayMs + depthMs` 사이에서 변조하고(`feedback`이 음수면 위상을 반전해 피드백), `phaser`는 1차 올패스 필터 2~12단(`stages`)의 노치 주파수를 `lowHz`와 `highHz` 사이에서 변조하며(2단을 원음과 반씩 섞으면 노치 주파수의 소리가 상쇄됨), `tremolo`는 음량을 `depth`만큼 `sine`, `triangle`, 모서리를 둥글게 한 `square` 모양(`shape`)으로 변조합니다. LFO는 `rateHz`로, 또는 템포 맵을 따라 `rateBeats`박마다 한 주기를 돌며, 위상이 곡 위치만으로 정해지므로 위치 이동, 반복, 실시간 재생 결과가 렌더링과 같습니다. 오른쪽 채널의 위상은 `phaseDeg`만큼 앞섭니다(트레몰로에서 180으로 두면 오토팬). `gate`는 피크가 `thresholdDb`를 넘으면 열리고, 그보다 3dB 아래로 내려간 뒤 `holdMs`가 지나면 `rangeDb`까지 닫힙니다(`attackMs`, `releaseMs`).
- **멀티밴드, 트랜지언트, 디에서.** `multiband`는 `lowHz`와 `highHz`에서 나눈 세 대역(링크위츠-라일리 4차. 저역 대역의 위상을 맞추므로 다시 합치면 0.000dB 이내로 평탄)을 대역마다 `<대역>ThresholdDb`, `<대역>Ratio`, `<대역>GainDb`(`low`, `mid`, `high`, 공통 `attackMs`, `releaseMs`, `kneeDb`)로 압축합니다. `transient`는 5ms RMS로 측정한 빠른 엔벨로프와 느린 엔벨로프의 차이로 어택(`attackDb`, 타격 순간의 처음 몇 ms)과 서스테인(`sustainDb`)을 따로 키우거나 줄입니다(음량이 일정한 소리는 0.1dB 이내로 그대로). `deesser`는 `frequencyHz` 위 대역의 피크가 `thresholdDb`를 넘으면 그 대역만 `rangeDb`까지 줄입니다.
- **덕킹.** `{ "type": "ducker", "rateBeats": 1, "depthDb": -12, "attackMs": 1, "holdMs": 30, "releaseBeats": 0.5, "curve": 1, "offsetBeats": 0 }`은 키 트랙 없이 펌핑 효과를 만듭니다. `rateBeats`박마다 `depthDb`까지 내려가 잠시 유지한 뒤 `releaseBeats` 동안 돌아옵니다(돌아오는 동안 남은 깊이는 `depthDb * (1 - r)^curve`). 감쇠량이 곡 위치만으로 정해지므로, 위치를 옮기거나 실시간으로 재생해도 렌더링과 샘플 단위까지 같습니다.
- **페이더, 밸런스, 효과, 센드 오토메이션.** 효과 객체에는 컨트롤러 오토메이션과 같은 포인트 형식으로 `"automation": { "cutoffHz": [ { "beat": 64, "value": 20 }, { "beat": 96, "value": 1200 } ] }`를, 센드에는 `"automation": { "levelDb": [...] }`를, 트랙, 버스, 마스터의 믹서에는 고정 게인과 밸런스 대신 사용하는 `"automation": { "gainDb": [...], "pan": [...] }`를 지정합니다. 오토메이션을 지원하는 파라미터는 `gain.gainDb`, `filter`의 `cutoffHz`, `resonance`, `mix`, `ducker`의 `depthDb`, `mix`, `delay`의 `mix`, `feedback`, `reverb`의 `mix`, `dryDb`, `wetDb`, `stereo.width`, `distortion`의 `driveDb`, `mix`, `chorus`와 `flanger`의 `depthMs`, `feedback`, `mix`, `phaser`의 `feedback`, `mix`, `tremolo.depth`이며, 그 밖의 파라미터에 오토메이션을 지정하면 오류가 발생합니다. 첫 포인트 앞에서는 첫 값을, 마지막 포인트 뒤에서는 마지막 값을 사용합니다. 오토메이션은 곡 위치의 32샘플 격자에서 템포 맵으로 읽으므로 블록 크기나 위치 이동과 관계없이 같은 샘플이 나오고, 컷오프 주파수의 포인트 사이는 로그 주파수로 보간합니다. 실시간 재생에서는 정지 중과 카운트인 중에 오토메이션과 덕킹이 재생 위치의 값으로 유지됩니다. 반복 구간 끝에서 되돌아가거나 위치를 옮긴 뒤에도, 지연 때문에 믹스에서 늦게 나오는 소리는 그 소리가 나온 곡 위치의 값을 사용합니다.
- **플러그인 효과.** `{ "type": "plugin", "format": "vst3", "plugin": "/Library/Audio/Plug-Ins/VST3/Some.vst3", "state": "<base64>" }`(AU는 `"format": "au"`와 식별자, 번들에서 하나를 고르는 `"name"`, `"program"`, `"parameters"`)로 트랙, 버스, 마스터의 모든 효과 슬롯에서 VST3나 AU 효과를 사용할 수 있습니다. 플러그인은 플레이헤드로 곡의 위치, 박, 템포를 전달받고, 지연은 내장 효과처럼 보상되며, 내보내기에서는 non-realtime 모드로 준비됩니다. 앱의 효과 추가 메뉴에는 플러그인 찾기로 찾은 효과가 표시되고, 플러그인 슬롯을 클릭하면 플러그인 UI(없으면 파라미터 목록)가 열리며, 바꾼 사운드는 플러그인 상태를 효과에 저장하는 편집 한 번으로 기록됩니다.
- **사이드체인.** 컴프레서에 `"sidechain": "Kick"`을 지정하면 자기 입력 대신 Kick 트랙의 프리 페이더 신호로 압축량을 정합니다. 트랙, 버스, 마스터 모두에서 사용할 수 있습니다. 키 신호는 컴프레서 위치의 소리와 시간을 맞추므로, 트랙의 지연(트랙의 리버브나 리미터)이나 체인 앞쪽 효과 때문에 덕킹이 늦거나 빨라지지 않습니다. 엔진이 키 트랙을 먼저 처리하므로 내보내기와 실시간 재생 결과가 같으며, 존재하지 않는 키, 자기 자신을 키로 쓰는 경우, 서로를 키로 쓰는 순환 참조는 오류로 알려 줍니다.
- **내장 신스.** 기본 piano, pad, strings, bass, pluck, drums 외에 `synth.supersaw`, `synth.saw-pad`, `synth.edm-pluck`, `synth.sub`, `synth.saw-bass`, `synth.lead`, `synth.noise`, 건반 악기 `synth.ep`(일렉트릭 피아노, 세게 치면 밝아짐)와 `synth.poly-keys`(아날로그 폴리 키), `synth.edm-drums` 키트(킥 36, 스네어 38, 클랩 39, 하이햇 42와 46, 크래시 49)가 있습니다. CC74로 필터를 열고 닫습니다. `synth.club-drums`는 클럽 음악용 키트이며, 모든 소리가 뚝 끊기지 않고 자연스럽게 사라집니다: 36 킥(클릭과, 약 850Hz에서 A1로 내려가는 바디, `tune` 0에서 55Hz, 0.36초에 소멸), 35 롱 킥, 38 스네어와 40 롤 스네어(0.11초, 32분음표 롤용), 39 레이어드 클랩, 42, 44, 46 하이햇, 49 크래시, 51 라이드, 41~50 탐, 60 임팩트(E1 서브 붐, 3.6초에 소멸), 62, 63 다운리프터(4박, 8박), 64, 65, 66 노이즈 라이저(4박, 8박, 16박), 67, 68, 69 리버스 심벌(1박, 2박, 4박). 효과음의 길이는 박 단위이며 음이 시작하는 위치의 템포 맵으로 계산하므로, 드롭 16박 앞에서 16박 라이저를 치면 드롭 박에서 끝납니다. 키트에 없는 건반은 소리가 나지 않습니다. `music-render instruments`로 키트별 건반 이름을 확인할 수 있습니다. `synth.808`은 808 베이스입니다. 위상 0에서 시작하는 사인파가 한 옥타브 위에서 제 음으로 떨어지고(`pitchEnv`, `pitchEnvDecay`), 천천히 감쇠하며, 새추레이션(`drive`)이 걸립니다. 한 번에 한 음만 냅니다(`mono`). 누르고 있는 음과 겹친 음은 새 어택 없이 `glide`초 동안 미끄러지고, 띄어 친 음은 앞 음을 끊습니다. 이 네 값은 모든 감산 합성 프리셋에서 쓸 수 있습니다.
- **라우드니스.** `master.targetLufs`를 지정하면 마지막 리미터 앞에서 라우드니스를 측정해 맞추고, 리미터 때문에 라우드니스가 줄면 다시 맞춥니다.

`engine/examples/orchestral_demo.json`은 이 기능들을 64초 길이의 현악 편곡에 모두 사용한 예제입니다.

## Music IR

작곡 스크립트는 결과 JSON에는 남지 않는 정보를 알고 있습니다. 어느 마디가 마지막 코러스인지, 어느 트랙이 선율인지, 반주가 어느 화음표를
따르는지, 주제가 어디서 다시 나오는지 같은 정보입니다. 스크립트는 곡 JSON 옆에 `<곡>.ir.json`을 함께 생성해 이 정보와 구간별, 트랙별 측정값,
그리고 음표마다 그 음을 만든 `compose.py`의 코드 줄을 기록합니다. "마지막 코러스의 현악"을 고쳐 달라는 요청을 받은 AI 에이전트는 스크립트와 JSON을
처음부터 다시 읽지 않고, 몇 번의 짧은 조회로 곡 전체에서 수정할 코드 줄까지 범위를 좁힙니다. 그리고 수정 결과가 의도한 마디와 트랙 안에서만 바뀌었는지
검사합니다. 설계와 측정값은 [docs/plans/music-ir.md](plans/music-ir.md)에 있습니다.

```bash
IR=tools/music-ir.py
$IR overview <song>                       # 구간, 트랙의 역할, 주제와 그 주제가 다시 나오는 위치
$IR section <song> "<section>"               # 화음, 트랙별 측정값, 주제, 코드 줄, 이 구간만 렌더링하는 명령
$IR deps <song> --section final --track family:strings   # 현악이 의존하는 것, 다른 구간과 공유하는 함수와 데이터
$IR source <song> --section final --track vln            # 그 음을 만든 스크립트의 코드와 현재 줄 번호
$IR notes <song> --section p2 --track air                # 음표와 컨트롤러 포인트를 그대로 출력합니다
$IR compare <song> a1 p1                  # 두 구간 비교
$IR check <song>                           # IR 파일이 최신인지, 참조가 올바른지 (모든 명령에 --json 지원)
$IR overview <other-song>                         # IR 파일이 없는 곡: 측정값과 신뢰도를 붙인 추론
$IR regen <song>                           # 스크립트를 임시 폴더에서 실행해, 다시 생성하면 바뀌는 항목을 알려 줍니다
```

수정할 때는 계획을 먼저 세웁니다:

```bash
$IR plan <song> --sections final --tracks family:strings --protect role:main-melody,piano,harmony
# songs/<song>/compose.py를 수정합니다
$IR verify <song>   # 수정한 스크립트를 임시 폴더에서 실행해 트랙별, 구간별로 계획과 비교합니다
$IR apply <song>    # 결과를 저장합니다. 앱에서 수정한 JSON이면 대상 항목만 옮겨 넣습니다
```

- IR을 붙여도 곡 JSON은 이전과 바이트 단위까지 같게 생성되며, 렌더러는 IR 파일을 읽지 않습니다. `MUSICIR_OFF=1`이면 IR을 끕니다.
- 스크립트는 마지막 생성 이후 바뀐 JSON(앱에서 저장한 편집)을 덮어쓰지 않고, 달라진 트랙과 구간을 알려 줍니다. `MUSICIR_FORCE=1`이면 덮어쓰되 기존 파일을 `build/music-ir/backup`에 백업합니다.
- IR을 지원하는 스크립트는 `compose.py`의 `describe()`에서 IR을 선언하고, `Part.add`와 `Part.lane`에서 `musicir.trace`를 호출하며, `json.dump` 대신 `musicir.save`로 저장합니다. 테스트는 `tools/musicir/tests/test_music_ir.py`(CTest `music_ir`)입니다.
